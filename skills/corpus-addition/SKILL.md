# corpus-addition

完成本批语料从选材到正式采用与临时材料清理的交付。按实际变更选择分支，沿用已有采用决定与检查能力。

## 执行依据

- 编写或审阅散文前，必须读取并遵循 `docs/spec/rag-prose-writing.md` 与 `docs/spec/rag-prose-terminology.md`；来源分工、写作要求、术语和联合审阅标准在这两份 spec 唯一维护。
- 正式 facts 与 raw 的职责见 `docs/adr/ADR-024-facts-storage-and-raw-lifecycle.md`。涉及输入路径或清理时，先按对应实施计划和实际消费者确认当前状态，不把规划中的迁移当作已完成。
- 脚本、工作副本与开发临时产物按 `scripts/INDEX.md` 处理；代码与测试改动遵循 `docs/rules/testing.md`，计划与记录遵循 `docs/rules/document-lifecycle.md`。

## 1. 确定本批范围

从 docs/inbox.md 的既有需求与采用决定起步，列明本批主题、来源篇目或对象、采用内容、目标文件以及需处理的事实缺口。已有候选与用户决定直接沿用，不重新做整库候选评估。发现同主题内容时优先合并或补充，只有独立阅读需要时才新建篇目。

工程批次由对应 plan 与 notes 承载；轻量修订使用已有任务记录，不为每个段落建立新计划、证明表或审批链。范围外问题回到 inbox，不挤入当批验收。

候选篇目多、采用与否取决于与本地承载的增量比较时，可按批派生只读评估子代理，逐篇输出来源对象、采用内容、与本地承载的关系、冲突与依据、建议落点及不采用理由；批内对象较多时按来源目录再分组。子代理清单只是采用输入：主代理须亲自抽核高影响、高冲突或与既有正文口径可能矛盾的篇目，清单里出现数值不等于已核对；评估子代理不承担写作 spec 的独立审阅职责，二者互不替代。

## 2. 取得材料并保留来源定位

按需要读取来源；已有固定版本可直接查阅时，无须额外复制。确需暂存的稿件落入 knowledge/raw/<批次>/，只放本批所需材料，不复制整个外部库。脚本、运行输出和仓库工作副本按 scripts/INDEX.md 放在 dev-temp/work/<任务>/。

在本批 notes 或既有任务记录中写明外部仓库地址、所用提交、源文件及采用段落；解包数据另记录对象 ID、字段及必要转换口径。本地实践记录影响判断的条件和依据。来源信息随正式采用结果保留，raw 内的头注不能成为唯一溯源记录；不新增哈希、指纹或全量来源副本台账。

## 3. 分别处理 facts 与散文

改写前确认分块、manifest 与定位计数是否将变化；有变化时，先按确定的变更范围更新 benchmark-integrity 等完整性测试预期，运行相关测试并观察旧语料失败，再修改正文与登记。代码与测试变更的其他测试先行要求及豁免按 docs/rules/testing.md 执行。

涉及 facts 增补或修订时，从固定版本解包数据核对条目与转换，更新正式 facts 输入及其必要映射记录；不得从散文或模型回答补填机械事实。目录变更不等于已完成来源映射验证。

散文按两份 spec 整理机制、分工、条件和取舍，结合现有正文去重。既有正文的泛称、绝对化结论或旧口径与本批条件冲突时，连同受影响篇目同批修正，不带入独立审阅。处理源稿中的外部目录、状态标记、协作指令和内部链接，保留适用的玩家内容。遇到 facts 缺项时按写作 spec 的来源与审阅边界处理，不把全量 facts 刷新作为所有散文的前置。

正文优先使用规范词改写，精确技能原文通过既有 facts 与关联提供。确需在正文逐字引用技能或 UI 原文时，按术语 spec 用引号并在相邻处给出规范词；引用仍受禁词检查，引号不构成豁免。

## 4. 正式落位并联合审阅

正式散文落入 knowledge/base 或 knowledge/guides，按需要更新 corpus-manifest、prose-links 及实际受影响的计数或定位。技能数据使用正式 facts 出口，不把临时稿注册成事实关联或检索对象。来源记录使用持久的仓库、版本、篇目或本地实践依据，正文不依赖 raw 文件才能理解或追溯。

正文改变既有事实卡片展示的适用条件时，同批同步 `bench/src/facts/curation` 的对应说明常量，只改文案、不动技能事实与解析。

正文、关联和采用记录一并送审，按写作 spec 核对关键条件与数值前提；来源有不同解释时回查原始定义，facts 暂缺的小节在正文保留必要条件。人类参与与独立审阅按该 spec「执行与维护」开展，结论记入现有 notes；同批提交的独立审阅可按 commit-convention 合并开展。

## 5. 按变更验证

同一批次复用仍适用的验证记录，后续变更按影响范围补做检查，记录覆盖范围与结果。

散文运行 `pnpm run check:prose-terms` 与 `node scripts/doc-check.mjs`。其余按本批实际变更选择既有检查，不新建门禁，也不在此复制命令清单（见 scripts/gates.mjs）：

- 分块、manifest 或定位计数变化：运行相应完整性检查，确认满足改写前确定的预期；
- 新增或变更必要关联、据关联删减重复事实，或分节改变读取范围：离线核对正文与必要事实的实际送达，记录结果；据关联删减重复事实时，即使关联与分节未变也须核对；
- 改动事实卡片说明常量：重新构建后复核送达与相应检查。

代码与测试变更遵循 docs/rules/testing.md，合并门禁仍以 scripts/gates.mjs 与 scripts/verify.mjs 为准，不新建一套语料门禁。施工中的计划未勾选项按 doc-check 的现有规则报告，不能以虚报完成消除错误。检查通过不替代散文联合审阅，也不代表模型质量改善；日常添加不要求付费运行或答对率达标。

## 6. 清理临时材料并交付

来源工作副本保留至本批最后一次来源审阅结束，随后按已核对范围清理，并在提交前确认清理结果。

先确认正式成果、来源定位、审阅结论和必要验证已落位，再按本批明确文件范围清理 raw 原稿、摘录及中间稿。已采用、未采用和被替换的材料均不因“以后可能有用”永久保留；部分采用只保留已确定续作批次所必需的部分，并在原记录写清剩余任务与清理时点。仅列入候选或笼统的未来待办，不构成保留原稿的理由。

清理前核对正式正文、facts 加载、manifest、prose-links 和当前测试是否仍依赖拟删文件；存在正式消费者时先完成迁移或替换。按文件列出并检查路径，禁止直接递归删除整个 raw。本批未向 raw 暂存材料时，确认无残留即可，清理重点为 dev-temp 的对照产物、来源工作副本与生成中间件。已跟踪文件按普通版本控制删除；dev-temp 临时产物沿用 scripts/INDEX.md 的显式清单流程，不扩大临时清理器的目录权限。清理不是必须新增脚本或维护长期清单的理由。

清理后确认本批无残留原稿、正式引用可用；清理影响定位或测试输入时，复核相应检查。在原记录简述采用结果、验证结果和清理范围，历史提交及已归档记录保持原貌；未纳入本批清单的临时产物写明归属计划与清理时点，不默认长期保留。若任务中断或交接，只保留继续实施必需的材料，并记录具体续作与清理条件；取消且无后续用途的材料同样清理。不要转存到另一目录作为永久原稿库，也不等待全库内容添加完才清理已完成批次。

本批完成以正式内容与必要 facts 已落位、联合审阅结束、适用验证完成、临时材料清理完成为准，不以 raw 中长期存有原稿作为完成凭据。
