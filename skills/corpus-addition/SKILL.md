# corpus-addition

完成本批语料从选材到正式采用与临时材料清理的交付。按实际变更选择分支，沿用已有采用决定与检查能力。

## 执行依据

- 编写或审阅散文前，必须读取并遵循 `docs/spec/rag-prose-writing.md` 与 `docs/spec/rag-prose-terminology.md`；来源分工、写作要求、术语和联合审阅标准在这两份 spec 唯一维护。
- 正式 facts 与 raw 的职责见 `docs/adr/ADR-024-facts-storage-and-raw-lifecycle.md`。涉及输入路径或清理时，先按对应实施计划和实际消费者确认当前状态，不把规划中的迁移当作已完成。
- 脚本、工作副本与开发临时产物按 `scripts/INDEX.md` 处理；代码与测试改动遵循 `docs/rules/testing.md`，计划与记录遵循 `docs/rules/document-lifecycle.md`。

## 1. 确定本批范围

从 docs/inbox.md 的既有需求与采用决定起步，列明本批主题、来源篇目或对象、采用内容、目标文件以及需处理的事实缺口。已有候选与用户决定直接沿用，不重新做整库候选评估。发现同主题内容时优先合并或补充，只有独立阅读需要时才新建篇目。

工程批次由对应 plan 与 notes 承载；轻量修订使用已有任务记录，不为每个段落建立新计划、证明表或审批链。范围外问题回到 inbox，不挤入当批验收。

## 2. 取得材料并保留来源定位

按需要读取来源；已有固定版本可直接查阅时，无须额外复制。确需暂存的稿件落入 knowledge/raw/<批次>/，只放本批所需材料，不复制整个外部库。脚本、运行输出和仓库工作副本按 scripts/INDEX.md 放在 dev-temp/work/<任务>/。

在本批 notes 或既有任务记录中写明外部仓库地址、所用提交、源文件及采用段落；解包数据另记录对象 ID、字段及必要转换口径。本地实践记录影响判断的条件和依据。来源信息随正式采用结果保留，raw 内的头注不能成为唯一溯源记录；不新增哈希、指纹或全量来源副本台账。

## 3. 分别处理 facts 与散文

涉及 facts 增补或修订时，从固定版本解包数据核对条目与转换，更新正式 facts 输入及其必要映射记录；不得从散文或模型回答补填机械事实。目录变更不等于已完成来源映射验证。

散文按两份 spec 整理机制、分工、条件和取舍，结合现有正文去重。处理源稿中的外部目录、状态标记、协作指令和内部链接，保留适用的玩家内容。遇到 facts 缺项时按写作 spec 的来源与审阅边界处理，不把全量 facts 刷新作为所有散文的前置。

## 4. 正式落位并联合审阅

正式散文落入 knowledge/base 或 knowledge/guides，按需要更新 corpus-manifest、prose-links 及实际受影响的计数或定位。技能数据使用正式 facts 出口，不把临时稿注册成事实关联或检索对象。来源记录使用持久的仓库、版本、篇目或本地实践依据，正文不依赖 raw 文件才能理解或追溯。

按写作 spec「执行与维护」组织当前批次的复核与人类参与，记录采用和冲突处理结论；修订集中于发现的问题及受影响内容。已有采用决定直接沿用。

## 5. 按变更验证

散文运行 `pnpm run check:prose-terms` 与 `node scripts/doc-check.mjs`；文件、分块、manifest、facts 或关联变化时，补相应既有完整性检查。按写作 spec 的触发条件离线核对相关正文与必要事实，记录实际送达结果。

代码与测试变更遵循 docs/rules/testing.md，合并门禁仍以 scripts/gates.mjs 与 scripts/verify.mjs 为准，不新建一套语料门禁。施工中的计划未勾选项按 doc-check 的现有规则报告，不能以虚报完成消除错误。检查通过不替代散文联合审阅，也不代表模型质量改善；日常添加不要求付费运行或答对率达标。

## 6. 清理临时材料并交付

先确认正式成果、来源定位、审阅结论和必要验证已落位，再按本批明确文件范围清理 raw 原稿、摘录及中间稿。已采用、未采用和被替换的材料均不因“以后可能有用”永久保留；部分采用只保留已确定续作批次所必需的部分，并在原记录写清剩余任务与清理时点。仅列入候选或笼统的未来待办，不构成保留原稿的理由。

清理前核对正式正文、facts 加载、manifest、prose-links 和当前测试是否仍依赖拟删文件；存在正式消费者时先完成迁移或替换。按文件列出并检查路径，禁止直接递归删除整个 raw。已跟踪文件按普通版本控制删除；dev-temp 临时产物沿用 scripts/INDEX.md 的显式清单流程，不扩大临时清理器的目录权限。清理不是必须新增脚本或维护长期清单的理由。

清理后确认本批无残留原稿、正式引用可用；清理影响定位或测试输入时，复核相应检查。在原记录简述采用结果、验证结果和清理范围，历史提交及已归档记录保持原貌。若任务中断或交接，只保留继续实施必需的材料，并记录具体续作与清理条件；取消且无后续用途的材料同样清理。不要转存到另一目录作为永久原稿库，也不等待全库内容添加完才清理已完成批次。

本批完成以正式内容与必要 facts 已落位、联合审阅结束、适用验证完成、临时材料清理完成为准，不以 raw 中长期存有原稿作为完成凭据。
