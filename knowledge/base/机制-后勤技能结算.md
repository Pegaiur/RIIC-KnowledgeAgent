# 后勤技能结算机制

> 来源：`knowledge/base/机制-基建总览.md`、各设施机制文与 `knowledge/references/技能-*.md`。本篇只整理来源中能直接确定的局部关系，不把旧散文的九步顺序恢复为统一算法。

## 先区分结算对象

后勤技能的文字可能作用于生产力、订单获取效率、订单上限、仓库容量、无人机充能、心情消耗/恢复、特殊订单或中间资源。它们是不同字段：

- 制造站生产力按 `1 + X + Y` 读取，仓库容量另行记录，具体见 `机制-制造站.md`；
- 贸易站的订单获取效率、订单上限和订单类型分别读取，具体见 `机制-贸易站.md`；
- 心情净变化按设施和适用技能计算，宿舍恢复按 `机制-宿舍.md` 与 `机制-心情与工休.md` 计算；
- “每个设施”“每名成员”“当前设施内其他成员”等限定词决定作用对象，不能把同一数字跨字段或跨设施复用。

因此，容量、效率、心情和订单类型即使出现在同一条技能文本中，也必须按各自字段处理；只有技能原文明确写出转化关系时，才允许从一个字段得到另一个字段。

## 中间资源的生成与转化

技能可能先生成全局或设施内资源，再由另一条技能把资源转化为生产力、订单获取效率或其他效果。生成量不是最终效率，转化比例、对象和上限必须逐条读取：

- `knowledge/references/技能-制造站.md` 中的感知信息、思维链环、标准化类技能和人间烟火等关系，分别由对应技能文本声明生成或转化；
- `knowledge/references/技能-贸易站.md` 中的感知信息、无声共鸣和木天蓼等关系，也只有在技能文本明确转化为订单获取效率时才进入该字段；
- 控制中枢、宿舍和办公室产生的资源若被其他设施技能读取，应按“资源名称 + 作用范围 + 当前设施”一起核对，不能只按同名资源连接。

本篇不假定所有资源都在同一时刻结算，也不假定资源生产者离开后历史累计值继续有效；这些状态依赖具体技能原文。

## 固定加成与跨设施影响

设施自身人数项和技能加成先按目标设施的机制公式读取。技能若明确写“每个发电站”“每个贸易站”“每间宿舍”或“所有制造站”，其加成属于对应的设施数量或跨设施效果，不是普通同站成员的生产力数字。

一个已确认的局部关系来自 `knowledge/references/技能-制造站.md` 的自动化技能：它会将当前制造站内其他成员提供的生产力归零，但明确排除“根据设施数量提供的加成”，同时保留其文字明确给出的发电站计数加成。因此，“归零”不能被泛化为“清空制造站所有来源”。同文件中按贸易站数量提供赤金生产力的技能也必须按其指定产物读取。

跨设施技能的作用对象仍以原文为准；例如控制中枢 references 中“所有制造站”或“同一贸易站”的措辞，不能改写成控制中枢成员自身的生产力。

## 容量、差值与他人效率

订单上限和订单获取效率不能直接相加。只有技能文本明确读取容量或订单差值时，容量才会参与该技能的结算：

- `knowledge/references/技能-贸易站.md` 的“招商引资”明确读取当前贸易站内成员提升的订单上限，并把它转化为订单获取效率；这不是所有订单上限的默认换算；
- 同文件的“摊贩经济”明确读取当前订单数与订单上限的差值；差值型技能应以当前状态为输入，不能用静态上限替代；
- 制造站中“其他成员提供的生产力”与“根据设施数量提供的生产力”是不同输入，槐琥的 `配合意识` 文本明确排除后者；这类排除条件优先于泛化的“同站生产力都算”。

如果多条技能都带有“特殊叠加规则”或读取他人效率，references 只确认到局部关系时，就保留该局部关系，不自行排列全部技能的先后。

## 归零与清除自身影响

“归零”必须同时读取作用对象和作用域：

- 贸易站 references 的“低语”作用于当前贸易站内其他成员提供的订单获取效率，并另行写出自身效果；它不是把自身效果或订单类型规则一并归零；
- 制造站 references 的自动化技能作用于当前制造站内其他成员提供的生产力，并明确不包含根据设施数量提供的加成；
- “清除/消除自身心情消耗影响”只处理被技能指定成员的自身心情效果，不等同于清除设施人数项、控制中枢全局减免或其他成员向设施提供的效果。`团队精神`、`杯莫停`等例子分别以当前制造站或当前控制中枢的技能文本限定对象。

所以，“归零”不等于“失去进驻资格”，也不等于“所有字段都清零”；必须保留技能文本未命中的字段。

## 取最高与可叠加

同类效果只有在技能文本或设施机制明确写出“同种效果取最高”时，才按同一对象的最高值处理。`knowledge/references/技能-宿舍.md` 对多类恢复技能直接写出该规则，`knowledge/references/技能-控制中枢.md` 对部分全局效果也写出该规则。

基础人数项、技能额外项、设施数量项和跨设施项是否相加，要分别回到对应机制文和技能原文；不能因为两个数字都带百分号就相加，也不能因为同名技能存在就叠加。解锁并存与提升替换的通用语义见 `机制-技能解锁与练度.md`。

## 订单类型与心情效果

特殊订单、贵金属订单分布和普通订单获取效率属于不同结算对象。`机制-贸易站.md` 已确认的固定特殊订单不受普通订单获取效率影响；改变交付数量或报酬的技能也不因此成为订单获取效率。

心情消耗/恢复是另一个字段。技能文本写明的心情增加、减免、全体恢复或自身恢复，应进入实际心情净变化；它不会自动改变生产力、订单获取效率或订单类型。若净变化达到 0 或转为恢复，工作状态随之改变，但这不表示技能的其他字段被取消。

## 未确认关系与使用边界

当前来源不足以证明一个适用于所有设施和所有技能的统一九步顺序，也不足以证明所有资源生成、容量差值、归零、订单类型和心情效果之间存在固定全局先后。α/β 多技能分布观测、不同特殊叠加标注和旧散文的完整顺序不进入本篇。

回答具体问题时，先定位目标设施机制块，再读取对应 references 技能原文；若原文只确认局部先后或作用范围，就只输出该局部关系，并明确其余顺序仍待核验。
