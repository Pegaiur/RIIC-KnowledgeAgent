# Agent 单题执行记录草案

> 创建日期：2026-09-04
> 修订日期：2026-09-05
> 状态：提案中

## 目标与依据

在不改变 Agent 路由、提示词、预算和回答行为的前提下，为每道基准题保存一份能人工复盘的执行记录。首版交付 `trace.jsonl`，用于检查工具选择、实际参数、返回内容和结果注入，判断错误发生在哪一步，或指出还缺什么证据。

当前 `records.jsonl` 已逐轮记录 token、成本和模型请求的工具名，`answers.md` 保存最终答案，`injected.json` 保存每题累计注入的 RAG/grep chunk ID。缺口主要是原始参数、实际执行参数、facts 返回内容，以及被强制检索丢弃的提前回答。

[2026-09-04 基线复盘](archive/plan-rag-facts-quality-loop.md)中，F05、S08 在 gold 完整注入时仍答错，facts 参数和结果则没有持久化。因此先补充可直接阅读的调用证据，自动统计与执行逻辑重构移出首版。

## 首版方案

### 1. 每题保存一个记录对象

在现有运行目录新增 `trace.jsonl`，每行包含 `schemaVersion: 1`、`queryId`、`question`、`status: completed | failed` 和按发生顺序排列的 `events`。失败时附上错误摘要、阶段（`llm`、`tool` 或 `runner`），以及当时可确定的轮次和工具调用 ID。

只保留三类事件：

| 事件 | 记录内容 |
|------|----------|
| `llm_call` | 轮次、实际提供的工具名、耗时、已有 usage 和 `truncated`、公开的 assistant content、模型返回的工具调用 |
| `tool_call` | 轮次、工具调用 ID、工具名、原始参数字符串、实际传给检索函数或 store 的参数、有序命中 ID、实际注入 ID、耗时、实际写回模型的完整文本 |
| `control` | 最少检索约束触发的轮次及追加的引导文本；被丢弃的提前回答由同轮 `llm_call` 保留 |

参数回退、参数拒绝、预算拒绝和未知工具等特殊处理，在现有分支直接填写一个原因字段。正常执行不另建 `argumentStatus × outcome` 状态模型，也不通过解析结果文本猜测处理原因。执行后没有命中用空 ID 数组表达；没有执行检索时，实际参数和命中字段缺省，不能记成空结果。

usage 直接复用 provider 返回值，成本仍由现有逻辑计算。provider 当前仅暴露 `truncated`，首版沿用该字段，不为原始 `finish_reason` 扩展接口。

### 2. 在现有调用位置采集

runner 为每题创建记录对象，经 `AgentOptions` 的可选字段传入 `runQuery`；在当前 LLM 调用、工具分支和结果回写处记录。调用前先登记轮次与调用身份，完成后补充结果和耗时，保证调用抛错时仍能知道失败的是哪一步。`AgentResult` 保持原有形状。

采集只使用已有结果和局部变量：

- RAG/grep：记录实际传入的 query、检索返回顺序对应的 chunk ID，以及本次实际写入上下文的 chunk ID；沿用现有截断判定，不补取评分或另建行明细结构。
- lookup/query_operators：在现有序列化之前以卡片已有的 `canonical` 标准名记录命中与注入标识，参数记录到 store 调用边界；不额外追踪 store 内部的别名解析或规整过程。
- 每次调用独立保留命中与注入 ID，跨轮重复仍保留；不能用累计去重后的 `injectedIds` 差集代替本次结果。
- 写回文本取实际追加的 tool message content，包含无匹配、参数无效或超限提示；除敏感值遮蔽外不再截断，也不从候选结果重新拼装。

LLM 响应在分支处理前记录，确保最终答案和被丢弃的提前回答都可见。仅在结束时导出 `messages` 无法保留这两类内容，也看不到参数回退后的实际调用。

### 3. 由 runner 落盘并保留失败前记录

每题结束后向 `trace.jsonl` 追加一行。`runQuery` 抛错时，runner 沿用现有失败处理，将已经采集的事件和失败位置一起写出，继续下一题；工具异常的传播方式保持不变。现有成本、答案和注入记录的写入协议不变，首版不承诺进程被强杀时保留当前未完成题目的记录。

当前源码没有可复用的统一脱敏函数。首版显式选择上表字段，避免序列化整个 config、请求 headers 或隐藏推理；在写盘副本中定向遮蔽本次配置的非空 API Key 等已知敏感值，包含错误摘要中的匹配值。遮蔽不修改传给模型的消息，不扩展成通用敏感内容识别系统。

## 首版之外

以下能力移出当前交付范围，仅在实际复盘暴露需要后重新评估：

| 能力 | 后续评估条件 |
|------|--------------|
| `executeKnowledgeTool` 与 `ToolDiagnostics` | 工具执行边界重构继续由现有代码债务 A1 跟踪，不作为记录能力的前置条件 |
| `searchDetailed()`、BM25 分数和 grep 评分明细 | 有具体错题需要解释候选排序，现有 query、命中顺序和文本不足以定位 |
| `diagnostics.md`、gold 快照、自动覆盖率与重复率 | 人工复盘已反复使用同一统计，值得固化；若引入历史覆盖率复算，再一起明确 gold 快照与自定义题集口径 |
| trace 体积治理与专用查看工具 | 实际产物大小或阅读成本已妨碍复盘 |

首版不引入新第三方依赖、事件总线、通用追踪 API、数据库或 replay。工具 schema、检索算法、fallback、预算和 prompt 的调优另行评估。trace 不依赖 gold，现有自定义 `--questions` 题集可直接记录。

## 实施与验收

1. **固定现有行为**：复用 `agent.test.ts`、`facts-tools.test.ts` 中的 Vitest provider mock，在固定时间下记录每次调用当时的消息和工具参数快照，作为改造前基准；无需新建 scripted provider 设施。
2. **补充采集与落盘**：在现有循环增加记录点和逐题写盘，覆盖正常单/多工具、参数回退与拒绝、空结果、未知工具、预算拒绝、强制检索，以及 LLM/工具异常。复用现有用例，只补记录完整性、失败保留、注入截断与敏感值遮蔽所需的断言和场景。
3. **验证行为中立**：固定 mock 下，改造前后消息序列、工具参数和最终 `AgentResult` 一致，异常传播一致；传入或不传入记录对象均成立。确认事件顺序正确、实际写回文本一致，现有 typecheck/test/build 通过。
4. **验证复盘价值**：选取几道代表题做真实调用并人工阅读记录，优先包含基线中的 F05/S08、提前作答的 F10，以及曾使用 facts 的题目。能据记录说明错误发生在哪一步，或明确尚缺的证据；首版不以完整 20 题复跑或自动报告为验收门槛。

真实模型的回答和成本波动仅作为调查线索，不能凭与历史基线不同就认定记录改造造成回归。行为中立由固定 mock 验证，真实调用用于确认记录是否有助于复盘，不要求旧错误必然重现或每题都能完成归因。
