# ADR-009：试验工作采用 exp 文档并仅保留过程结果结论

- 日期：2026-09-09
- 状态：已实施

## 背景

本项目包含探针、对照、测量、诊断、历史运行分析和答案核查。此前 inbox 主要路由至工程 draft/plan；试验结束却没有工程交付时，记录滞留为草案，或混入已完成计划归档。report 与 spec、草案的职责交叠，原始数据和导出副本也形成额外维护负担。

## 决策

仅新增 `exp-<主题>.md` 类型，所有试验性工作由 inbox 路由到 exp。活动文档位于 docs 根目录，已结束或已取消后移入 `docs/archive/exp/`，归档与发版解耦。正文仅含过程、结果、结论，格式以 [exp 模板](../templates/exp.md) 为准；状态区分设计中、进行中、暂缓、待审定、已结束和已取消。未执行不能写成已完成，负面或证据不足的结果也可正常结束。

取消 report 文档类型；核查记录归 exp，跨运行复用的判定规则仍归 spec。工程提案保持 draft → plan，架构决定仍归 ADR；试验形成工程交付时另建 plan 引用 exp，不将实验正面结果视作正式策略变更授权。既有 plan 类型、位置、正文和清单不调整，仅修正迁移导致的可点击链接。

exp 最终只保留文内过程、结果和结论，不额外保留试验数据、原答、轨迹、截图、数据集、一次性脚本或附件。不把原始数据整体转储进正文。执行期间必要临时文件在任务结束、暂缓或交接前清理；重启需要的数据重新取得，无法取得时说明限制。不为 exp 导出或保留共享快照，不通过改称工程资产规避这一边界。已有正式非 exp 消费者的资产按真实用途维护，不能仅凭 spec/plan 中的历史引用认定仍有用途。

现存 spec v4 独立审定采用一次性过渡，仅限 A/B 两次运行（2026-09-07T14-55-33-663Z、2026-09-08T03-21-55-405Z）实际需要的既有原答、trace、injected、records、必要 meta 和快照。审定完成或取消时清理，不扩增副本，新 exp 不继承该例外；本次不启动或取消审定，具体未清理输入及终止条件写在 [v4 核查](../exp-answer-baseline-v4.md) 结论中。

已跟踪快照按普通版本控制变更移除；临时原件通过显式清单清理，不绕过运行结束、指纹、Git 跟踪和 .keep 等保护，也不清除 Git 历史。操作约定统一由 [生命周期规则](../rules/document-lifecycle.md) 和 [scripts 导航](../../scripts/INDEX.md) 承载。

## 理由

试验产出是问题的观测与判断，并不必然交付功能。独立类型允许试验按自身状态结束，避免为了归档虚构工程验收清单。单文档保留必要细节降低附件、重复索引和跨文件同步成本。

## 备选方案

- 继续使用 draft/plan：不能区分未定稿工程方案和已经结束的试验，不采纳。
- 独立 experiments 目录并保留 report、数据附件和试验台账：增加类型和维护成本，不采纳。
- 立即删除所有历史输入：会破坏既有待审定工作，也会误删有独立工程用途的资产；采用限定的一次性迁移过渡。

## 后果

原始数据清理后不能保证完整重放或重新核查；文内必须保留必要的测量、判定依据、失败及不确定性，并说明可复核范围。不得把清理后的历史引用当作仍存在的附件入口。

六份既有未归类记录迁为 exp，spec 的运行观测移至 exp，现有 plan 归档脚本不变。inbox、AGENTS、生命周期与脚本收尾规则、发布技能同步适配。未执行、待审定、撤回说明及历史事实不得因迁移改变；不重新评分或调用模型。
