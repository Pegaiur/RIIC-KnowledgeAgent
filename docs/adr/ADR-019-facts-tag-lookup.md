# ADR-019：facts 显式标签反查入口

- 日期：2026-09-13
- 状态：已实施
- 替代：局部例外 ADR-015 决策 1「不再保留单字符串入参或第二字段」与 ADR-010 §5「facts 模式仍只开放 facts_search，不新增参数」；`queries` 的精确词条语义、六类词条与别名/子串/组合路径继续有效。

## 背景

docs/plan-index-and-tags.md 第 3 步要求「现有 facts 工具增加显式标签入口」，派生链为 标签 → 设施 → 技能 → grant → 干员，卡级去重聚合、同卡多命中保留依据，并明确「不自动合并同名职业、设施和标签」「补证据不扩大候选」。当前来源标签只以原文形式落在 `RecordSkill.target`（`〔标签：…〕` 注记），`FactsMatchCategory` 六类不含标签，`termQuery` 仅按 `target` 子串偶然命中，不存在标签 → 持有者的反查入口。

现状约束：`facts_search` 参数为字符串数组 `queries`（ADR-015），名称与职业/设施/技能组/标签可能同名；工具结果引用完整的记录卡并要求技能—持有者—解锁—替换逐项呈现（ADR-010）。宽查（设施/职业词）当前完整返回、无分页，ADR-015 §50 要求若引入分页须同时重定义 `complete` 与送达计数。

## 决策

1. `facts_search` 增加可选参数 `tags`（非空字符串数组，`minItems 1`）；`queries` 与 `tags` 互斥，至少提供其一。普通 `queries` 的精确词条语义、六类词条与别名/子串/组合路径不变。
2. 标签以技能行来源标签（`SkillFact.tags`，落到 `RecordSkill.tags`）为源，只做 trim 后精确匹配，不做别名、子串或模糊扩展；标签名与职业/设施/技能组同名时不自动合并——走 `tags` 只返回标签派生结果，走 `queries` 只按六类精确词条/别名/子串/组合。
3. 派生链：标签 → 设施（`REFERENCE_ROOMS` 固定序）→ 命中技能 → grant（持有者、解锁、替换）→ 干员。卡级按 canonical 去重聚合；同卡经多个技能/设施命中时，保留全部命中依据（标签、设施、技能名、解锁与替换），不合并为单一效果。
4. 展示：保留完整记录卡；每卡前置命中设施技能；按设施与 canonical 名称稳定排序；「描述相同」与「完整效果等价」分开表达，不计算综合收益，不把组合收益写成单人固定值。
5. 分页：不静默 Top-N，不截断卡片。提供可选 `offset`（非负整数，默认 0）与固定页上限；结果给出本次命中总数、本页返回数、`complete` 与续读 `offset`。`complete=true` 仅表示本次匹配的卡已在本页读完，不代表标签能力或来源范围穷尽。首版固定页上限取 20 张记录卡（`FACTS_TAG_PAGE_CARDS`）：按真实来源标签复核，44 个标签中最大命中为「订单效率」73 张、共 12 个标签超过 20 张，取 20 可在限制单次结果体积的同时用 `offset` 覆盖全部命中。
6. 版本与元数据：递增 `TOOL_SCHEMA_VERSION` 与 `FACTS_RESULT_VERSION`；结果元数据新增标签分页信息（offset、页上限、matchedCount、returnedCount、complete、nextOffset），`queries` 路径继续完整返回。tags 路径的 `resolution.items[].canonicals` 表示该标签的命中集合（不随本页收窄），实际送达计数与覆盖范围以 `tagPage` 为准。
7. 目录同步：标签入口接通后，把 knowledge/关键词目录.md 中来源标签行的入口标注从「标签独立入口尚未接通」更新为可用 `tags` 查询，并重算生成物。

## 理由

- 独立 `tags` 参数使标签派生与精确词条查询语义分离，避免同名职业/设施/标签被自动合并，符合 ADR-010 的「明确引用与自然语言搜索分开」。
- 以技能行来源标签为源并保留 grant/解锁/替换，保证「技能—持有者—解锁—替换逐项对应」，不因同标签把不同技能视为完整效果等价。
- 显式分页元数据使宽标签覆盖范围可判定，落实 ADR-015 §50 对分页须重定义 `complete` 与计数的要求。

## 备选方案

- 复用 `queries`，按同名类别自动识别为标签 — 放弃原因：会与同名职业/设施/技能组混合，违反「不自动合并同名职业、设施和标签」。
- 新增独立标签工具 — 放弃原因：plan 明确「现有 facts 工具增加显式标签入口」，且三份计划共同边界为不新增模型工具。
- 从零建立标签元数据 — 放弃原因：来源标签已在技能行注记中维护，另建副本会与真源漂移。
- 首版不做分页、宽标签完整返回 — 放弃原因：plan 要求宽标签不静默 Top-N 且必要分页明确覆盖范围，显式分页更可控；代价是协议与元数据变更。

## 后果

- 需同步：工具 schema 与版本、facts 结果版本与元数据、参数解析分支、标签索引与渲染、trace/report 等元数据消费方、知识库目录标签行，以及相关测试。
- `RecordCard.skills[]` 增加来源标签字段（投影自 `SkillFact.tags`）；fixture 兼容回归按既有可比较字段进行，不受新增字段影响。
- 标签入口只做精确匹配，未收录标签返回明确的「未收录」结果，不猜测、不做模糊兜底。
