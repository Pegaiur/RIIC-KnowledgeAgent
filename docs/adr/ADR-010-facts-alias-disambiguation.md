# ADR-010：facts 别名、集合词条与消歧真源及查询契约

- 日期：2026-09-09
- 状态：提议

## 背景

`facts_search` 目前只认规范词条，精确匹配六类索引（干员/技能/技能组/设施/阵营/职业），别名、简称、合称、俗称一律查不到；`RecordCard.aliases` 恒为空，`TODO(tech-debt) R5-2` 与 [ADR-002](ADR-002-facts-record-card-source.md) 均把此项后置。四模型统合报告显示失分集中在专名消歧（S03 深巡/乌尔比安、异格档位）与类别成员（S08 格拉斯哥帮、散件边界）。

现成真源 [歧义.md](../../knowledge/references/歧义.md) 有三节：31 组子串包含对（标注"自动生成"）、简称与合称（人工维护）、官方术语表同组。但该文件由 `scripts/build_refs.py` 生成（脚本不在本仓），文件头声明"请勿手改"，且 [数据源.md](../../knowledge/references/数据源.md) 声明该脚本"不含手工维护的数据"——不能作为运行时解析源。

实测约束（2026-09-09）：705 个 `SkillFact` 去重后仅 697 个技能名，存在 8 组重名（澎湃紊流、得心应手、丰富工作经验、领袖、以身作则、辅助专精·α、红龙之血、作战指导录像）；[类别.md](../../knowledge/references/类别.md)「规则说明」内「特殊加成」「特殊叠加规则」各 2 条同名。因此技能身份不能只用名字，`termId` 不能只用 `canonical`。

语料盘点（2026-09-09）：可检索 `guides/` 与 `raw/组合知识库.md` 各有 **19 个带成员表的组合名**（贸易 9 / 制造 8 / 跨设施 2），成员按核心/重要/次级分层；[歧义.md](../../knowledge/references/歧义.md#L46-L76) 只明确标注 5 个合称（德狼、能蕾、银崖、孑拉德、龙门中枢组），其中 4 个可映射到组合名。`raw/组合知识库.md` §9 另列 18 个旧称/废弃名。存在三处需先规范化：① 「龙门中枢组」合称（2 人）与组合成员表（3 人）不一致；② raw「红松林骑士组」与 guides「红松骑士团组」命名不一致；③ 组合名与阵营/干员/技能/资源同名约 14 组。

工具侧现状：[ADR-007](ADR-007-single-term-facts-tool.md) 已把 facts 收敛为单词条精确入口，`facts_search` 不接受多条件、不做分词/子串/模糊兜底，工具本身没有"反问"能力。

## 决策

阶段 1 做 **term + alias + 集合词条**（现有六类规范名 + 别名/消歧 + 组合名集合 + 查询时契约）：

1. **真源落点**：别名/消歧与组合名集合词条的人工数据登记在 `bench/src/facts/curation/*.ts`，随代码版本控制；`歧义.md` 与 `guides/` 组合散文仅作人工登记依据，不做运行时解析。初稿由 agent 生成，人工复核后维护；不在运行时用 LLM 生成。
2. **覆盖范围**：
   - 别名：`歧义.md` 第一节 31 组子串对与第二节简称/合称/俗称/旧称全部登记（含子串对，不靠运行时推导）；第三节"官方术语表同组"不登记——现状同名跨类别并集已覆盖。
   - 集合词条：19 个组合名（guides 组合标题 + 成员表，贸易 9 / 制造 8 / 跨设施 2）登记为集合词条，按核心/重要/次级分层保存成员；5 个明确合称映射到对应集合词条。语料无成员表的体系名（如「推王龙门」）暂不登记。
3. **target 范围**：阶段 1 别名与集合词条只指向干员，`targets` 用 `operator:<canonical>`；避开技能重名与 `termId` 唯一定位问题。
4. **不回写卡字段**：别名与集合词条不进 `RecordCard.aliases`（该字段保持为空），作为独立表由运行时/脚本组装进 store 索引。
5. **查询契约**：`facts_search` 仍只接受一个词条、不分词、不做子串/模糊兜底；按以下类型输出：

   | 查询类型 | 行为 | 输出标注 |
   |---|---|---|
   | 规范名 | 精确命中，整卡返回 | `精确词条：X` + 命中类别 |
   | 唯一目标别名 | 归一后返回目标卡 | `别名命中：推王 → 推进之王` |
   | 合称/集合词条 | 返回成员卡 + 分层标注 | `组合命中：红松骑士团组 → 焰尾（核心）、薇薇安娜（核心）…` |
   | 子串歧义（设施不重叠） | 返回候选卡 + 各卡设施 | `可能指：临光（控制中枢、宿舍）/ 耀骑士临光（训练室）` |
   | 子串歧义（设施重叠或未点明） | 返回候选卡 + 设施线索 + 反问提示 | `需消歧：… 请确认设施或具体干员` |
   | 旧称/废弃名 | 归一为规范组合名或明确拒绝 | `旧称：巫恋裁缝核 → 龙舌兰组` / `该名称已废弃，不作为组合` |
   | 未收录词条 | 保持现状 | `未收录精确词条：X` |

   工具不反问、不静默挑一个；反问由 `knowledge/AGENTS.md` 决策契约 + 上述标注承载。
6. **规范化前置**：先统一命名与旧称口径——① 「龙门中枢组」以组合成员表为准（核心斩业星熊、重要诗怀雅、次级陈），`歧义.md` 的 2 人理解并入组合分层；② 规范名取 guides 的「红松骑士团组」，`红松林骑士组`/`红松林经验体系` 作旧称；③ `raw/组合知识库.md` §9 的 18 个旧称/废弃名建立归一或拒绝映射；④ 组合名与阵营/干员/技能/资源同名时按现有"同名跨类别并集 + 命中标注"处理，不静默挑一个。
7. **版本**：`TOOL_SCHEMA_VERSION`→7（工具描述提及别名与组合名支持），`FACTS_RESULT_VERSION`→3（结果语义与标注变化），新旧快照必须分组。

## 理由

- 复用现有精确索引与卡序列化，不引入自然语言解析、模糊匹配或相关性检索，与 ADR-007 取舍一致。
- 合称改为以语料的组合名成员表为真源，而不是仅凭 `歧义.md` 的 5 条手工 target：19 个组合名都有明确核心/重要/次级成员，可核对、可断言，减少猜测。
- 集合词条与子串歧义返回候选集合并附设施/分层线索，落实 `歧义.md` 的硬规则（不许静默挑一个），把"反问"交还给有决策契约的 Agent 层。
- 数据放 `facts/curation/*.ts` 与代码同版本控制，避免被生成流程覆盖，也不需要本仓不存在的上游脚本。
- target 限定干员，回避技能重名导致的 `termId` 唯一定位复杂度；技能/设施/阵营别名如确有需求另议。

## 备选方案

- 扩 `歧义.md` 并新增解析器 — 放弃原因：生成文件且脚本不在本仓、声明不含手工数据，手改会被覆盖。
- 新建 `knowledge/references/名词表.md` 作为运行时源 — 放弃原因：用户选择与代码同版本控制的 curation 落点。
- 合称只手工登记 `歧义.md` 的 5 条 — 放弃原因：语料已有 19 个带成员表的组合名，手工猜 target 既少又不稳；改为集合词条。
- 自动推导 31 组子串对 — 放弃原因：用户要求全部手工登记，便于人工维护与消歧线索标注。
- 运行时用 LLM 生成别名/俗称 — 放弃原因：违反编码核心约束 #9，不可复现。
- 别名回写 `RecordCard.aliases` — 放弃原因：合称/集合词条是"词条→多卡"，不属于单卡字段；回写会改动卡语义与 fixture。

## 后果

- 需新增：curation 别名与集合词条结构、store 索引与 `factsSearch` 解析分支、`serializeFactsMatches` 输出标注、两个版本号 bump、`knowledge/AGENTS.md` 消歧口径、测试与计数断言（31 组子串对、19 个组合名、别名索引、卡字段仍空）。
- 规范化前置项（龙门中枢组、红松命名、18 个旧称、同名碰撞）必须先落地，否则集合词条会带冲突口径。
- 阶段 2（`equivalenceGroup` / `resource` / `rule` / `facilityGroup` 类别、表 C/D/E 关系边与条件词表、数值化）不在本 ADR 范围。
- 技能等非干员别名若后续需要，须另定可读唯一定位（技能重名 8 组）。
