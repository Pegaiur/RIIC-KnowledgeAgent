# ADR-010：facts 别名、集合词条真源与同名全部返回契约

- 日期：2026-09-09
- 修订日期：2026-09-10（二次修订：纳入子串对；三次修订：去除旧称重定向与拒绝路径，后续清理旧称说明及专项验收要求）
- 状态：已实施
- 替代：局部扩展 ADR-007 的精确匹配契约，新增已确认干员别名、确定搭配集合与已确认子串对；保留六类规范查询及同名全部返回，不含任意子串扫描或模糊兜底；三次修订移除旧称重定向与拒绝路径

## 背景

`facts_search` 当前精确查询干员、技能、技能组、设施、阵营和职业，并返回同名跨类别并集。`RecordCard.aliases` 恒空，ADR-002 与R5-2留有名称真源缺口。扩展入口需要保留集合身份、成员归属及多个来源，不能只用一份无路径的卡片列表表达。

正式 guides 的搭配候选盘点为19个（贸易9、制造8、跨设施2），含红云任选分支、裁缝任选、五选四及开放技能类别成员。简写合称不能直接等同于完整搭配，例如“银崖”不自然包含喀兰贸易组其他核心。

用户于2026-09-10明确：简写合称暂不支持；多人集合只支持确定阵营与搭配；反问及消歧措施不在本计划范围内，仅保留同名重叠全部返回。本次修订取代本ADR先前的相关策略设计；运行时实现已按计划完成，发布元数据收束尚未执行。

用户于2026-09-10二次裁决：在保留“不做消歧、不反问”的前提下，将 knowledge/references/歧义.md 第一节的31组“短名 ⊂ 长名”子串对纳入登记，按短→长单向、全量返回（见 §6）。本条款实施时为 TOOL_SCHEMA_VERSION=8、FACTS_RESULT_VERSION=4，后经三次修订将结果版本升至 5（见 §7）。

用户于2026-09-10进一步收窄三次修订范围：仅清理 `legacyNames` 承载的旧称重定向与拒绝实现；组合／搭配命名标准与语料治理暂缓，仅保留待办。§7 已实施并取代 §1–§6 中相关旧称条款；别名、子串对、搭配与同名全部返回继续保留。实施与回归见 docs/archive/plan-facts-legacy-purge.md。

后续提交 `dd2f23e` 已清理三个旧组合名在语料、ENTITY_WORDS、fixtures 注释及搭配条件中的过渡说明。2026-09-10 用户要求修正删除过时描述和要求，现同步该范围并取消固定旧词的专项验收；决策正文移除已废弃的兼容规则，查询统一遵循现有登记及通用未收录契约。组合／搭配名称结构标准仍暂缓，历史实施及评测结果不回写。

## 决策

### 1. 范围与真源

- 保留六类规范词条查询，新增证据充分的干员别名与正式搭配规范名。别名若有多个已确认目标，全部登记、全部返回，不选择默认目标。
- 不支持德狼、能蕾、银崖、孑拉德等简写合称，不以别名绕道接入；未收录时不拆词、不猜测成员。
- 新增已确认干员子串对（短名是长名的真子串，共31组），按短→长单向展开并全部返回；子串对只以人工登记清单为准，不做任意子串扫描，也不按字符串包含关系自动扩候选（见 §6）。
- 不设计反问、设施/上下文选择、指代确认提示或相关回归，不修改 `knowledge/AGENTS.md` 与旧检索语料的相关规则；子串条款对真源反问策略的覆盖只记录于本ADR与实施计划。
- 人工登记在 `bench/src/facts/curation/terms.ts`，独立于九设施CurationBatch；不回写RecordCard.aliases，不新增哈希字段。阵营成员仍来自事实卡索引，不另建人工副本。
- 用户最新裁决优先；身份/设施/阵营/技能以references为准，搭配定义以正式guides为准。生成的名称说明和raw只可提供核对线索，不解析为运行时源、不反向覆盖正式知识；两份新raw仍不纳入。
- evidence记录来源相对路径与小节标题，来源变更同步复核。19个搭配候选按具名清单确认登记或缺证原因，不以数量代替审定。

### 2. 数据身份与搭配边界

- 干员目标采用 `operator:<canonical>`，搭配采用 `combo:<规范名>`；不引入阶段2的新类别或技能身份体系。
- 子串对沿用 `operator:<canonical>` 目标身份，仅限干员名，不引入技能、阵营、设施或阶段2的新身份。
- 搭配保存显式成员及核心/重要/次级/挂件/可选角色、条件摘要、来源与覆盖范围。保留原有练度、设施分工、任选数量等条件，不实现条件求解器，也不据成员卡推导完成度。
- 技能类别等开放成员范围以文字保留并标注非穷尽；阶段1只返回明确登记的卡片，不动态扩充名单。
- “龙门中枢组”保留该规范名，成员为斩业星熊、诗怀雅、陈及正式guides分层，不另保留同名二人合称。
- 红松骑士团相关搭配使用“红松骑士团组”为规范名；它与“龙门中枢组”是独立身份，不互相归一。
- 禁止同一身份重复定义、重复目标/成员、悬空目标及失效证据；允许同词对应多个身份，不施加全局字符串唯一限制。

### 3. 同名全部返回

query仍为唯一输入，trim后精确查索引。一次查询收集六类规范词条及已登记别名、子串对、搭配的全部命中，不以首个命中提前返回，不按类别或上下文择一。

- 同词命中规范名与别名时，保留正式名结果及别名全部目标。
- 同词命中阵营与搭配时，保留两套独立成员归属。例如“叙拉古”分别标注阵营及搭配，不能混成一个无分类集合。“企鹅物流”在现有真源中未登记同名阵营，仅返回已登记搭配，不为构造重叠补造阵营。
- 全部路径共享的卡片仅输出一次，保留每条路径身份、来源及成员角色；路径按固定类别顺序、卡片按现有卡序输出。
- 别名与搭配按已登记的干员目标直接取卡，不把目标名称递归作为新查询；具名成员不自动展开为异格。子串对是经登记的显式异名扩展（见 §6），按固定规则产出，不改变同名重叠全部返回的既有语义，也不等同于自动展开异格。
- 尚未支持的resource/rule等类别不伪造命中。

### 4. 查询级结果与序列化

结果承载原查询、命中路径列表（精确/别名/子串/组合）、每条路径的目标身份及来源、成员信息、去重卡片、条件摘要和覆盖范围。归一目标放在路径内，不用单个全局归一词覆盖多个目标。

| 场景 | 输出 |
|---|---|
| 规范词条 | 精确词条、命中类别及完整卡 |
| 干员别名 | 别名与所有登记目标，例如“维娜 → 维娜·维多利亚” |
| 已登记子串短名 | 短名自身与全部登记长名；长名已被同查询其它路径覆盖时该子串路径不产出 |
| 搭配规范名 | 搭配身份、成员角色、条件摘要、来源与覆盖范围 |
| 同词多身份 | 全部命中及各自成员归属；共享卡片只输出一次 |
| 未登记词或简写合称 | 未收录精确词条，不列猜测成员 |

输出仅提供客观命中信息，不增加指代判断字段或提示。查询级信息进入工具结果元数据，不从正文反推类型。

`matchedCount`为全部路径去重卡数，`returnedCount`为实际返回卡数。保持完整整卡返回，不引入截断；complete=true表示本次匹配卡已全部返回，不代表开放成员范围穷尽。无合法命中为empty、executed=true、空路径、计数0、complete=true；有合法卡则success。协议/运行错误及预算计量沿用既有规则，正文、hitIds/injectedIds、trace和落盘结果一致。

### 5. 版本与实施边界

已实施部分为 TOOL_SCHEMA_VERSION=8、FACTS_RESULT_VERSION=5（三次修订经 §7 将结果版本由 4 升至 5），工具描述、元数据、测试和观测输出同步。facts模式仍只开放facts_search，不新增参数，不修改Agent决策契约。不为本任务生成新快照或启动付费测评。

本次子串条款部分恢复 R5-2 所指的子串解析能力，但仅限已登记短名的精确展开，不恢复历史 lookup 的合称与模糊解析，也不能宣称其余历史能力已恢复。阶段2新类别、关系边、数值化和简写合称后续另议。

### 6. 子串对（短→长，全量返回）（2026-09-10 二次修订）

- **数据**：新增 `SubstringEntry { text; targets; evidence }`，`text` 为短名、必须是已登记干员规范名，`targets` 指向的干员规范名包含 `text` 且不等于 `text`；登记于 `bench/src/facts/curation/terms.ts`，evidence 指向 knowledge/references/歧义.md 第一节。仅限干员名，不含技能、阵营、设施或职业。
- **语义**：查询词 trim 后恰等于 `text` 才命中；返回短名自身（经 exact operator 路径）与全部 `targets`。长名查询不反查短名；未登记串不扩展。
- **产出条件**：先收集同查询 exact / alias / combo 路径，以其成员并集判断覆盖；某条目的目标 canonical 若全部已被覆盖，则该 substring 路径不产出（`能天使`、`嘉维尔` 因阵营精确路径已含长名而不产出）。部分覆盖时仍保留完整 `targets` 与全部目标的 `memberIds`，不裁剪为差集；判定后按 exact → alias → substring → combo 输出。substring 不贡献 `categories`，共享卡片仍只输出一次。
- **校验**：`text` 已 trim 且命中 canonical；`targets` 为非空数组，各项均为存在的 `operator:<canonical>`，去掉 `operator:` 前缀后校验 `targetCanonical.includes(text) && targetCanonical !== text`；`text` 仅在 `substrings` 内唯一且条目内 targets 不重复，允许跨索引同名；`evidence` 至少一条并沿用既有来源路径与小节校验。完整性以测试侧显式 31 条清单做集合相等断言，**不以名册包含关系派生**（名册包含会误纳 `陈`、`阿`、`红`）。
- **语料关系**：歧义.md 中「设施重叠→必须反问」的策略在本特性下由「全量返回」覆盖；不修改 `knowledge/references/歧义.md` 与 `knowledge/AGENTS.md`，差异只记录于本ADR与实施计划。
- **治理**：本条款由用户 2026-09-10 裁决授权，属通用别名/身份能力，不针对评测题、问法或预期答案添加特判。
- **实施**：见 docs/archive/plan-facts-substring-pairs.md。

### 7. legacy 实现与旧称说明清理（2026-09-10 三次修订及后续收束）

- **背景**：清理前 `legacyNames` 维护三条组合旧称 redirect，生产 reject 条目为零。用户决定删除该兼容实现；组合名称结构、成员描述与推荐边界继续暂缓。
- **决策**：删除 `LegacyEntry`、`legacyNames`、`ResolutionPath` 的 legacy / rejected 及专用索引、校验、渲染。查询按四类现有路径处理，不维护旧词黑名单或固定旧词专项回归；通用未收录、合法命中、工具错误与预算处理保持。
- **范围**：三个旧组合名在 guides、raw 工作稿、ENTITY_WORDS、fixtures 注释与搭配条件中的说明已清理，使用现有规范名；保留别名、31 组子串对、搭配成员与实际使用条件。检索白名单、检索算法、术语规则、Agent 契约及历史评测未改写，组合命名标准不在本次范围内。
- **行为影响**：语料文字和词表变化会改变检索输入、字面匹配及排序；搭配条件文字同时进入正文和 resolution 元数据。这是名称数据更新，不是零行为重构，也不改变工具参数或四类路径的结构。
- **路径**：最终顺序为 exact → alias → substring → combo；substring 仍以全部其他路径的成员并集判断覆盖，全部覆盖才省略，部分覆盖保留完整目标和成员。
- **版本**：`FACTS_RESULT_VERSION` 已由 4 升至 5；`TOOL_SCHEMA_VERSION` 保持 8，参数与工具描述不变。当前运行时为 8 / 5。
- **生效**：决策正文已同步四类路径与通用查询契约，删除被本节替代的旧称分类、映射、拒绝及覆盖规则；历史实施与核查结果保留当时事实。
- **治理**：本次为用户授权的能力收缩，不新增替代映射或拒绝机制，不针对评测题添加特判。实施见 docs/archive/plan-facts-legacy-purge.md。

## 理由

- 同名全部返回延续当前精确查询并集行为，不需要选择优先级或上下文策略。
- 简写合称后置，避免扩大用户词语的成员含义。
- 子串对以显式清单登记，兼顾「不静默择一」与「不引入任意子串扫描」，并保持查询结果确定性；产出条件避免与既有阵营命中重复。
- 条件摘要和覆盖范围保留组合边界，无需提前建立计算模型。
- 查询级多路径信息保留身份与成员归属，支持空结果与共享卡去重计数。
- curation独立于生成文件，来源定位及同步核查降低成员表漂移风险。

## 备选方案

- 命中首个身份后返回：不采纳，会遗漏同名其他结果。
- 依据子串自动扩展候选：不采纳，会按名册包含关系误纳未列入真源清单的对象（如 `陈`、`阿`、`红`）；改为登记歧义.md第一节的31组。
- 子串对双向匹配：不采纳，长名唯一，反向扩展只增噪声。
- 简写合称映射整套搭配：不采纳，用户明确暂不支持。
- 默认不推荐即拒绝名称：不采纳，推荐策略与查询事实不同。
- 完整条件图、回写卡别名或运行时解析散文：不采纳，超出当前最小实施范围。

## 后果

需修改登记校验、store及调用者、查询级结果、执行器元数据、序列化、工具描述与回归测试；不修改Agent契约。测试覆盖同词多目标、多类别、去重路径、已登记子串单向扩展与未登记子串不扩展、具体成员/条件、非法数据与协议，不以反问行为或答题正确率验收。

本轮修订已按最新范围实现并完成回归；此前独立审查中的规范名连写已修正，旧语料反问规则冲突不在本计划处理。计划尚未冻结归档，发布元数据收束另按发版流程执行。二次修订新增的子串条款已实施，实施与回归见对应计划。
