# ADR-014：测试约定采用规则文本先行，不引入机械门禁与覆盖率阈值

- 日期：2026-09-12
- 状态：已决策

## 背景

- bench/src 工具链与 scripts 开发脚本已接入 Vitest，`pnpm run test` 也是 merge/release 门禁步骤；但 docs/rules/ 无任何测试规则，AGENTS.md 核心约束未涉及测试，也没有 src↔test 映射，命名、落位、断言风格全靠模仿现有文件，Agent 增量开发时无成文依据。
- 存量测试存在未追溯差异（如 provider.test.ts 的 fetch 全局替身未配对还原、inputs.test.ts 未恢复 EXPERIMENT 前值）。当前确认的缺口是缺成文约定，尚未证明机械检查能稳定发现哪些真实遗漏。
- 回答正确率、逐题评分不是自动门禁（AGENTS.md 核心约束 7/8/9），测试约定不能与评分口径耦合。

## 决策

- 测试约定以单一成文规则（docs/rules/testing.md）先行，限定覆盖对象与豁免、落位与命名、行为与回归断言、隔离与替身、数据与断言维护、验证与变更说明六组内容。
- 不引入覆盖率阈值、src↔test 映射检查或其他测试机械门禁；scripts/gates.mjs 的 BASE_STEPS 与 vitest 配置不变。
- 约定自生效起只约束范围内文件的新增与修改行为，不批量重写或迁移存量测试。

## 理由

- 当前排查未证明存在可机械稳定发现的真实遗漏，规则文本能立即约束增量开发，成本低于先建门禁再补规则。
- 存量差异尚未收敛时引入覆盖率或映射门禁，易诱导为过线制造低价值测试，或掩盖真实覆盖缺口。
- 与核心约束 7/8/9 一致：不把回答正确率或逐题评分升级为测试断言或自动门禁。

## 备选方案

- 方案 A：src↔test 映射机械检查 — 放弃：一个源码文件对应一个测试文件不成立，新增行为可由已有用例覆盖，机械映射会制造形式化补测。
- 方案 B：覆盖率阈值门禁 — 放弃：存量缺口未收敛，阈值不能证明断言质量，且易诱导为过线补测。

## 后果

- docs/rules/testing.md 成为 bench/src、scripts 测试行为的唯一权威约定，AGENTS.md 入口与 skills/commit-convention 按名称引用，不复制条文。
- 存量差异按增量适用处理：只有修改相关用例或行为时，才在同一变更内修复其边界，不顺带全量整改、不建逐文件豁免台账。
- 若后续出现机械检查能稳定发现真实遗漏的证据，另行评估是否引入门禁，不在本决策内预设。
