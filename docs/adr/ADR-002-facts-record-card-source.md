# ADR-002：事实记录卡采用确定性源解析

- 日期：2026-09-04
- 状态：已决策

## 背景

R5 上游计划原定通过全量 LLM 转录生成记录卡，再用程序化核对约束机械字段。落地前复核发现，`knowledge/references/` 的名册和 9 个技能分片已经形成稳定的标题、技能行、解锁/替换文法及“技能 → 持有者”生成索引；全量机械事实可以由解析器直接提取，效果文本也可以保留原文。全量 LLM 转录会为稳定结构增加成本和非确定性，但不会改善本轮不处理的体系判断与消歧。

## 决策

本轮事实记录卡采用“确定性源解析 + 程序化核对 + 独立人工优化”：解析器负责机械字段、技能事实、持有关系、替换边、类别和等价关系；原始效果/注记逐字保留；人工优化只改善已确认事实的表达。`aliases` 保留兼容字段但本轮不录入、不索引，别名、简称、合称和交互式消歧另立方案。

## 理由

- 当前 references 的结构可被 100% 消费并以批次计数、关系闭合和原文回渲染验证。
- 稳定事实由代码确定性生成，便于 TDD、重跑和审查；原文指纹变化能使人工覆盖失效，避免静默沿用。
- 不引入新依赖、不改变查询工具名或 `runQuery` 公共签名，符合本轮“避免过度防御”的边界。

## 备选方案

- 方案 A：全量 LLM 转录 + 程序化核对 — 放弃原因：对当前稳定的机械结构增加成本、非确定性和回归面；本轮语义判断也不在范围内。
- 方案 B：纯程序化直接拼出旧 `RecordCard`，不保留规范化中间层 — 放弃原因：无法明确表达共享技能、持有关系、替换边及等价组精确落点。

## 后果

解析器必须针对当前 references 格式快速失败，并同时核对技能分片的两个区段；未覆盖的格式变更需先修复解析器和相关 fixtures。语义表达优化不由 LLM 自动生成，人工覆盖需要维护原文指纹。若后续引入 LLM、别名/消歧、数据库或公共接口变更，应另立方案并按生命周期规则复审。
