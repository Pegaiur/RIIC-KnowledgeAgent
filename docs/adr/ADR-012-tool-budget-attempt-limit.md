# ADR-012：工具预算改为失败不消耗与双上限，取消并行调用

- 日期：2026-09-10
- 状态：已实施
- 替代：局部替代 ADR-005（每题积分预算的扣除口径与并行调用决策）

## 背景

ADR-005 决定：每题默认 5 点积分，所有工具共享，**每个获准尝试消耗 1 点**，批次先按顺序预占再执行；同时由 Qwen 显式开启同次响应内的并行调用。该模型把「模型尝试次数」与「成功取证次数」压成同一个数字，带来两个后果：

1. **失败也计入成本**：参数错误（`invalid_params`）、未知工具（`unknown_operation`）与执行异常（`error`）同样扣点。归档试验中出现过整批 12 次参数错误的情况（ADR-006 背景），这类调用没有取得任何证据却消耗了额度，使「模型再试一次」在额度上不可行。
2. **整批预占不适合按结果扣点**：一次响应可返回多个 `tool_calls`，现有逐项结果可以区分成败，但预算 used 只代表获准尝试数；整批预占无法根据前一项是否取得非空结果决定后一项准入。

本次宿主串行用于保证逐项预算结算的顺序。同批调用已由模型一次决定，串行执行不会让模型根据批内前一项结果改写后一项；依赖取证结果的决策仍须跨模型轮次，不将串行本身视作取证质量提升的证据。

## 决策

工具预算改为「成功额度 + 尝试硬上限」双记账，并取消并行工具调用：

- **成功额度**：每题默认 5 次，只在调用返回**非空执行成功结果**（`executed === true && status === 'success'`）时扣 1。`empty`、`invalid_params`、`unknown_operation`、`error` 均不扣成功额度，但获准调用仍计入尝试次数；这不改变 provider 的实际 token 费用计量。
- **非空判定**：按实际证据内容区分 success/empty，不按 JSON、占位提示或分页元数据是否非空判定。facts 无命中、RAG 未送达非空证据、小节阅读未返回非空正文页均为 empty；小节正文为空或 offset 恰好等于正文长度的读取不扣点。不能用 hitIds 统一判断，因为正常 read_section 也不填该字段；重复返回非空证据仍每次扣点。
- **尝试硬上限**：每题默认 10 次获准尝试，与成败无关；达到上限后新增调用一律不执行。
- 两项上限独立判定，任一用尽即拒绝后续调用，返回结果区分「成功额度用尽」与「尝试次数用尽」两种原因；同时用尽时优先提示成功额度用尽。拒绝计入 requested/denied，不增加获准尝试数；最后一次获准调用结算后即提示相应上限已耗尽。
- 请求不再发送 `parallel_tool_calls: true`；若模型仍一次返回多个 `tool_calls`，宿主按返回顺序逐项「检查上限 → 增加获准尝试数 → 执行 → 结算成功额度」，不再整批预扣。每项执行或拒绝结果按原 call ID 完整回写；这不保证模型每轮仅生成一个调用。
- 配置新增 `toolAttemptLimit`（默认 10），`toolBudget` 语义明确为成功额度（默认 5）；CLI 增加对称的 `--tool-attempt-limit`。
- `executed` 保持既有观测语义，包含已执行的空结果与执行错误；保留既有 fatal 判定，fatal 错误仍终止整题，非 fatal 错误维持原回馈行为。call ID 缺失或重复仍整批不准入、不扣点并终止，不因免扣额度自动增加错误重试策略。
- 保留耗尽后继续提供工具与 auto 的既有循环，后续工具请求收到拒绝。10 次硬上限只限制获准工具尝试，不限制 LLM 请求数、HTTP 重试数和超限请求数；整题仍可能持续至回答或 sessionTimeoutMs。

## 理由

仅非空执行成功扣点，使模型在参数错误或空结果后重试不再损失成功额度；10 次获准尝试上限限制实际准入量。它不保证模型停止反复请求，单题时间仍由既有 sessionTimeoutMs 约束。

分别记录非空成功数、获准尝试数、请求数与拒绝数，使空结果、参数试错和超限请求可区分观测。非空结果不代表答案正确或覆盖充分，不能以扣点计数替代质量核查。

逐项结算后，同批调用按顺序竞争剩余额度；例如只剩一次成功额度时，前一项参数错误不会阻止后一项有效调用。批次 attempts 等于 granted，successes 仅计非空成功，executed 继续记录实际执行，三者不再混用。批内串行的时延影响需后续观测，不预先承诺提升或固定增量。

保留 executed 的既有语义可以继续解释执行错误与空结果；独立按结果状态扣点，避免为了预算重定义已有观测字段。

## 备选方案

- 只加尝试上限，保留「获准即扣点」 — 放弃原因：未解决失败调用消耗额度的问题，模型仍会因参数错误而提前耗尽额度。
- 失败不消耗，但取消固定额度、只留 10 次尝试 — 放弃原因：失去「成功取证次数」这一与费用、覆盖率直接相关的指标，也使 `toolBudget` 的既有观测字段失去含义。
- 增加「连续失败 3 次即提前终止」的熔断 — 放弃原因：本次未采纳，避免在失败语义之外再引入一个需要单独解释的终止条件；若后续观测到参数错误打满 10 次，再按证据另议。
- 仅执行批内第一个调用，其余回写拒绝 — 放弃原因：会使模型本可一次完成的取证作废，且拒绝理由需新协议表达；串行按序执行保持兼容。
- 保留并行并以批次为额度单位 — 放弃原因：批次大小由模型决定，额度不可预测，也与逐项归因的目标冲突。

## 后果

- `ToolBudgetState`、`ToolBatchStats`、`meta.json`、`inputs.json`、trace、`answers.md` 与 snapshot 同步双预算，实际 toolAttemptLimit 进入输入记录及两条系统提示构建路径。新批次始终写 attempts/successes，逐题快照保存 attemptUsed/attemptLimit。
- snapshot 同步字段白名单与历史可选字段集合，同时兼容旧预算行和新双预算行。历史缺失的新统计保持不可用，不伪填零、不由 executed 推算非空成功；覆盖旧快照读取、旧目录导出、新目录导出及新快照往返读取。结构版本与现有消费者一并核对，不改写旧记录或新增指纹字段。
- 历史运行记录按原口径解读，不与新账本直接比较；`toolBudget` 字段名保留但语义已变，比较时须同时看 `toolAttemptLimit`。
- 尝试上限提高后，单题工具往返次数可能增加，总耗时与 token 用量需在后续观测中确认是否仍在 `sessionTimeoutMs` 内。
- 未调用工具直接作答的宿主回馈（每题最多一次）不受本次决策影响，继续按 ADR-005 的既有取舍执行。
- 本次不发起付费运行，不据此指定正式质量基线。
