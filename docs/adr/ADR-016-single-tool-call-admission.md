# ADR-016：工具步骤只准入首个调用，同批超量拒绝

- 日期：2026-09-12
- 状态：已实施
- 替代：局部替代 ADR-012 的「同次响应按返回顺序执行整批 tool_calls」决策及其「仅执行批内第一个调用」备选方案的放弃理由；ADR-012 的双预算、失败不消耗、执行状态、超时与首检回馈等其余决策继续有效。

## 背景

ADR-012 取消并行调用后，宿主在同一模型响应返回多个 `tool_calls` 时按返回顺序逐项「检查上限 → 获准 → 执行 → 结算」。这保证逐项预算结算顺序，但整批调用已在同一模型步骤决定，模型无法利用批内前一项结果决定下一项；执行层串行不能替代模型的逐步决策。knowledge/AGENTS.md 第 4 条已声明每次模型步骤只能提出一个工具调用、同批额外调用不会被拒绝以外的处理，而宿主仍整批逐项执行，两者存在现实不一致。

需求要求每次模型决策最多准入一项工具调用。整题报错会放大模型偶发多调用的影响，静默丢弃会破坏后续对话的 call ID 对应，仅靠提示或传输参数都不是确定性保证。宿主能够保证最多准入一个，仍不能保证模型每步只生成一个调用。

## 决策

1. 每次模型步骤只准入首个工具调用（索引 0）；索引大于 0 的调用统一返回 `protocol_rejected` 且 `executed=false`，不解析或执行其工具参数，不增加获准尝试或成功用量。首项无效、为空、失败或因预算被拒绝时均不递补第二项。
2. 「同批按返回顺序逐项执行整批」的行为由本决策局部替代；不新增 `parallel_tool_calls` 参数，`tool_choice` 保持 auto，不改变 provider 默认值与注册表。
3. 整步 call ID 校验沿用既有语义：缺失或重复 ID 记 `protocol_error`，整步不执行、不扣额度、不拼造 ID，也不改成超量拒绝。
4. 计量口径：`requested` 含所有提出项，`denied` 含 `budget_exhausted` 与 `protocol_rejected`；`granted` / `attempts` 只计获准首项；`protocol_rejected` 不计入 `executed` / `errors` / `successes`。超量项以其在本步的位置为稳定分类，不随余额切换拒绝状态。
5. 拒绝文案说明该项未执行及单调用规则；仅当成功额度与获准尝试均有余额时提示「若仍缺这项证据，在下一步重新提出」，任一上限用尽则提示依据已有证据作答；首项耗尽额度时不同时要求重试。
6. 非中断且能正常形成结果的步骤按原顺序保留所有结果；assistant 消息保留原始完整 `tool_calls`，下一次模型请求前每个 ID 均有对应 tool 消息。超量项仍逐项写入 trace 的 `tool_call`（原 call ID、工具名、原参数、拒绝状态、原因与 writtenContent），不伪填命中、耗时或执行证据。
7. fatal、取消与截断沿用既有终止路径，不为终止情况新增补回写、恢复或等待协议；`toolTrace` 与 `ragDelivery` 仅排除新增的 `protocol_rejected`，保留旧参数错误、预算拒绝与执行异常的既有语义。
8. 工具 schema、`TOOL_SCHEMA_VERSION` 与 `FACTS_RESULT_VERSION` 不变。

## 理由

- 仅提示或传输参数不构成确定性保证（见 docs/exp/exp-single-tool-call-probe）；宿主保留首个、其余回写，可在不破坏 call ID 对应的前提下满足「每次模型决策只准入一项」。
- 整题报错会放大模型偶发多调用的影响；静默丢弃破坏后续对话对应关系。
- 以位置而非余额决定拒绝分类，使统计与 trace 在同一条件下稳定可解释。
- 保留既有 ID 校验、终止路径与持久化字段名，避免无行为收益的全量重命名。

## 备选方案

- 整题报错 — 放弃原因：一次偶发多调用即作废整题，放大了模型行为对结论的影响。
- 静默丢弃首项以外的调用（不写回拒绝） — 放弃原因：后续对话缺少对应 tool 消息，破坏 call ID 对应关系。
- 仅提示或发送 `parallel_tool_calls=false` — 放弃原因：不是确定性保证；既有探针显示该配置下仍返回多调用。
- 按返回顺序执行整批（ADR-012 现状） — 放弃原因：模型无法利用批内前一项结果决定下一项，不满足每次模型决策只准入一项。

## 后果

- 需在单调用宿主实现的同一变更内同步 knowledge/AGENTS.md、agent.ts 运行时能力块及 provider.ts、inputs.ts、runner.ts 相关注释，不留长期不一致。
- 模型每步只执行一个调用，多对象取证须跨模型步骤进行；工具往返次数、token 用量与耗时的变化需后续观测，不承诺 token、费用或耗时收益。
- 本决策不保证模型每轮只生成一个调用；ADR-012 的该判断继续有效，不视为已解决。
- 历史记录按原协议解读，协议不可确定时说明未知，不新增协议版本、哈希/指纹或自动分类器，不改写旧台账。
