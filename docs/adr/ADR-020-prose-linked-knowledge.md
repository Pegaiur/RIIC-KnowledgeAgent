# ADR-020：散文小节关联事实的引用、提示与显式展开契约

- 日期：2026-09-13
- 状态：已实施

## 背景

- 质量观察存在「散文已给出候选，精确条件与代价未送达」的情况（见 docs/exp/exp-agent-quality-baseline.md）：正文点名了干员或技能，但 Agent 未必再取到对应事实卡。
- ADR-013 的内部 facts 附带由 rag_search 的 query 命中登记词触发，覆盖干员、技能、技能组、阵营与登记组合；它不等于「作者在某个小节明确登记了关联对象」，也不保证命中小节与附带对象对应。
- 检索块、原文小节目录与按文件扩展的送达范围不同：base/guides 命中小节扩展为整篇原文时，命中小节与同篇其它小节混在一起。人工标注若绑定检索块序号，会随切块变化被迫重写。
- 事实层的 skill/grant ID 依赖原文内容，更新后即变化，不能作为跨版本人工锚点；干员 canonical 出自名册，可作稳定锚点。
- 需要在不改正文、不改 knowledge 真源、不新增标签、不改变检索分词/切块/排序的前提下，提供「作者登记关联 → RAG 给可调用入口 → Agent 主动展开」的独立能力。

## 决策

### 1. 人工旁挂标注的位置、定位与引用（施工契约）

- 人工标注旁挂于 knowledge 数据层，文件为 `knowledge/prose-links.json`，不进入 corpus-manifest，也不参与 BM25 正文、分词、切块与排序。
- 每条标注按「文件 + 标题路径」定位小节，并可用 `occurrence` 消歧同文件同路径的重复标题；不记录检索块序号或 chunk ID。标注只保存明确对象引用，不保存数值、效率或条件原文。
- 可读引用两类：
  - 干员：`operator:<名册标准名>`（canonical 出自 knowledge/references/名册.md，稳定）。
  - 技能/grant：设施 + 技能名 + 持有者（可选解锁/替换文本用于消歧），生成期解析到当前 `skill:`/`grant:` 内部 ID。
- 无标注或空关联合法；首版只标明确小节，不做篇级自动继承。

### 2. 装配期解析与机械检查

- 装配期连接现有小节目录与 references 事实，把可读引用解析为当前 operator/skill/grant 内部 ID，不把人工记录绑定到检索块。
- 解析只做精确唯一匹配，不经过别名、子串或同名全部返回入口；同一小节的引用去重。
- 生成器检查：小节定位（文件与标题路径可解析、重复标题已消歧）、引用存在性与解析唯一性、条目内引用无重复。缺失或歧义显式报告，不猜测迁移；事实更新后重新解析。
- 合法的空关联不视为错误；有标注而解析失败属错误，须修正标注。
- 校验不扩展到散文数值抽取、阈值与练度断言。

### 3. RAG 提示小节可展开入口

- rag_search 继续按现有正文范围返回，额外给出对应小节的可展开导航提示；提示只负责导航，不自动返回关联事实，不改变 ADR-013 query 触发的内部附带语义。
- 提示按文件列出登记了关联的小节（附可复制 sectionId），即使原文被按文件扩展，也逐小节保留关联所属小节，不把整篇所有事实默认并入命中小节，也不因证据中的其它名字递归扩张。
- 提示只使用既有小节上下文的剩余预算，缺空间时整行省略，不输出被截断的 ID；提示本身不计为事实送达。

### 4. read_section 显式展开

- 增加显式选择关联事实的能力（可选布尔参数 `linked`）；默认保持读取原文行为，参数与其分页契约不变。
- `linked=true` 时直接按登记引用读取记录卡（复用 facts 对象读取与卡片展示），只返回登记对象范围，不经过别名、子串或同名全部返回入口，也不递归扩大对象集合；与 `offset` 互斥。
- 响应区分原文与关联事实，标明关联小节、登记引用与实际返回对象；技能保持持有者、设施、解锁、替换、产物、条件与代价的对应，不因同卡关联而相加。

### 5. 观测与计量

- RAG 提示走 rag_search 送达台账（trace、records.jsonl、snapshot 与 meta 汇总同步新增字段），提示与实际送达可区分：written 表示提示行是否实际写入正文。
- read_section 显式展开记入 trace 的 tool_call 事件（read_section 无 records/snapshot 台账口径，本次不新增该层）。
- 成功/空结果与工具预算沿用现有口径：提示不算送达；显式展开实际送达非空卡片计成功，空关联按空结果处理。
- 历史记录缺字段表示不可用，不补零。

### 6. 版本

- read_section 新增参数与 rag_search 返回数据语义扩展合并为一次协议变更：`TOOL_SCHEMA_VERSION` 由 13 升至 14。
- `FACTS_RESULT_VERSION` 保持 7，不因关联展开重新编号。

## 理由

- 用可读引用 + 装配期解析，既让标注可在事实变化后重解析，又避免把易变的内部 ID 当跨版本锚点。
- 复用既有小节目录与直接卡读取，不新增图遍历工具、不做散文字符串扫描，保持「明确引用」与「自然语言搜索」的边界（ADR-010）。
- 提示与展开分离：提示不冒充已取得事实，模型仍有主动选择权；与 ADR-013 的 query 附带正交，两者可独立观测。

## 备选方案

- 方案 A：在 rag_search 里按命中小节名字自动附带关联事实 — 放弃：等于绕过作者登记与结构化引用，会把同篇所有事实并入命中小节，且难以与 ADR-013 query 附带区分。
- 方案 B：把关联内联进正文或 knowledge/AGENTS.md — 放弃：改写正文会改变分词与检索输入，逐段关联复制进指令源既膨胀又易漂移。
- 方案 C：把人工标注绑定 chunk ID — 放弃：切块变化即失效，违背「按文件与标题小节定位」。
- 方案 D：直接以 skill/grant 内部 ID 作人工锚点 — 放弃：内部 ID 随原文变化，无法跨版本维护。

## 后果

- knowledge 数据层新增一个旁挂 JSON；需提供标注格式与维护说明给语料计划，后续语料只维护关联内容。
- rag_search 与 read_section 的返回数据语义扩展、read_section 参数扩展，需同步 schema 描述、trace、records/snapshot 消费者。
- 关联载荷的分页与体积优化推迟另议（plan 非目标）；首版展开范围即登记对象，不因证据中其它名字扩张。
- 不做散文断言与事实的机械校验（plan 非目标），格式合法不证明相关性，也不证明散文断言正确。
