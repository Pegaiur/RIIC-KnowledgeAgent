# ADR-007：单词条 facts 统一入口

- 日期：2026-09-07
- 状态：已实施
- 替代：局部替代ADR-006中facts/hybrid暴露lookup与query_operators的决策，其余契约继续有效

## 背景

两个facts入口要求LLM选择精确名称或分类查询，并理解多个过滤字段。用户明确要求降低tool schema负担，先采用单词条query，避免同时引入自然语言解析和相关性检索问题。方案已独立初审、修订并复审通过。

## 决策

对外以facts_search({query})统一facts能力，facts模式只暴露该工具，hybrid另暴露rag_search。内部从审定记录卡的干员、技能、技能组、设施、阵营、职业字段建立精确词条索引；同名跨类别取带依据说明的卡并集，canonical去重并完整返回卡。

仅trim首尾空白，不分词、不做子串或模糊兜底，不解析复合条件。不再对外提供多条件AND、excludeIds及技能投影。一个准入调用只扣1点，预算、auto、并行、异常和正文结束契约不变。新结果协议为版本2；历史lookup/query_operators结果及缺失版本保持原状可读，新执行器对旧名称按既有unknown_operation处理。

## 理由

外部只需选择facts或片段检索，并填写一个词条；类别判断由确定性数据索引完成。减少输入schema复杂度而不新增模型解析调用或检索召回调优。该设计不承诺总token、费用或回答质量提升。

## 备选方案

- 保留两个入口并追加提示词：不能消除工具选择和字段选择负担。
- 用统一operation/params外壳：重新引入嵌套协议复杂度。
- 自然语言facts检索或模糊兜底：引入条件解析和相关性判断，超出用户当前范围。

## 后果

需要同步工具类型、模式映射、执行器、dry、指令、报告及历史兼容测试。规范词条未收录时仍可空查；宽泛职业/设施可能输出较多卡；同名并集须明确类别。高级过滤能力收缩是明确取舍，不能在query中暗设复杂语法恢复。具体U01–U11验收以计划为准。
