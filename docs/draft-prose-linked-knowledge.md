# 散文关联知识与二级披露草案

> 创建日期：2026-09-13
> 状态：未定稿（范围与方案讨论中）
> 需求入口：docs/inbox.md

## 目标

为切块后的散文附加一份关联索引，指向本段涉及的事实对象；当查询 Agent 判定散文是目标时，可用一步取得该块关联的详细知识，弥补"散文给名单、数值与代价在事实层"的送达缺口。关联只保存对象的稳定标识，数值与条件仍由事实层提供。

## 非目标

- 不处理载荷体积与分页：本轮不设体积上限、不做截取策略；效果确认后另议。
- 不改写散文正文内容，不为散文另建数值副本；关联只存标识，不复制数值或效率。
- 不做查询分类、玩家问法映射或自动意图路由。
- 关键词目录与标签语义归 docs/draft-index-and-tags.md；正文内容与批次归 docs/draft-corpus-supplement.md。
- 当前仅草案，未实施，未启动付费试验。

## 背景与依据

- 质量基线的缺口之一是"必要证据未送达"：办公室、贸易站技能分片未被注入时，散文只写"较高心情消耗"或只给百分号，具体数值与代价缺失（F05.3、G01.2、G02.2）。观察见 docs/exp/exp-agent-quality-baseline.md。
- 现有附带机制按问题中字面出现的具名干员触发（ADR-013 的 facts 附带），不会因为散文里列了一串名字就带回这些名字的事实。
- 机械检查目前只覆盖"命中"：`check:prose-terms` 只扫 base 与 guides 的术语，doc-check 管文档之间的一致性；散文中的数值、练度或条件与真源冲突没有门禁。
- 事实层已有稳定标识与解析入口（干员、技能、grant，以及别名、子串与歧义口径），可作为关联的锚点；实际可用字段以实现时读取为准。
- 2026-09-13 讨论结论：方案可行，但须限定为「人管相关、机械管形式」，并另起草案，不与既有两份绑定。

## 候选方案与评估

| 方案 | 判断 |
|---|---|
| 查询期附带扩展到"命中散文块内提及的名字" | 轻量；复用 ADR-013 既有实体标记与附带通道，可作先行验证；随 RAG 结果一并返回，体积随结果增长 |
| 预计算块→关联索引，配合增强 read_section 二级披露 | 倾向作为长期方向；按需懒加载、可复用，并可为"散文断言与事实"提供机械核对 |
| 由人工为每段标注关联内容（复制数值与解释） | 不采用；不可维护，且与"散文难以长期守规则"的前提冲突 |

## 实施方案（候选）

1. 关联对象与产出（撰写侧）

- 关联粒度以检索块为单位，与现有切块口径一致；必要时按篇继承，避免逐段重复。
- 关联内容只保存稳定标识：干员、技能、grant 等；不保存数值、条件原文或效率。
- 由散文撰写者判断"本段涉及哪些对象"（人管相关），生成与校验为机械步骤（机械管形式）。
- 无关联或关联为空是合法状态，不作为发布阻塞条件；不追求全量覆盖。

2. 生成与校验（机械侧）

- 校验关联标识能否解析到当前事实；事实重建或标识变更后需重新生成。
- 可机械校验的部分限于：标识存在性、可解析性、块与关联的对应完整；"关联是否恰当"不由机械判定。
- 存储落位与格式待定；不新增哈希或指纹字段。

3. 消费（Agent 侧）

- 先行验证倾向轻变体：把既有查询期附带从"问题中字面出现的具名干员"扩展到"命中的散文块内提及的名字"。
- 目标形态为增强 read_section：返回原文块时一并返回其关联知识，按需一步取得；该工具契约变化需在定稿时按判据建 ADR。
- 返回须区分"原文"与"关联事实"，并以事实为准；同设施多条技能仍分别展示产物与成立条件，不因关联存在而相加。

4. 与散文核查的衔接（可选延伸）

- 关联若锚定事实层，可对散文中事实可编码的断言（人名、数值、阈值、练度）做机械核对；策略与判断类内容不纳入。
- 是否本轮实施、纳入哪些字段，见待定事项。

## 待定事项

1. 关联粒度（块或篇）与继承规则。
2. 关联的存储落位与格式（旁挂文件、生成期派生或纳入 corpus-manifest），以及重建触发条件。
3. 消费方式取舍：先做查询期附带的轻变体，还是直接做增强 read_section；后者触及 ADR-008 与 ADR-013。
4. 是否本轮就做"散文断言与事实"的机械核对，以及纳入的字段范围。
5. 载荷体积与分页方式（明确推迟，效果确认后另议）。
6. 关联由人维护时的操作细则：撰写侧的判断口径与机械校验的边界如何划分。

## 验收清单

以下为首版候选条目，定稿后转 plan。

- [ ] 关联以稳定标识表示，不复制数值；无关联为合法状态。
- [ ] 关联可解析到当前事实，事实重建后不失效或可重新生成。
- [ ] Agent 能按散文块一步取得关联知识，且与原文区分、以事实为准。
- [ ] 不改写散文正文、不新增人工数值副本、不引入查询分类。
- [ ] 运行时改造按 docs/rules/testing.md 先观察行为测试失败再实现，通过 pnpm run typecheck 和全套 pnpm run test。
- [ ] 文档通过 node scripts/doc-check.mjs；质量试验另按 exp 流程，不新增固定基线门槛。
- [ ] 涉及 read_section 或附带范围的公共契约变化，在定稿时按判据建立 ADR。

## 关联 ADR

- ADR-008 — 增加原文小节阅读能力；增强 read_section 需明确相对既有契约的扩展。
- ADR-010 — facts 别名、集合词条真源与同名全部返回契约；关联解析复用其别名与同名口径。
- ADR-013 — 检索范围、原文扩展与 RAG 内部 facts 附带契约；附带触发条件若变化需明确衔接。
- 本草案与 docs/draft-index-and-tags.md、docs/draft-corpus-supplement.md 并列，分别定稿、实施和验收；是否新增 ADR 在公共接口定稿后按判据确定，不预分配编号。
