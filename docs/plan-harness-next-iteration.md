# Harness 基线可复核性与首轮离线验证计划

> 创建日期：2026-09-08
> 状态：实施完成，报告待独立审定与发布收束（独立计划审查已通过）
> 需求入口：[inbox](inbox.md)
> 评估依据：[性能与 ROI 评估](draft-harness-performance.md)

## 目标

使下一次 harness 对照的实际输入可追溯，完成既有 A/B 回答的 v4 语义复核，并以离线检索证据确定下一项高 ROI 实验。交付可验证代码与报告，不把模型答错自动转成修复任务。

## 非目标

- 本轮无新模型请求、付费实验或新20题真实基准；固定证据忠实度、实体标记、模型切换留待下一轮。
- 不改变正式提示词、工具协议、预算、检索排序/切块/返回、知识事实、题集及 spec v4；不增加答案特判、别名兜底、强制 facts 或二次模型审核。
- 不恢复未知历史输入、不回写旧运行或快照，不要求历史质量达到某个通过率。
- 不提交、合并、发版或清理仍用于复核的历史原件。

## 架构分析

`runner.ts` 在开始时读取 trim 后的人工指令并记录哈希，但源码状态在结束时采集，缺少实际指令正文、完整模型非敏感配置与运行输入标识；`snapshot.ts` 以白名单导出 meta，新增数据必须经过同一安全边界。最新 B 样本的人工指令哈希与当前 LF/CRLF 两种口径均不符，不能视为当前指令的严格基线。

当前 `agent.ts` 已接收 runner 固定的指令，工具 schema 可由 `toolSchemaMetadata`/`toolsForRetriever` 获得，语料已有显式 manifest。复用这些入口，避免并行维护另一套提示、schema 或语料发现机制。新增记录仅服务复核，不参与模型取证决策。

当前 v4 报告未审定，所有40份原答、144个必答编号、额外断言与送达归因需逐项重新核查。静态 hitrate 不能替代这项工作；离线回放也不能模拟模型改策略后的反事实答案。

## 实施方案

### 1. 核实历史指令与锁定本轮输入

检查 A/B 原件 meta、已知相关提交中 `knowledge/AGENTS.md`，以及已知相关任务目录内存在的指令原件；遵守 scripts/INDEX 的限定搜索，不全仓扫描忽略区。哈希沿用实际 loader 的 trim 字符串，另外计算 LF/CRLF 仅用于诊断，不悄悄修改运行时规范。

对每个历史样本给出“找到精确匹配文本+来源”或“在已检查范围内无法恢复”的结论与检查范围。无法恢复即结束历史查找，不能无限枚举或把它变成后续工作的阻塞；不由哈希猜测语义差异。结果记入计划实施笔记，修正性能草案的当前基线边界。

开始代码修改前按模板创建本计划对应的 notes，记录当前 HEAD、工作区已有变更和实际实施选择。当前 feature checkout 中已有父任务评估/计划文件，保留并接续，不新建 worktree 或覆盖未提交内容。

### 2. 增加最小运行输入记录

在现有运行目录增加 `inputs.json`，在第一题/第一次 provider 调用之前完成写入。用局部变量捕获该次运行使用的输入，后续继续传给现有 runner/agent 路径；不得在模块顶层读写，不为观测额外发起请求。

记录格式设 `schemaVersion: 1`，至少包括：

- 人工指令的实际 trim 字符串与同口径 SHA-256；现有生成函数产生的 system prompt 和工具 schema 数组及其指纹。不得改指令换行或模板以迁就旧哈希。
- 当前运行实际的 provider、model、thinking、temperature（未传为 null）、maxTokens、retriever、topK、maxContextChars、toolBudget、sessionTimeoutMs、feedbackOnNoToolAnswer、toolChoice、parallelToolCalls、prices，以及问题 id/category/question。tokenizer/entityBoost 从 `currentTokenizer()`/`currentEntityBoost()` 记录实际有效值，配置声明值如需保留须另列；不在本轮改变它们的配置驱动方式。用显式字段白名单组装，禁止 spread BenchConfig、env、secret.yaml、headers 或密钥。
- 开始时的源码状态（HEAD/dirty，Git 不可用明确标未知），既有结束时 source 字段保留其语义。
- RAG 的实际 chunks 计算内容指纹，包含 id/来源/标题/正文等实际结构。对象键可规范化，但 chunks/cards 数组必须保留实际顺序，不因稳定排序改变检索平分或结果次序。指纹不等于原文可恢复：本轮不把全库或完整卡片复制进运行目录，不声称仅有哈希可还原历史知识库。

facts 保持现有惰性加载：初始 inputs 标记“尚未加载”；只有合法 facts 执行实际取得 `getCardStore()`（包括既有缓存）时，才观测所用 cards 并补记指纹。不得为了观测提前调用 store、另建投影或让 dry/无 facts 调用提前触发门禁。结束时区分“未使用”“已捕获”“加载失败”；失败时不得生成伪指纹，原工具错误/终止语义保持不变。仅观测一次实际使用的 store，在结束写 meta 前更新 inputs 并计算最终落盘哈希；旧指令/schema/问题记录保持开始时的值。异常未能完成写盘的目录不声明为完整可复核运行。

inputs 记录的是送入 harness 的非敏感输入，而非模型服务端状态。沿用现有 trace 的敏感值识别/脱敏能力，检查指令、问题、schema 及字符串配置中的已知敏感值，不能只靠字段白名单。命中时正文脱敏并显式记 `redacted=true` 与不可全文精确恢复；分别保留原始实际输入的哈希、脱敏标记和最终落盘文件哈希，不把脱敏文本冒充原文，也不将原始输入另存临时文件。meta 新增 `maxTokens`、输入记录版本及文件内容 SHA-256（以最终落盘字节计算）；在现有 meta 版本约定下采取向后兼容的可选字段，旧运行字段缺失保持缺失。

`snapshot.ts` 只增加上述小型 meta 字段的显式准入、类型校验和导出保留，不嵌入 inputs 全文、system prompt 或整个语料；旧快照读取及重导出仍兼容，不补造新字段。inputs 留在本地运行目录，与 trace 同生命周期；共享快照只证明所关联 inputs 的指纹，若原件被清理，应明确失去全文恢复能力。

如果复用 facts 现有数据入口无法在不改变公共接口的前提下完成指纹，先在 notes 记录实际接口方案，并按生命周期规则判断 ADR，不绕过规则引入第二套投影或全新数据注册表。

### 3. 重新核查既有40份回答

输入固定为：

- A：`bench/results/2026-09-07T14-55-33-663Z-qwen-off-t0.json` 与同 runId 的 bench-runs 原件。
- B：`bench/results/2026-09-08T03-21-55-405Z-qwen-off-t0.json` 与同 runId 的 bench-runs 原件。
- spec：`92ab212d4397ae652c0841f7b9f7b88c2874960c` 的 spec v4；知识依据按 spec 声明的 `b008f80c00c05097856921da946fe344bcaed600`，若当前文件不同，读取该提交而不是覆盖工作区。

复核现有 `docs/reports/draft-answer-baseline-v4.md`，不从旧标签或 v3 汇总继承判定。逐个必答编号记录原答摘录/可定位位置、完整条件覆盖、支持或反驳的真源位置与满足/遗漏/冲突/待核验；另外逐题覆盖全文新增例子、名单、公式、名称与范围断言。送达归因核对真实 tool.writtenContent，不能只看库中存在或 injectedIds。

全部40份原答核对后才重算汇总；以明确的复核范围和剩余不确定性替换撤回状态。附每份原答的必答编号计数、额外断言检查完成标记与 trace 证据定位；完整性计数不能当作语义正确性证明。未解决来源关系使用“待核验”，不是任务失败，也不得为减少该状态修订 spec/知识事实。报告沿用 draft 文件名直到独立结果复核；本轮完成全量复核不等于自动指定正式质量基线，inbox 如实更新到“全量复核完成，待审定”。

### 4. 离线检索诊断与留出题冻结

在 `dev-temp/work/harness-next-iteration/` 做一次性回放，不维护第二个 agent loop，不向运行时注入 gold。输入覆盖 A/B trace 中全部真实 rag_search 调用；目标明确为“逐条 RAG 调用的独立离线重执行”，不复现原模型调度或混合 facts 批次预算。原 executed=true、状态为 success/empty 且参数有效的调用，经当前导出的 `createKnowledgeToolExecutor` 与 `serializeToolResult` 获取真正格式化、截断后的工具内容，不直接以 search() 返回代替送达结果。每条用独立足额预算，比较 data 与 injectedIds，envelope 的预算余额单列为非可比调度字段；原拒绝/无效/错误项全部保留原状态与不可直接比较理由，不静默删除。记录原参数、原送达块与当前同参数检索块及差异，保留空结果。先报告历史/当前输入不一致的限制，不把回放差异一律判为缺陷。

另设计6个未用于当前20题调优的新问题（机制/组合/条件散件各2题），避免只改写原题同一答案；问题文件与人工参考要点/来源分文件保存，不改 bench/questions.json。冻结问题和参考材料指纹后，仅运行当前检索基线，报告送达覆盖与字符量；运行时消费者只读取问题字段，不读取答案文件。

本轮不实施相关小节扩展候选。结合完整语义复核，把缺口分为“必需证据未送达”“证据已送达但失真”“额外断言无据”和无法归因；在原性能草案更新下一轮优先选忠实度或相关小节覆盖的依据。留出题在本轮已被观察，后续若据其结果调参，就改标开发集，另建未参与调优的问题作最终验证，不再宣称未见留出集。

### 5. 验证与交付

新增行为测试应覆盖：输入记录在首个模型请求前存在且与实际 prompt/schema 一致；maxTokens/未传温度；LF/CRLF 字符串精确指纹；实际 chunks/facts 数据或数组次序变动导致指纹变化；声明配置与有效 tokenizer/entityBoost 不同时正确记录；facts 未使用不初始化、实际使用后捕获与加载失败不伪造指纹；已捕获指令不会被中途文件改动改写；干净/dirty/Git不可用状态；inputs/meta 最终文件哈希一致；测试密钥进入配置、问题或指令时均不泄露且脱敏标记/原始哈希正确；快照只接收允许字段且旧快照兼容。使用 fake provider 或现有 dry fixture，不发真实请求。

运行 `pnpm run typecheck`、`pnpm run test`、`pnpm run build` 和离线 `pnpm run bench -- hitrate --topk '3,5,10'`；新增观测不能改变既有检索指标和运行策略。最终运行 `node scripts/doc-check.mjs`、`git diff --check`。文档门禁 D1 在施工中因未勾选项失败是预期，不能伪勾选以求通过；仅真实完成后勾选并重跑。

报告代码变更、全量复核覆盖、仍未确定的判定、离线观测、测试结果与下一轮建议。一次性脚本/回放输出按 scripts/INDEX 收尾；6题及参考材料保留并交接其用途和污染边界。A/B 原件在结果审定前继续保留，不生成新的正式基准快照。
