# 上级范围阅读入口与无增益搜索停止引导计划

> 创建日期：2026-09-08
> 状态：已完成
> 需求入口：[inbox](../inbox.md)

## 目标

在既有小节导航能力上，为 RAG 命中与 `read_section` 增加「直接上级范围」入口，并在 `knowledge/AGENTS.md` 明确优先读取上级范围、不重复相同查询、搜索未增加证据时停止追加查询；目标是更合适的范围阅读入口与停止引导，不以增加阅读次数或全部答对为目标。

## 非目标

不新增工具，不改工具参数/schema、检索排序、分词、topK、切块、chunk ID、facts、预算、模型或 agent loop；不修改知识事实，不加入题目特判；不新增宿主拦截、缓存、计数器或强制终止流程；不创建新版本管理体系，不新建草案。本任务不发起付费模型请求，真实对照只准备材料。

## 架构分析

已有对照显示：范围枚举题会逐个 `read_section`（4 次补读仅增加 4 个对象），另一题反复 `rag_search`（最后两次查询完全相同）。现有 RAG 展示只给出当前命中小节标识、父级引导与兄弟导航，缺少「直接上级范围」的可复制入口；`read_section` 只返回当前小节分页，缺上溯信息。`SectionEntry` 已含 `parentId`，`SectionDirectory.get` 可直取父级，无需改目录数据模型。对照报告 `dev-temp/work/guided-evidence-test/compare-report.md` 存在漏评（SN4 实际有改善、H2 仍误释初始档位、H4 仍有过度推断），本轮不照搬其「7/8 不劣」结论。

## 实施方案

1. **保留对照基点**：改动前构建一次，将完整 `dist` 复制到 `dev-temp/work/scope-reading-test/before-dist/`，保存旧指令快照与源提交、dist 文件指纹、指令指纹；副本仍从仓库根 cwd 运行复用根依赖与语料，用一次无付费 `--dry` 检查可启动。`meta.source.gitHead` 只表示运行时 checkout，不冒充旧构建源提交，对照说明分别记录。
2. **RAG 上级范围入口**（`bench/src/tool-executor.ts`）：对实际送达的命中小节取直接父级、按命中顺序去重，显示完整可复制 section ID、文件、完整标题路径、正文 UTF-16 字符数，并注明「包含下级小节的原文范围、不等同于完整答案集」；无父级不虚造。展示顺序：命中正文 → 当前小节标识 → 上级范围入口 → 既有父级引导与兄弟导航。新增信息只用正文后的剩余空间；含可调用 ID 的行整行放入或省略，不输出截断 ID，普通引导文字仍按既有方式截断。
3. **`read_section` 上溯**：先按现有算法确定核心元数据、正文页、`next_offset` 与 `complete`，仅在剩余空间足够时插入完整父级行（ID、文件、标题路径、正文长度）；不为新增信息重切正文、改变分页边界或让原本可读的页面失败，保持每页 6000 字符、总输出预算、连续续读与计费规则。
4. **更新人工决策指令**（`knowledge/AGENTS.md`）：涉及多个同级条目且有上级范围入口时优先读取该范围；后续页可续读但不强制读完；不重复提交完全相同的查询；搜索未增加相关证据时只继续明确新线索或能改变覆盖范围的查询，否则转向范围入口或按已有证据作答并说明缺口；部分证据不支持完整名单，也不能证明未检索对象不存在。
5. **确定性测试**（`bench/tests/section-navigation.test.ts`）：父级映射/同父级去重/无父级；剩余空间足够与不足时的入口行为（不挤占正文、不切坏 ID）；通过父级入口读取含多子节原文并连续续读；新父级信息不改变原分页正文、`next_offset`、工具计费与搜索统计。
6. **真实测试只准备**：以 SN3、H3 为开发样例，再冻结两道未参与设计的范围问题；后续 before（旧构建＋旧指令）/ after（新构建＋新指令）各跑 4 题一次，串行运行、临时切换指令后恢复，不复用只切提示词的旧脚本。本任务不执行。

# 实施笔记：上级范围阅读入口与无增益搜索停止引导

## 决策偏离
> spec 中没有提到，但在实施中做出的重要决策

### 2026-09-08 — 父级行插入位置与分页解析
- **背景**：`read_section` 输出为「3 行元数据 + 空行 + 正文页」，既有测试用固定行号解析正文页。
- **选项**：
  - A: 把父级行追加到正文页之后，正文页行号不变但尾部多一行。
  - B: 把父级行作为元数据行插入到 `行范围` 行之后、空行之前。
- **决策**：选 B（元数据行），符合「附加当前小节元数据」的语义；同步把测试里的分页解析改为按空行分隔，而非硬编码行号。
- **影响**：`read_section` 文本行数可变，任何按行号解析的调用方需改为按空行定位；正文页内容与 `next_offset` 不变。

## 实现调整
> spec 中有描述，但实际实现方式不同

### 2026-09-08 — 「实际送达的命中小节」判定
- **spec 原文**：对实际送达的命中小节取直接父级。
- **实际做法**：以 `injectedIds`（真实进入上下文的 chunk）作为「已送达」判据，仅对这些小节的直接父级生成入口。
- **原因**：`injectedIds` 已是既有「真实送达」定义，避免为被截断掉的命中生成父级入口。
- **后果**：无下游文档需要更新；`injectedIds`/`hitIds` 语义未变。

## 意外发现
> 实施中发现的 spec 未覆盖的依赖/边界/风险

### 2026-09-08 — 切块不覆盖 H1，首行标题存在识别边界
- **发现**：`splitChunks` 只按 `##`/`###` 切块，H1 正文落入 `（未分段）` 块且包含 H1 行；位于文件首行的标题因 `headingLine !== i` 初值判定不会被识别。编写「无父级」测试时需用无 H1、首行非标题的文档才能命中带 `sectionId` 的顶层小节。
- **影响**：属既有切块行为，本轮未改；已在新测试中用无 H1 文档覆盖，不需要更新 spec 或新建 ADR。

### 2026-09-08 — 分页元数据预算是保守值
- **发现**：`sectionMetaLength` 按 `next_offset=Number.MAX_SAFE_INTEGER`、`complete=false` 预留元数据，比实际渲染（`null`/`true`）更长，因此缩小 `maxContextChars` 会先压缩正文页预算。
- **影响**：新增父级行的空间判定必须在正文页确定之后进行，不能用「父级行长度」直接反推可容纳的 `maxContextChars`；测试已据此设计。

## 阻塞与解决
> 遇到的阻塞问题及解决方案

### 2026-09-08 — 新增测试两处失败
- **症状**：无父级测试取不到 `sectionId`；父级行「不改变分页」测试正文页被压缩。
- **根因**：前者是切块/标题识别边界（见上）；后者误用「父级行长度」反推 `maxContextChars`，未计入保守元数据预留。
- **解决方案**：无父级测试改用无 H1 文档；分页测试改用 `maxChars = full.length - 1`，仅使父级行差一个字符不放入，正文页预算仍充足。
- **预防**：涉及 `read_section` 预算的测试，先确定正文页再评估附加信息，不假设元数据长度等于实际渲染长度。
