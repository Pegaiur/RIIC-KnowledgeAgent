# RAG 送达格式瘦身计划

> 创建日期：2026-09-17
> 状态：已完成

## 目标

压缩 rag_search 默认送达文本里的非证据部分（文件路径、分区说明句、行内 read 示例、父子导航重复），在保持阅读 ID 契约不变的前提下降低每次调用的送达字符数与工具结果成本。

## 非目标

- 不改工具名、参数、`section_id` 算法与 read 行为；不引入 JSON 等结构化容器——评估结论是同信息换容器会因键名、引号与正文换行转义而增字，而 `writtenContent.length` 直接进成本计量。
- 不改交付台账字段（`fragmentRanges` / `linkedEntries` / `readDelivery` 的 schema），不改根 AGENTS.md 的质量基线登记表；本轮只改展示文本，以及 depended on 该文本的「是否实际写入」判定输入。
- 不改全文扩展路径（`expandFulltext=1`）的块头与分区结构。
- 不改检索、topK、maxContextChars、facts 附带与提示词策略；不针对当前题集做任何特判。
- 不发起付费跑测；验证只用本地重渲染与既有测试。

## 架构分析

默认送达路径（`buildHitBlockData`，见 bench/src/tool-executor.ts）现在同时做四件事：送命中块正文、给块头、在末尾追加四段上下文（小节上下文 / 上级范围入口 / 父级引导 / 小节导航 / 关联事实入口），每段各自携带文件路径与 ID。

最近一轮 20 题（GLM-low，`expandFulltext=false`）的实测构成：送达总字符 93,078，其中命中块正文 45,274（48.6%）、关联事实入口条目 12,875、小节导航 7,011、父级引导 6,820、命中块头 6,165、上级范围入口 5,959、小节上下文 5,760、分区说明句 3,214。非正文合计 51.4%。

重复的具体形态：一个 ID 平均出现 5 次（599 次出现、119 个去重）；`.md` 文件路径在导航区被提及 469 次（去重 23 个文件）；行内 `示例：read(section_id="…")` 110 次共 4,620 字符，而 read 工具定义里已经写了用法；同一父级下多个子小节命中时父级引导整行重复（技术债 PD-1）。

同期核查：近 5 次运行的 read 调用里，`section_id` 有 88/93 来自本 run 已送达的 ID，0 次重复读取同一 ID。因此本计划定位为成本与可读性优化，不声称修复既有缺陷。

## 实施方案

1. 块头去文件路径：`【标题 | L起-止 | sectionId】`。仅在拿不到 sectionId 的防御分支（该文件没有文档范围）保留文件路径，避免来源信息完全丢失。
2. 三段上下文合并为单张【小节索引】表：按文件分组，文件路径只在分组行出现一次；每行 `- <id>｜<关系>｜<标题>`，关系取 `命中`（本次送达证据）/`上级`（包含命中范围的原文范围）/`邻近`（同文件同级或直接下级小节），同一 ID 只出一行、关系可组合（既是命中节点又是某命中的上级范围时写 `命中/上级`）。上级行保留 `｜正文 N 字符`，邻近行保留省略提示 `（省略 N 项）`；已作为命中或上级列出的 ID 不再重复列为邻近。
3. 关联事实入口并入索引行的 `｜关联 M 个对象` 列，删除独立分区句与行内 read 示例；候选仍是实际显示的命中节点与导航项（ADR-020 的「提示只做导航」语义不变）。`linkedEntries` 观测的字段不变，`written` 仍按该行是否实际写入判定。父级引导行依附其上级入口行：上级行未整行写入时一并省略，不出现无所属的孤立引导。
4. 父级引导按父级去重（偿清 PD-1），缩进挂在对应上级行之下，`parentLeadFragments` 的登记随展示口径统一。
5. 测试先行：先更新表达旧格式的用例（bench/tests/section-navigation.test.ts、rag-delivery.test.ts、prose-links-hint.test.ts）并观察失败，再改实现。
6. 零费用验证：用同一批历史 query 在本地重渲染，统计新旧字符数差异，结果写入实施笔记。

## 第二轮：送达结构改为文件目录树

> 追加日期：2026-09-17（同日，第一轮验收已全部完成）。第一轮把索引压成一张表，本轮把这张表整体替换为同文件的 Markdown 目录树，并把命中正文改为就地预览。

### 目标

同一批调用的送达字符再降一档，且让模型看见命中文件的完整小节结构：结构由缩进自描述，不再需要「命中/上级/邻近」关系词与逐行重复的祖先路径。

### 第二轮规则（定稿）

1. 一段树 = 一个命中文件。根行 `- <文件 H1 标题>｜doc:<文件名>｜全文 N 字符`；树内不再出现任何相对路径。文件无 H1 时标题回退为不含扩展名的文件名。
2. 只有根行与命中节点带可调用 ID。命中节点 `- <sectionId>｜<标题> ◆`（有关联登记时追加 `｜关联 M 个对象`）；非命中节点只写标题，按原文顺序、按 `level-1` 级缩进。
3. 命中节点就地展开命中块正文的前 100 个 UTF-16 字符：硬截断、不拆代理对，保留原文换行、每行加 `> ` 前缀并比命中节点深一级；被截断时末行接 `…（截断，全文 N 字符）`，N 为该命中块正文全长。取消独立命中块头区与其行范围展示。
4. 命中映射到文档范围（标题前首部）时，标记落在根行上，预览挂在根行之下。
5. 删除父级引导与其登记（不再产生 `kind: 'parent_lead'`），删除「上级范围入口」；上级阅读由整篇入口替代，模型的选择空间收敛为「已送达的命中预览」与「read 整篇」。
6. 预算不足时按行原子省略，优先级固定为：命中节点 ID 与其祖先链 > 命中预览块 > 其余结构行；整棵子树折叠为 `<标题>（含 N 个小节未展开）`。
7. 文档范围 ID 由 `doc:<相对路径>` 改为 `doc:<文件名>`；`corpus.ts` 在解析白名单时机械校验基线名唯一（跨 `base/` 与 `guides/`），冲突时中文报错并列出两个相对路径。旧形态 ID 不再可解析，按 ADR-022 决策 1「不模糊匹配」直接失败。
8. `expandFulltext=1` 的块头同步由相对路径改为文件名（第一轮把该路径列为非目标，本轮取消该限制）。
9. 工具描述同步：`rag_search` 去掉「上级范围入口」，`read` 的 ID 说明保持「原样使用已返回的 ID」；`TOOL_SCHEMA_VERSION` 15 → 16。

### 第二轮非目标

- 不改 `read` 的分区结构、分页字段与导航格式（本轮只承接 ID 形态变化），不改 `read` 的父子导航。
- 不改检索、topK、`maxContextChars`、facts 附带、提示词与提示词注入。
- 不改 `fragmentRanges` / `linkedEntries` / `readDelivery` 的字段与 schema；`kind: 'parent_lead'` 取值不再产生，历史记录照旧可读。
- 不改全文扩展路径的正文与续读结构（只改块头里的文件标识写法）。
- 不发起付费跑测；验证只用本地重渲染与现有测试。

### 第二轮实施方案

1. 测试先行：更新表达旧索引表的用例（bench/tests/section-navigation.test.ts、rag-delivery.test.ts、prose-links-hint.test.ts）与 `doc:` ID 断言（fulltext-expansion / prose-links / read / retrieval-range / snapshot），新增目录树、100 字预览、基线名冲突用例，先观察失败。
2. `sections.ts`：文档范围 ID 改 `doc:<文件名>`；新增按文件返回全部小节（含未命中、含无标题文件）的只读接口。
3. `corpus.ts`：`resolveManifestFiles` 增加基线名唯一校验（Windows 大小写口径同现有重复项判定）。
4. `tool-executor.ts`：`buildSectionContext` 重写为目录树渲染（含命中预览与整子树折叠）；`renderRagHeader`、`parentLeadFragments`、`INDEX_HEADER` 与独立块头区退役；`buildRagDataLegacy` 与全文扩展块头同步新写法。

# 实施笔记：RAG 送达格式瘦身计划

> 对应 plan：docs/plan-rag-delivery-format-slim.md
> 开始日期：2026-09-17

索引表条目记录首轮过程，文件目录树为第二轮最终方案；当前契约见 ADR-023。

## 决策偏离
> plan 中没有提到，但在实施中做出的重要决策

### 2026-09-17 — 关联事实入口并入索引表而非保留独立分区
- **背景**：plan 只写了「去掉行内 read 示例」，未定关联入口的容器。独立分区每行重复 ID、文件路径与标题路径，是除正文外最大的一块（12,875 字符 / 13.8%）。
- **选项**：
  - A：保留【关联事实入口】独立分区，只删示例与文件路径（改动最小）
  - B：把「关联 N 个对象」并入索引行的列，删除独立分区
- **决策**：选 B。索引表已按文件分组列出命中与同级节点，关联对象数是这些节点的属性，并入后同一 ID 只出现一次，且省掉整段分区句。
- **影响**：`linkedEntries` 的 `written` 判定从「独立提示行」改为「索引行是否实际写入」；观测字段与 schema 未变，消费方（report / snapshot）无需改动。

### 2026-09-17 — 预算让位与折叠的执行顺序
- **背景**：plan 只写「按行原子省略，优先级：命中节点 ID 与祖先链 > 命中预览块 > 其余结构行；整棵子树折叠为一行计数」，未定折叠选哪一棵、渲染如何让位。
- **选项**：A 逐行判断、跳过放不下的行继续渲染；B 先按优先级预留必需条目额度、再写入，放不下即停止。
- **决策**：B。初版先为后续必需条目预留额度，再按文档顺序写入，任一行放不下即停止。验收时复现前置可选行挡住后续命中，最终按必需条目、预览、其余结构依次分配额度，再按原文顺序展示；父条目未选中时省略其下级。折叠在渲染前独立进行：预算不足时从文档顺序**最后**一棵非命中子树开始折叠为 `<标题>（含 N 个小节未展开）`，直到放得下或没有可折叠子树。
- **理由**：命中 ID 优先于预览，预览优先于其余目录结构；按父子关系保留条目，使预算省略后的层级仍然成立。
- **后果**：条目可按优先级省略，输出保持原文顺序。◆ 表示检索命中，实际预览按 `injectedIds` 与 `fragmentRanges` 登记。

### 2026-09-17 — 预览的可用性决定送达成败
- **背景**：目录树即使只送出表头与根行也算「有输出」，但没有任何正文证据。
- **选项**：A 有输出即 success；B 一条预览都没送达时按容量错误返回（不发送只有结构的树）。
- **决策**：B，沿用 ADR-022 的「不发送没有阅读 ID 的正文」同源口径，改为「不发送没有正文证据的结构」。
- **影响**：单命中且无预览可送时，调用返回容量错误、`linkedEntries` 缺省；多命中或全文扩展的部分目录仍可能含 `written=false` 观测。

### 2026-09-17 — 无命中保持 empty，不发送表头
- **背景**：首版实现无命中时也会渲染表头，`written.length === 0` 判为容量错误，使 `empty` 语义退化为 `error`。
- **决策**：命中集合为空时直接返回 `empty`（`data` 为空、无容量错误），由 `rag_search 内部 facts 附带集成` 与 `tool-executor` 的既有用例暴露。
- **后果**：零命中检索行为与本轮之前一致。

### 2026-09-17 — 关联提示只保留在命中行
- **背景**：第二轮后非命中节点只有标题、不带 ID，关联对象数无处可挂（挂了也无法 read 展开）。
- **决策**：`｜关联 M 个对象` 只标在命中行（树上唯一可调用的非根节点）；`linkedEntries` 字段与 schema 不变，`written` 按该命中行是否实际写入取值。
- **后果**：ADR-020 的导航语义仍在（读命中行 ID 即可展开该小节子树登记），但提示条数由「命中 + 邻近」降到「命中」。

### 2026-09-17 — 命中行不再展示原文行范围
- **背景**：plan 只写「取消独立命中块头区」，未说明块头里的 `L起-止` 是否需要迁移到命中行。
- **决策**：不迁移。命中行为 `- <sectionId>｜<标题> ◆`，只有 ID 与标题；原文行范围继续由 `fragmentRanges` 台账承载，不在展示层出现。
- **理由**：用户明确「只展示散文文件的标题，避免引入无关信息」；行范围对模型构造调用没有作用（read 用字符 offset 续读，返回里自带分页元数据）。
- **后果**：ADR-022 决策 7 的「ID 先于正文、不因导航预算丢失」保持（命中行是必需条目），但「范围元数据」不再进入展示层，检查口径改为以台账为准。

## 实现调整
> plan 中有描述，但实际实现方式不同

### 2026-09-17 — 索引表实现细节
- **plan 原文**：「一个可调用 ID 只出一行……同一 ID 在表中只出现一次，已作为命中或上级列出的不再重复列为邻近」「父级引导按父级去重，缩进挂在对应上级行之下」。
- **实际做法**：
  - 关系列改为可组合：同一小节既是命中节点又是别的命中的直接父级时只出一行，关系写作「命中/上级」，不因此丢掉「可读整段子树」的规模提示。
  - 邻近行排除已作为命中或上级列出的 ID；表头用一句说明取代原来的四段分区说明句。
  - `SectionContextLine` 新增 `attachToPrevious`：父级引导依附其宿主行，宿主行因预算整行省略时引导一并省略，不出现无所属的孤立引导。
- **原因**：合并成一张表后同一 ID 出现两行会让关系自相矛盾；孤立引导则让「这段引用属于哪个范围」不可判。
- **后果**：无下游文档或 schema 需要同步；`linkedEntries` / `fragmentRanges` 字段未变。

### 2026-09-17 — 零费用重渲染对照（验证结果）
- **方法**：对 bench-runs/2026-09-17T02-58-03-524Z-glm-low-default 的 20 次 rag_search 调用，用同一 query 与同一配置在本地重放（关闭 facts 附带，只对比 RAG 送达），使用当轮一次性重渲染脚本。脚本从 dist 导入，前置 `pnpm run build`。
- **结果**：RAG 送达字符 79,533 → 59,149（-20,384，-25.6%）；单次差值上中位数 -1,053、最大 -2,135；命中证据集合按块头 ID 比对 20/20 不变；命中块正文 27,796 字符两侧完全一致。
- **分区**：索引行 33,865 → 18,824（-15,041）、父级引导 6,820 → 4,655（PD-1 去重）、命中块头 5,997 → 4,213（去文件路径）、索引元信息 5,075 → 3,681。首轮分区统计把每次输出末行也计一个换行，多计共 20 字符；总字符直接取 data.length，不受影响。
- **口径**：对比对象是同一批调用参数的 RAG 送达文本，已排除附带事实卡分区（13,525 字符）；toolResultChars 与真实成本的下降幅度需真实运行才能确认，本轮未付费跑测。

### 2026-09-17 — 目录树接口与机械校验落点
- **plan 原文**：「`sections.ts` 新增按文件返回全部小节（含未命中、含无标题文件）的只读接口」「`corpus.ts` 在解析白名单时机械校验文件名唯一」。
- **实际做法**：
  - `SectionDirectory.outlineFor(file)` 返回 `{ file, title, nodes }`：`nodes` 只含二级及以下小节（一级标题由根行承载），`title` 取首个一级标题，无一级标题时回退为去扩展名的文件名；无标题文件返回空 `nodes`（只有根行）。
  - 基线名校验放在 `resolveManifestFiles`，与既有重复条目判定共用 Windows 大小写归一，错误信息列出两个相对路径。
  - 折叠候选只在 `buildTreePlan` 内计算（「非必需且父级为必需或文件根」的最外层子树才进候选），不做跨文件全局排序。
- **原因**：一级标题若同时作为树节点与根行标题，会出现重复行；把校验放在 manifest 解析处可覆盖 `collectMarkdownFiles` / `loadCorpusManifest` / `buildSectionDirectory` 全部入口。
- **后果**：多 H1 文件的第二个一级标题不再作为树节点出现，其下级小节直接成为森林根（现有语料无此形态，`fulltext-expansion` 的多 H1 用例只断言文档范围正文）。

### 2026-09-17 — `expandFulltext=1` 的目录树不重复展开预览
- **背景**：整篇正文已经送达，若命中节点再展开 100 字预览就是同一内容送两遍。
- **决策**：`buildTreePlan` 增 `withPreview` 开关，全文扩展路径传 `false`：树只补结构、命中标记与关联列，不展开预览。
- **后果**：`prose-links-hint` 的按文件扩展用例仍能按 `<id>｜<标题> ◆｜关联 N 个对象` 断言。

### 2026-09-17 — 退役 `contextFor` 与其用例
- **背景**：`SectionDirectory.contextFor` 只服务父级引导展示，本轮删除父级引导后它没有生产消费者。
- **决策**：删除 `contextFor`、`SectionContext`、`SectionParentLead`（`SectionEntry.firstChildHeadingLine` 保留，`prose-links` 仍在用），`sections.test.ts` 的「父级引导取父标题到第一个子标题之间的正文」用例改为断言新的 `outlineFor` 契约。
- **理由**：行为已废弃，属测试规则允许的用例替换；留着会是无消费者的死代码。

## 意外发现
> 实施中发现的 plan 未覆盖的依赖/边界/风险

### 2026-09-17 — 文档范围 ID 自带文件路径
- **发现**：标题前首部没有对应小节时以同文件文档范围为阅读入口，其 ID 形如 `doc:base/制造.md`，因此块头仍会带文件路径。这属于既有 ID 契约（ADR-022 决策 1），不是重复展示。
- **影响**：首轮保留该形态；第二轮按 ADR-023 切换为 `doc:<文件名>`。

### 2026-09-17 — 块头变短会移动既有预算边界用例的前提
- **发现**：section-navigation 的「首个可调用 ID 行放不下」原本用 baseline 长度加表头长度构造边界。块头去掉文件路径后 baseline 变短，同一预算下会多放进一个块，原前提失效（表头放不下、data 以续读行结尾）。
- **影响**：该用例改为以「实际正文长度 + 实际表头行长度」构造边界，不再依赖 baseline 常量。plan 未覆盖这类测试装配依赖，先记录以免后续误判为回归。

### 2026-09-17 — 100 字硬截断会落在词中
- **发现**：真实语料下 100 字常落在句子中间（如 `- 同一干员`、`承接组` 处截断），预览末行看起来像一条完整条目。
- **影响**：按用户裁定保留硬截断（不做句边界回退），截断标记 `…（截断，全文 N 字符）` 是唯一提示；后续若要改善，属展示口径变更，需重新定案。

### 2026-09-17 — 预览行与树节点同形
- **发现**：预览若直接沿用原文换行与缩进，`    - 同一干员…` 与 `    - 自动化组` 在文本层面不可区分。
- **解决方案**：预览每行加 `> ` 前缀（Markdown 引用语义），成本约 +2 字符/行。

### 2026-09-17 — BM25 单字分词会命中无关语料
- **发现**：bigram 分词同时产出边界单字，`共同关键词` 会因 `关` 命中正文 `无关正文。`，使测试语料里的「未命中」小节变成命中。
- **影响**：新写的目录树用例改用与查询无共同单字的正文；这是测试语料设计约束，不是实现缺陷。

### 2026-09-17 — 首轮全文回退路径的块头文件标识
- **发现**：`expandFulltext=1` 且缺少小节目录时走既有全文回退分支，块头仍会打印文件标识；本轮按「不展示路径」统一改为文件名。
- **影响**：防御分支与全文扩展块头口径一致，不再出现相对路径。

### 2026-09-17 — 非命中节点不再可精准读取
- **内容**：目录树只给命中行与整篇入口，命中文件内其它小节不再有 ID；需要其中的证据时可 read 整篇，也可继续检索或使用 read 返回的导航。
- **依据**：这是用户在本轮选定的设计取向（「精准命中阅读或全文阅读二选一」），量化结果见上文「结构性代价」。
- **重启条件**：真实运行显示 read 侧总字符显著上升，或作答质量因缺少邻节入口而下降时，再评估是否恢复部分邻节 ID。

> 遇到的阻塞问题及解决方案

### 2026-09-17 — 关系列取值命名：同级还是邻近
- **症状**：初版把 navigationFor 的返回集合命名为「同级」。
- **根因**：该集合实际是「同父级的兄弟 + 命中小节的直接子级」，不是单一层级，用「同级」会让模型误判层级关系。
- **解决方案**：关系列取「邻近」，表头说明写「同文件同级或直接下级」；plan 与实现同步更新。
- **预防**：层级与关系类标签按 sections.ts 实际返回的集合命名，不按直觉缩写。
