# R4 规则前缀（rules-prefix：稳定机制知识前置植入）

> 创建日期：2026-09-01
> 状态：已完成
> 上游：`docs/plan-retrieval-tuning.md`（R2/R3 检索器结论）；调研：2026-09-01「规则前置」四路调研（Concliude 规则机制 + 业界实证）

## 背景

- **检索词元层已闭环**（2026-09-01 三指标）：bigram 全面胜出（recall@5 33.5% vs 29.4%、precision 31.0% vs 24.0%、nDCG 0.368 vs 0.338）；jieba 在污染率与排序质量上同样更差——词级切分 × FTS5 AND 语义的 Concliude 经验离开其语义环境后失效（详见 `notes-retrieval-tuning.md` R3 节）。
- **文档侧改进已被实证排除**：小语料（267 chunks ≪ 5k）BM25 常胜稠密检索（SciFact nDCG@10 0.661 vs 0.645；<5k 文档 BM25 赢 3–8 点）；术语密集语料正是 embedding 结构性弱项（EntityQuestions：BM25 领先 DPR 49.8pp）；HyDE 具编造风险（弱模型毒药）；RRF 仅 +1.3–5%、引入依赖与成本。
- **真实杠杆转向知识分层**：稳定规则前置 vs 检索——CAG（WWW 2025）预载知识库可大幅加速；机制稳定垂域（基建规则）预估部分查询可获前置覆盖、减少补检轮次。Concliude 生产已用同一范式（AGENTS.md 常驻约束 + docs/rules/ 按需加载 + 静态前缀缓存设计）。
- **本语料天然分层**：`0-规则/`（发电站/制造/贸易/中枢/办公室机制）+ `2-体系/`（互斥组、核心双人）四维全过（稳定×全局×体量小×确定性）；`4-散件工具人/速查`、体系论证细节走检索。

## 目标

提炼「基建基础规则」注入 system prompt（指令段 + 知识段分层），用 20 题 A/B 实测量化对正确率/编造率/轮次/成本的影响，产出是否采用与规则内容基线。

## 非目标

- 不做「先答再决定」免检索门控（SR-RAG 式）——弱模型常错判「无需检索」→ 幻觉（ACL 2025 实证，minRag 调研已确认）；minRag=1 护栏保留
- 不做向量/RRF/HyDE/reranker（已实证排除，见上游）
- 规则段不做动态字段（时间戳/会话变量）——保 Hy3 前缀缓存命中（提示缓存对完全相同的稳定前缀：输入价格 4 折，1 元/M → 0.25 元/M）
- 不把语料全量塞 prompt（token tax 实证：全量载入正确率略高但每查询 token 26×）

## 设计

### 分层结构（核心架构：指令段 vs 知识段分离）

遵循「指令密度」实证（可靠遵守的并发约束仅 ~3–5 条；500 条指令时前沿模型遵循率塌缩至 15–69%；小模型更早衰竭）与「Lost in the Middle」（中部信息忽略 >30%，置顶优先遵循）：

```
┌─ system prompt ────────────────────────────────────┐
│ 【必须遵守】（≤5 条硬约束，置顶）                   │ ← 指令段：参与遵循竞争，每条 1 句
│  ⚠ 规则版本 v2026-09-01；与检索冲突时以本规则为准    │
│   1. 先套用下方基础规则作答，不得凭印象编造         │
│   2. 规则未覆盖 → 用检索；仍不确定 → 明说不知道      │
│   3. 引入干员/机制/数值必须能在语料原文找到依据（规则仅定位，不作证据） │
│   4. 给出答案时标注来源（必须为语料原文 file#小节；规则仅作提示、不构成独立来源） │
│   5. 数值类答案若规则与检索矛盾 → 以较新版本为准     │
│                                                    │
│ 【基建基础规则 v2026-09-01】（300–700 token）       │ ← 知识段：静态参考知识，不参与遵循竞争
│   发电站优先/数量 · 制造贸易配比 · 中枢互斥          │
│   体系互斥（meta_chain）· 公招刷新取向 · 排班原则    │
│   缺人降级路径概念 · 核心双人（缺一不可）            │
└───────────────────────────────────────────────────┘
```

- **指令段与知识段分离是硬性要求**：知识段标记为「参考知识」（非指令），避免被纳入遵循竞争（事实段虽长但只读不改，指令紧凑各自管理）
- **知识段仅为语料提炼的重复性事实、作提示定位**：不构成独立来源，答案须回指语料原文 `file#小节`（见指令段 Rule 3/4）
- **完全静态**：两段均无时间戳/会话变量/运行 ID；动态内容（检索块、对话历史）保持在消息末尾（DigitalOcean 教训：system 顶部加一行时间戳 → 缓存命中率 98.7%→0.7%）
- **版本戳**：`RULES_VERSION` 常量（如 `2026-09-01`），规则段首行显式标注；冲突裁决「版本高者胜 + 标注冲突」

### 内容来源与候选条目（四维判据筛选）

- **转录来源**：`docs/notes-rag-answer-baseline.md`（20 题参考要点与 file#小节 出处已梳理，可直接对应）+ `arknights-base-vault/docs/0-规则/` 与 `2-体系/` 核心节
- **候选进知识段**（初稿，实施时逐条对照语料核定）：
  - 发电站：优先级最高、数量规则、与虚拟电站关系
  - 制造站/贸易站：设施数量依赖型、效率分档、缺人降级路径
  - 控制中枢：主题站数、派系计数型（核心体系依赖）、中枢随体系同上同下
  - 办公室：公招刷新取向（核心干员取向、~30% 公招）
  - 体系互斥：meta_chain 互斥组、配套 buff 站、核心双人（缺一不可）、感知生产者（越多越好）
  - 宿舍/排班：不轮换、长班 12h/短班 6h 规则
- **明确不进**：散件数值表（4-散件速查，海量）、体系论证细节（数学推导）、CLI 求解器、版本易变内容
- **落地文件**：`bench/src/rules-prefix.ts`（纯数据：`RULES_VERSION` + `MUST_RULES[]` + `KNOWLEDGE_RULES[]`；零依赖、零副作用）+ 单测（静态性断言：无模板占位符/无 Date/无 env 引用；条目数上限：指令段 ≤5、知识段 ≤700 token 估算）
- 规则实现与语料一致性校验：gold 标注环节已有出处对照，实施时新增规则条目 → 反查语料原文确认（防「规则与语料冲突 → 整段失效」，arXiv 2607.19608：小模型忽略与任务先验冲突的指令）

### 实施步骤

1. `rules-prefix.ts` + 单测（静态性断言 + 条目数上限 + 版本戳格式）
2. `config.ts` 集中注入：`EXPERIMENT.rules`（默认关，A/B 对照组为 0；B 组置 true，长期结论后改默认）——实验开关集中 `config.ts` 头部 `EXPERIMENT` 常量，**不再读环境变量**（防 shell 残留污染基准）
3. system prompt 拼接：规则段置顶（在现有 system prompt 之前或紧跟角色段，需实测「前缀缓存稳定」是否受影响——**规则段本身不变即可命中**）
4. agent.ts：无需改动（冲突处理靠指令段）；保留 minRag=1
5. A/B 评测（见下）
6. 结论落盘 `notes-retrieval-tuning.md` 新增「R4」节（或独立实施笔记）

### A/B 评测判据

- **组**：A = 无规则前缀（当前基线）/ B = 有规则前缀（`EXPERIMENT.rules=true`）；同 20 题、同档（qwen-low + hy3-off 参照）
- **主指标**（人工核查）：正确题数、编造数（≥1 处即计）、平均轮次、≥2 轮占比
- **成本指标**：单题均价（含规则段固定输入 ~500 token 溢价）、缓存命中率（如运行记录可观测）
- **通过标准**：正确数不降 **且** 编造数下降 **且** 平均轮次 ≤ 基线 → 采用；任一不满足 → 规则精简（砍知识段条目）后复测一次，仍不满足则记录结论暂缓
- **补充**：单轮检索即正确占比统计（B 组中「1 轮检索即正确、无需再补检」的题数；不作通过标准，仅观察前置规则对轮次的削减效果）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 规则条数超遵循容量（指令密度崩溃） | 指令段硬上限 ≤5 条；超出内容一律入知识段（标记参考） |
| 规则与语料冲突 → 弱模型整段忽略 | 每条规则反查语料 + 版本戳 + A/B 回归 |
| 规则过期误导（语料更新后） | 语料入库触发版本 bump + 回归；旧版保留（move-then-retire） |
| 缓存命中被破坏 | 规则段完全静态 + 动态内容末尾（已有教训） |
| 弱模型「先答再决定」误判 | 明令不做免检索门控；minRag=1 保留 |
| 知识段过长稀释注意力 | 上限 700 token；超出部分修剪（按 A/B 复测） |

## R4：规则前缀（检索词引导）A/B 首轮实测（2026-09-01）

> 对应 plan：docs/plan-rules-prefix.md「R4 规则前缀」；前置：R2/R3 检索词元层闭环 + R1 注入矩阵（瓶颈在模型整合而非召回词元）。
> 方向演进：草案初稿为「稳定机制知识前置」，经多轮核对改为「检索词引导（QUERY_GUIDES）」——集中弥补语料缺 index 层导致的 RAG 代偿；且前置规则**不作来源**，答案须引用语料原文 file#小节。

### 实现（决策偏离）
- `bench/src/rules-prefix.ts`：纯数据（RULES_VERSION + MUST_RULES≤5 + QUERY_GUIDES 检索词建议），零副作用；`buildRulesPrefix()` 完全静态，保前缀缓存。
- 实验开关集中 `config.ts` 头部 `EXPERIMENT` 常量（rules/entityBoost/tokenizer/...），**不再读环境变量**（防 shell 残留污染，如 BENCH_ENTITY_BOOST=1.5）；retriever currentTokenizer/currentEntityBoost 读 EXPERIMENT；仅 API Key 保留 secret.yaml/env 兜底。
- query 引导为 rag/grep 构造能命中的关键词（抽象问题→query / 别名→官方词 / 体系→核心干员词）；agent 无 read 工具，故**不写文件路径**，只给 query。设计之基为「agent 对问题关联词的掌握 → 命中 query」假设。

### 检索词引导质量（hitrate 单轮口径，20 题）
引导词相对原问句首轮 recall 显著提升：

| 版本 | recall@3 | recall@5 | precision@5 | nDCG@5 |
|---|---|---|---|---|
| 原问题 | 21.3% | 33.5% | 31.0% | 0.374 |
| v3 引导 | 37.5% | 58.8% | 61.0% | 0.676 |

### G01 语料结构优化
G01（贸易站效率锚点散件）检索不到经诊断为**语料缺陷**：`散件干员速查.md` 多设施共文档 + 无设施级锚点 + 「贸易站」跨文档高频交叉（目标块被「制造站（赤金）」表、「贸易站搭配」等挤到第 6 位）。落地：各设施标题加「散件」类目标签（`## 贸易站散件` 等）+ 贸易站表加一句描述；gold G01 键迁移 `#贸易站散件`。G01 首轮 recall@3 0→1/1。

### A/B 首轮实测（qwen-low、20 题，唯一差异 EXPERIMENT.rules）
- **成本**（A=rules off / B=rules on）：
  - 平均轮次 2.20 vs 2.20（**未降**）；LLM 调用 44 vs 44。
  - 总输入 44,740 vs 80,839（**+80%**）；总输出 28,019 vs 44,153（+58%）；思考 14,052 vs 27,481（**+96%**）。
  - 总费用 ¥0.0314 vs ¥0.0513（**+63%**）。
- **质量抽查**（对照 notes-rag-answer-baseline）：
  - F02 制造站：A 偏题（套贸易站/9 步结算）→ B **聚焦修复**（面板 1+X+Y、红云/泡泡仓库转化、归零类）。
  - F08 排班：A 错误（12+12）→ B **正确**（12-6-6、A/B 上 18h 休 6h、C 上 12h）。
  - G01 散件：A 严重混装（清流/引星棘刺/苍苔/砾/阿罗玛/夜烟/斑点误入贸易站）→ B 大幅改进（混入减半、补全真散件、标注 file#），但仍混入 4 个制造站赤金散件（G01 为已知「散件分类混装」失败模式）。

### 全量基线核查修订（A/B/off 三组，2026-09-01）
> 上节「质量抽查」仅为 F02/F08/G01 三点，口径偏乐观；随后按 `notes-rag-answer-baseline.md`（v2 详版）逐条全量核查 A/B/off 三组（判定 正确/漏检/编造/存疑），修正如下。

三组环境（均 20 题 / qwen / bm25 / topK5 / maxContextChars 12000）：A=规则关、low；B=规则开、low；off=规则开、thinking=off。

| 组 | 正确 | 漏检 | 编造 | 存疑 | 平均轮次 | 总费用 |
|---|---|---|---|---|---|---|
| A（规则关, low） | **9** | 4 | 3 | 4 | 2.20 | ¥0.0314 |
| B（规则开, low） | 8 | 8 | 4 | 0 | 2.20 | ¥0.0513 |
| off（规则开, off） | 7 | 8 | 3 | 2 | **2.15** | **¥0.0297** |

- **规则开/关（A vs B，同为 low）**：B 正确 8 < A 9、编造 4 > A 3 → 本版 QUERY_GUIDES v3 + rules **未产生可验证的质量收益、反而略降**，且成本 +63%。**推翻上节「B 组显著优」**（该抽查高估了 B，上轮 F02/F08/G01 三点不能代表全量）。
- **G01 三组皆编造**：都把制造站（赤金）散件误入贸易站效率锚点——与 rules/thinking 无关，属语料「贸易站 vs 制造站」类目边界 + 检索层命中的根本问题。
- **off 是最经济解**：¥0.0297 比 A 低 5%、比 B 低 42%（成本瓶颈消失）；质量与 B 相当（正确 7 vs 8、编造 3 vs 4），仅略多 2 处存疑。
- 编造高发区 = 需跨文档归纳类目边界的题（F02/S05/G01）；强清单/锚点题（S03/S04/S06/S07/S08/G02）三组稳定正确。
- 评估噪声：跨组 subagent 判定存在口径差（如 A 的 F08 被描述为「12h↔12h 对半、结构错误」却仍标漏检），±1~2 计数不宜过度解读；关键项建议人工抽查语料原文（见基线使用说明第 3 条），本次未复验。

### 判定 / 结论（修订）
- 原「暂缓三选一」的根因（成本 +63%、平均轮次未降）经 off 组验证：**关闭思考即可把成本压到基线之下（更比 A 低 5%）、且平均轮次 2.15 < 基线 2.20**；但**规则本身（QUERY_GUIDES v3）未带来质量收益**。
- 按草案通过标准「正确数不降 ∧ 编造数下降 ∧ 平均轮次 ≤ 基线」复评：B 组正确降、编造升 → 不达标；off 组编造持平（3=3）但正确降（9→7）、轮次降（2.15）→ 仍不达标。
- **结论：R4 规则/检索词引导暂不采纳；默认基准调整为 qwen + thinking=off（关思考降本）+ 取消限流**。G01 类目边界与检索层命中为后续治理重点（语料/检索层，而非提示词注入）。
