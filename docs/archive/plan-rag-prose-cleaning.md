# RAG 散文清洗与索引组织计划

> 创建日期：2026-09-04
> 状态：已完成
> 下游：`docs/draft-facts-quality-iteration.md`（质量闭环在本计划完成后执行）

## 目标

把现有推荐散文清洗为适合 BM25 RAG 检索的玩家知识：删除外部项目实现与过程噪声，按少量主题文件和自然标题组织组合、培养与散件内容，并在人工通读后替换语料白名单中的旧 recommendation 文档。

## 非目标

- 不新建清洗台账、claim ledger、文档 schema、额外索引文件或索引生成器。
- 不修改 `knowledge/references/`、facts 记录卡、lookup/query_operators 或既有确定性门禁。
- 不在本轮重制 F01–F10/G01–G02 spec，不运行 12+5 正式评测；若发现 spec 与 `knowledge/references/` 直接冲突，只做最小一致性修正，并在实施笔记中记录。
- 不把 Rust、BFF、Redis、Python narrator、前端协议或其他外部项目实现迁入 RAG 语料。
- 不借清洗工作补做 S 类完整体系评测、`minEff` 数值化或 references 再生脚本。

## 架构分析

当前 `knowledge/recommendation/` 混合了玩家知识、产品策略、外部项目实现、历史状态与待办说明。`knowledge/corpus-manifest.json` 已把其中 `组合知识库.md`、`高效率散件与搓玉名单.md`、`新手必练与必收集名单.md` 纳入 RAG，因此 hybrid 查询可能检索到与当前仓库无关的实现描述或未经现有 references 重新核对的旧结论。

现有语料加载器已经按 `##` / `###` 标题切块，并以 `maxContextChars=12000` 作为上下文预算。清洗无需新建复杂索引体系，只需让文件名、一级标题和二三级标题直接表达玩家检索主题，并保证每个标题块可以独立理解且不被预算截断。

机械事实仍以 `knowledge/references/` 为唯一真源，机制公式以 `knowledge/base/` 为准。清洗后的散文主要承载组合用途、适用条件、协作原理、缺人替代和不适用场景；精确技能原文、完整持有者名单和动态分类继续由 facts 工具回答。

实施中还必须同步当前消费者路由：`knowledge/SKILL.md` 仍指向已经删除的 `docs/0-规则/`、`docs/2-体系/`、`docs/4-散件工具人/`，只切换白名单而不更新该入口会使 RAG 内容可检索但问答技能仍走失效路径。

## 组织形式

新增 `knowledge/guides/`，只建立五篇可检索成品：

```text
knowledge/guides/
├─ 贸易站组合.md
├─ 制造站组合.md
├─ 跨设施组合.md
├─ 新手培养.md
└─ 高效率散件.md
```

- 组合类文件按组合名称使用 `###` 标题；旧称或常见别名直接写在标题或开头一句，不维护独立别名索引。
- 每个组合块只保留：用途、适用条件、成员与分工、运作原理、缺人替代、冲突或不适用情况。
- 新手与散件文件按设施或用途使用 `##` / `###` 标题，不复制完整技能表。
- 不添加 YAML frontmatter、文档 ID、标签表或额外元数据层。

## 清洗规则

### 保留

- 玩家能直接使用的组合、培养与散件结论。
- 解释结论所需的设施条件、核心成员、关键练度、协作原理和缺人路径。
- 有助于检索的规范名、旧称和常见别名。
- 对选择有决定作用、且能由当前 `base/` 或 `references/` 核对的关键数值。

### 删除

- Rust、BFF、Redis、Python、前端、CLI、接口、缓存和部署描述。
- `data/*.json`、外部仓库路径、不存在的相对链接和旧实现状态。
- C1/T9 等内部裁决编号、阶段进度、TODO、交接和验收说明。
- 推荐人数上限、前端展示顺序等产品输出策略。
- 与 facts 重复的完整技能原文、完整干员名册和大段机械枚举。

### 核对

- 干员规范名、设施、练度、技能升级/替换、派系、技能类别和等价组直接对照 `knowledge/references/`。
- 设施公式和基础机制直接对照 `knowledge/base/`。
- 机械事实与关键数值必须由当前 `references/base` 确认；已批材料只承载玩家判断，且不得与机械真源冲突。`组合成员练度审阅稿.md` 可作为已批判断材料，但不是机械事实真源。
- 每个 `##` / `###` 块应能脱离上下文独立阅读，避免只写“同上”“见前文”。

## 实施方案

1. **首轮散件试点**：以现有 `knowledge/recommendation/高效率散件与搓玉名单.md` 为输入，生成未登记到白名单的 `knowledge/guides/高效率散件.md` 候选；保留玩家判断、成立条件和身份边界，删除实现、报告策略和内部裁决噪声。办公室章节按 `knowledge/references/技能-办公室.md` 补齐可核验的联络散件，并排除 references 未登记办公室技能的焰狐龙梓兰。
2. **首轮人工通读**：由用户逐段确认候选稿的事实冲突、条件是否被过度压缩、重复维护、内部术语和遗漏项；审查结果追加到实施笔记，并据此固定后续四篇的清洗规则。首轮审查未完成前不批量清洗、不切换白名单。
3. **清洗组合散文**：以现有 `knowledge/recommendation/组合知识库.md` 与已批审阅材料为输入，提取仍有用的玩家判断，按贸易站、制造站、跨设施三个主题改写为 guides；逐项以当前 references/base 修正成员、练度、设施和互斥关系。输出 `贸易站组合.md`、`制造站组合.md`、`跨设施组合.md`。
4. **清洗新手散文**：以现有 `knowledge/recommendation/新手必练与必收集名单.md` 为输入，整理为一篇短文，保留选择理由和条件，删除外部实现及产品输出规则。输出 `新手培养.md`。
5. **消费者与结构导航同步**：将 `knowledge/SKILL.md` 的机制、体系、散件和布局路由切换到 `knowledge/base/` 与 `knowledge/guides/`；更新 `AGENTS.md` 的仓库结构说明，标明 guides 是经审定的 RAG 散文；同步修正受影响的加载器注释或旧路径说明，不改变运行时接口。
6. **人工通读与收缩**：五篇成品完成后由用户逐篇确认事实冲突、重复维护、内部术语、失效链接和依赖上文才能理解的片段；未确认或无法核验的内容删除或收缩表述。人工通读未完成前不得切换白名单。
7. **原子切换白名单**：五篇均通过通读后，在 `knowledge/corpus-manifest.json` 中用 `guides/` 成品替换三篇旧 recommendation 文档，不整目录放行。同步更新 `bench/tests/corpus-allowlist.test.ts` 的批准集合，断言 9 篇 base、14 篇 references、5 篇 guides 被加载，旧 recommendation 成品不再加载。
8. **现有管线验收**：运行文档一致性、类型检查与测试；使用现有检索器的聚焦单测，以少量代表性问题确认组合规范名、旧称、新手与散件主题能命中正确标题块，且不会检索到外部实现内容；同时确认目标块没有被 12000 字符上限截断。验收不依赖当前停用的 hitrate gold。

# 实施笔记：RAG 散文清洗与索引组织计划

## 决策偏离
> spec 中没有提到，但在实施中做出的重要决策

### 2026-09-04 — 玩家侧术语与上游直出格式分层
- **背景**：清洗稿同时出现“精零”和“无练度要求”、稀有度值的文字与符号写法，以及“订单效率/订单获取效率”“联络效率/联络速度”等成对称呼；直接全仓替换会改动 references 的上游直出格式，并混淆最低练度与推荐策略。
- **选项**：
  - A：只在本轮人工修正文案，不建立长期约束。
  - B：为 `knowledge/base/` 与 `knowledge/guides/` 建立玩家侧规范词表和自动检查，references 保留原始格式。
- **决策**：选择 B。拥有即可满足统一写“精零即可”；“不设独立培养目标”只表示不单独推荐培养；稀有度与设施指标使用统一规范词。
- **影响**：新增 `docs/rules/rag-prose-terminology.md` 和 `pnpm run check:prose-terms`，并将检查加入合并门禁；当前清洗稿与 base 中同类写法同步收敛。

### 2026-09-04 — 将问答消费者路由纳入交付范围
- **背景**：草案只要求更新 `AGENTS.md` 结构导航和白名单，但当前 `knowledge/SKILL.md` 仍把机制、体系、散件内容指向已删除的旧散文路径。
- **选项**：
  - A：仅切换白名单并更新 `AGENTS.md`，保留 `knowledge/SKILL.md` 现状。
  - B：同步更新 `knowledge/SKILL.md`、`AGENTS.md` 及受影响的旧路径说明。
- **决策**：选择 B。白名单切换和问答入口必须保持一致，否则运行时虽能加载 guides，技能路由仍会产生失效引用。
- **影响**：本计划增加消费者文档同步验收，但不改变 RAG/facts 公共接口或检索实现。

## 实现调整
> spec 中有描述，但实际实现方式不同

### 2026-09-04 — 先生成未入白名单的散件候选稿
- **spec 原文**：先清洗现有推荐散文，再在五篇成品完成人工通读后原子切换白名单。
- **实际做法**：先从 `knowledge/recommendation/高效率散件与搓玉名单.md` 生成 `knowledge/guides/高效率散件.md` 单篇候选，不修改 `knowledge/corpus-manifest.json`、白名单测试或其他 guides。
- **原因**：先让用户审查一篇真实清洗结果，确认保留/删除、条件表达和标题切块规则，再批量处理其余文档，避免五篇一起返工。
- **后果**：候选稿在人工通读完成前不属于运行时语料；后续需根据审查结果决定是否调整内容、补充缺口或回退结构。

### 2026-09-04 — 首轮散件候选通过人工通读
- **spec 原文**：首轮候选通过人工通读后，才能固定后续清洗规则并继续其他 guides。
- **实际做法**：用户确认 `knowledge/guides/高效率散件.md` 的清洗效果通过；候选稿继续保持未登记白名单状态。
- **原因**：人工审查确认了玩家判断、成立条件、组合边界和实现噪声的拆分方式可用于后续文档。
- **后果**：后续可按该结构继续清洗；办公室散件与当前 references 的冲突仍需单独裁决，不能因本轮通过而自动补入。

### 2026-09-04 — 办公室散件定向复核通过
- **实际做法**：用户确认删减后的高效率散件候选通过人工审核；办公室段按 `knowledge/references/` 保留可核验的驻员联络效率，并明确区分焰狐龙梓兰的控制中枢全局加成。
- **结果**：G02、F05、F09 的办公室口径完成最小一致性修正；候选稿仍未登记到白名单。

### 2026-09-04 — 以 references 作为办公室散件冲突的权威口径
- **背景**：用户确认后续处理支持 `knowledge/references/` 口径。现有 G02 将焰狐龙梓兰列为办公室散件，但 references 的名册仅将其登记为贸易站、控制中枢干员，技能-办公室没有对应条目。
- **决策**：以 `knowledge/references/` 为机械事实真源；在高效率散件候选中补入 references 已记录且达到办公室参考线的珊比、艾雅法拉、遥、普罗旺斯，保留斥罪、凯尔希·思衡托等带代价或设施条件的单独边界，并排除焰狐龙梓兰。
- **影响**：对 G02 只做最小一致性修正，不重制整份评测规格；该修正完成后，办公室段仍需用户针对新增内容做一次定向复核。

## 意外发现
> 实施中发现的 spec 未覆盖的依赖/边界/风险

### 2026-09-04 — 同义词排查包含语义不同的近似表达
- **发现**：“无练度要求”在旧材料中既表示最低练度为精零，也用于表示挂件不产生独立培养建议；此外还发现订单获取效率、联络速度、仓库容量等指标存在简称混用，base 会客室表使用了与 guides 不同的稀有度值和精英阶段记法。
- **影响**：统一规则必须同时记录最低练度和推荐策略，不能做单纯同义替换；自动检查范围限定在人工清洗层，避免改写机械真源。

### 2026-09-04 — 办公室散件口径无法从当前输入直接补齐
- **发现**：当前散件源文档没有办公室章节；旧评测 spec 将遥、艾雅法拉、焰狐龙梓兰列为办公室散件，但当前 `knowledge/references/名册.md` 将焰狐龙梓兰登记为贸易站干员，`knowledge/references/技能-办公室.md` 也没有对应条目。
- **影响**：首轮候选暂不擅自加入办公室散件，避免把 spec 与 references 的冲突写入新 guide；正式白名单切换前必须由人工审查决定以哪个真源为准，并同步更新 spec 或数据层边界。

### 2026-09-04 — 贸易站组合候选进入人工审查
- **发现**：首轮散件人工通读通过后，下一篇最适合验证组合清洗规则的是贸易站章节；原文包含核心、重要成员、挂件、跨设施分工和旧名边界，能覆盖后续组合文档的主要结构。
- **处理**：生成未登记白名单的 `knowledge/guides/贸易站组合.md`，只保留玩家可执行的设施分工、成员条件、练度、缺人降级和不适用边界；未修改 manifest、加载器或白名单测试。

### 2026-09-04 — 贸易站组合候选通过人工通读
- **实际做法**：用户确认删减后的 `knowledge/guides/贸易站组合.md` 清洗结果通过人工审核。
- **结果**：组合候选可作为后续制造站、跨设施组合文档的结构样板；本次提交仍不切换白名单。

### 2026-09-04 — 制造站组合候选进入人工审查
- **处理**：按已批组合成员练度材料和当前制造站相关 references，生成未登记白名单的 `knowledge/guides/制造站组合.md`，覆盖赤金、经验和通用制造组合。
- **取舍**：保留核心/重要成员、设施分工、启动条件、缺人降级和组合值边界；怒潮凛冬仅保留“按散件使用”，搓玉不建立组合；删除实现路径、动态枚举细节和报告展示策略。
- **状态**：用户已人工通读并通过；未修改 manifest、加载器或白名单测试。

### 2026-09-04 — 制造站组合候选通过人工通读
- **结果**：`knowledge/guides/制造站组合.md` 的组合分组、设施分工、练度条件和收益边界通过审核，可作为后续跨设施与新手文档的清洗样板。
- **后续**：候选稿继续保持未登记白名单状态，待五篇成品全部通过后统一切换。

### 2026-09-04 — 跨设施与新手培养两篇批量评估
- **评估对象**：组合知识库中的感知信息组、龙门中枢组、凯尔希·思衡托挂件关系，以及新手基建必练与必收集名单。
- **结论**：两篇内容边界清晰、相互依赖少；跨设施成员与设施可由当前 references 核对，新手名单只需保留最低目标、获取方式和去重口径，适合一次生成两篇候选。
