# RAG 送达范围与入口优化计划

> 创建日期：2026-09-11
> 状态：已完成
> 当前阶段：施工中（工程步骤 0 契约、步骤 1 技能表退出、步骤 2 原文扩展、步骤 3 精确词条自动附带 facts、步骤 5 测量口径与观测消费者收敛已完成；步骤 4/6 为独立试验与付费对照，待授权后另行 exp；2026-09-11 修订）

## 目标

收缩 rag_search 的检索候选池（九份技能表退出检索）、让机制/指南语料按文件扩展原文返回、并让 rag_search 的精确搜索词自动附带内部 facts 记录卡，从而改善必要证据的送达；同时承接「名称改写与干员/阵营/组合混用」的实体标记验证设计。本计划整合两条需求，工程交付与试验执行分别验收：本轮检查、修订和细化需求，不启动运行时改造或付费调用。实体标记与付费对照按步骤 4、6 另行路由 exp，不作为工程提交必须先取得正面试验结果的条件。

## 非目标

- 不改 agent loop、ADR-012 的外部调用双上限与扣点规则、knowledge 事实真源。定稿实施时允许同步工具描述与 knowledge/AGENTS.md 的工具选择说明，使其准确描述 RAG 附带 facts 的行为；不借机调整作答策略。
- 不引入向量检索、rerank、字段/文档类型加权等新打分层，也不改 BM25 参数（k1=1.5、b=0.75）——单列为另一条线，另行评估。
- 不针对题集做特判或改写；优化须可泛化，并用未参与调优的问题验证。
- 不新增哈希/指纹字段（编码核心约束 #10）。
- 实体标记探针只作用于固定工具返回的渲染副本，不修改正式语料、references 直出格式、索引或生产默认渲染；不由探针直接授权全库改写。
- 本轮不处理「证据已送达但回答未覆盖」与练度档位误读两类问题——它们属作答行为，不在检索范围与入口改动的作用面（见「架构分析·本轮归因边界」）。

### 关键风险

- facts_search 只吃精确词条、不解析自然语言。自动附带可减少符合入口规则时的额外显式调用，但不会补齐模型未提出的词条；组合、设施等入口可一次返回多卡，不能把取证成本等同于逐人调用数。默认 5 次成功额度是否够用仍需行为验证。
- 增加同次返回内容可能减少后续调用，也可能增加无关证据、截断与累计输入 token；调用次数下降不能替代费用测量。现有独立 facts_search 返回完整卡，不受 RAG 的 maxContextChars 限制；自动附带必须单独明确容量契约。
- RAG 合并结果默认受 maxContextChars=12,000 约束；read_section 是另一工具，其正文另受每页 6,000 字符上限约束，该分页上限不自动约束 rag_search 的原文扩展。命中文件不等于整文必然送达。
- 现有 runHitrate 在 gold 无法解析时会报错，不只是 recall 下降；只改 runner 的过滤又会让 CLI hitrate 继续测旧范围。gold/spec 的事实要求不因技能表退出而删减，检索排序与实际送达需要分别计量。
- 渲染层实体标记不改变分词、切块或 BM25 排序，但会增加返回长度并可能改变后续模型调用；必须隔离截断差异。把标记写入正式语料才可能改变索引，本计划不包含该变更。

## 实施方案

先完成步骤 0 的契约与步骤 5 的测量口径设计，再实施步骤 1→2→3；步骤 5 的观测落地随工程实现贯通。步骤 4 是独立试验设计，不阻塞步骤 1–3 的工程验收，也不依赖它们完成；步骤 6 的主工程对照依赖步骤 1–3、5，实体标记端到端对照只有在步骤 4 形成采用提议后另行安排。文件级 BM25、本次未登记的新词条与正式实体标记均不混入首版工程。

### 步骤 0 — 施工前契约收口与 ADR

检索范围调整、原文扩展返回契约与 RAG 内部 facts 附带接口属跨模块公共接口变更，按文档生命周期须建 ADR。编号取 docs/adr/INDEX.md 最大值递增，只引用编号更小的 ADR。登记后本计划「关联 ADR」同步。

- 输入：本计划；输出：ADR 文件 + INDEX 登记；验收：ADR 覆盖检索范围、原文扩展、内部 facts 附带契约，并区分外部工具预算与内部查询观测。
- 本步骤完成前不开始运行时改造；保留本计划作为工程入口。对应 notes 已记录本轮需求复核，后续实施继续实时登记偏离与决策。
- 固定首版采用「小节 BM25 + 命中文件原文扩展」，文件级 BM25 不作为本计划必须实现的第二套方案。语料范围与是否附带 facts 分别配置：bm25/hybrid 默认均排除技能表、均可扩展原文，只有 hybrid 附带 facts；不让对照模式暗中改变同名范围。
- 为步骤 6 提供可读、相互独立的有效配置：是否包含技能表、是否扩展原文、是否自动附带 facts。冻结默认组合（排除/扩展/附带；bm25 附带关闭）与对照组合（见步骤 6），由统一配置装配供 runner/CLI 使用，并写入 inputs/meta；显式在 bm25 请求附带应报中文参数错误。不要增加新的检索模式枚举或全部排除 references 的生产选项。
- 容量决策必须先落文档（2026-09-11 定稿，ADR-013 决策 4）：工具 `data` 的 UTF-16 长度分批计量，外层 JSON 长度单独观测、不冒充同一上限。RAG 正文（来源头、导航、续读元数据与正文）沿用 `maxContextChars`（12,000）；RAG 内部 facts 附带在该上限之外另给独立额度 4,000 字符，两部分不互相回收，合并 `data` 上限为 maxContextChars + 4,000。facts 附带只计入分区头、未附带提示等必要元数据与卡正文；RAG 极小上限沿用步骤 2 的明确容量错误语义，不无限压缩正文。
- schema 分层：工具定义版本 TOOL_SCHEMA_VERSION（步骤 0 设计时为 9；步骤 2/3 的 rag_search 返回语义扩展合并为一次递增，步骤 3 实施升为 10），facts 结果版本 FACTS_RESULT_VERSION=5，trace 版本=3，不能统称「schema v5」。ADR 须列出本次实际变动的 schema、字段及消费者；按协议变更递增，不因内部实现改动盲目重编号，不新增哈希字段。

### 步骤 1 — 检索范围收缩（技能表退出）

- 范围：九份 `references/技能-*.md`；其余 references 保留。校验中明确区分「仅排除技能表」（145 块）与「排除全部 references」（110 块）两种范围，不混用。
- 落点：在检索装配层过滤，不改 knowledge 真源与 corpus-manifest 语义；分块真源与原文目录仍用于证据定位。
- 两种模式共用同一范围装配，按步骤 0 默认排除技能表；旧范围仅通过显式配置用于同工具集对照。过滤在建索引前执行，索引下标与过滤后数组配套传递，不得用过滤后下标索引全量数组。
- 证据预期：单独排除主要降低注入占比与噪声（本轮技能表占注入 40.2%），仅 F04.1 由此进入 top5；机制送达主要由步骤 2 承担。
- 输入：语料与索引装配；输出：过滤后索引与可辨识的范围参数；验收：默认技能表块不再进入 rag_search 候选，其他 references 与 base/guides 的成员集合保留（排名可因索引统计变化而改变）。复现全量 749 与排除技能表 145 两组；110 仅作解释性计数，不扩展产品范围。保留完整小节目录及 gold 定位，不从 manifest 删除技能表，也不新增通过路径任意读盘的能力。

### 步骤 2 — 机制/指南语料按命中文件扩展原文（依赖步骤 1）

- 保留小节 BM25。取 topK 命中后，base/guides 按文件去重并扩展到原文目录的文档范围；顺序取首次命中位置，不在去重后自动补满 K 个文件。其他 references 仍按原块返回。扩展内容必须取运行级原文快照，不拼接 clampTexts 后的片段（该函数会省略中段）。
- 证据预期：在容量足够、原文范围正确时，有机会送达表中的五个目标小节；F08.3 逐分项检查。F07.2 的原 query 未命中宿舍文件，read_section 只能读取已有可调用 ID，不能作为跨文件自动兜底；模型可依据线索重新检索，但本计划不承诺其成功，不增加题目特判或自动查询改写。
- 容量契约：单文件当前均小于 12,000，但多结果、来源头、导航和 facts 附带的总量可能超限。定稿约定合并结果上限与 RAG/facts 的空间分配；超限不承诺整文一次送达，须保留完整可调用的读取入口与明确的未送达状态，不能把命中文档等同于全部证据已注入。read_section 现有 6,000 字符分页上限保留为首选，单改 maxContextChars 不改变此上限，是否修改另作显式决策。
- 输入：topK 命中；输出：扩展后的送达正文与未送达状态；验收：命中文件的其他小节可被送达，超限行为可解释且不伪报已注入。
- 范围与续读：当前目录有 H1–H6，小节正文包含下级标题，无标题文件才建 level=0 根节点，不能假定每文件都有可读根 ID。实现须提供已登记、覆盖整个正文的文档范围与其 ID，或明确验证单 H1 范围确实覆盖正文；无 H1、多 H1、标题前正文都不能静默丢失。复用原文行号与 UTF-16 offset，frontmatter 排除按既有阅读契约；已有 section ID 不变，新范围不得令旧 ID 失效。
- 超限按可续读的连续原文范围送达，元数据先留位，记录实际起止 offset、行范围、complete 和 next_offset。导航 ID/词条不可截半；正文只有一个字符送达也不算整节已读完。极小上限连必要元数据加一个正文字符都放不下时，返回明确 error，不伪装 empty 或扩容；延续同类 read_section 非 fatal 容量错误语义，不新增重试。
- 覆盖测试：同文件多命中去重、跨文件稳定排序、无 H1/多 H1/空正文、超长行与非 BMP 字符、恰好容纳/不足一个字符、跨页拼接无缺口、references 不扩展，以及正文头部/中段/尾部的实际送达。source 行范围和 offset 必须对应原文，不能用展示长度推算完整覆盖。

### 步骤 3 — RAG 精确词条自动附带 facts（依赖步骤 1–2）

目标：在一次 rag_search 返回中附带相关事实；实现复用 store.factsSearch，不在 agent loop 内伪造额外 facts_search 调用，不引入额外 LLM 请求。

#### 入口识别

1. 仅在 hybrid 的 rag_search 启用；bm25 保留纯 RAG，不暗中取得 facts 能力。独立 facts_search 的单完整词条协议保持原样。
2. 词典来自现有六类 facts 词条与已校验的 alias/substring/combo 登记，与 factsSearch 使用同一套数据；不另建题集词表，不从 notes、技能效果散文或 BM25 分词结果推导入口。store 可提供只读候选词访问能力，派发层不自行重建另一套事实解析规则。
3. query 只做首尾 trim，保留内部标点、大小写与空白。先尝试整条 query 精确匹配：所有现有合法词条类别均可触发，单字正式名也可；若成立，不再扫描其内部短词。
4. 整条未匹配时，从左到右识别由空白边界隔开的完整登记搜索词：边界为字符串首尾或 JavaScript `\s` 空白，词内字符原样相等。含内部空格的登记长词整体匹配；同起点先按长度确定完整词边界，再按规则 5 判断是否准入，不通过也不拆其内部短词。已消费范围不重复触发，其他非重叠词按 query 中出现顺序处理并去重。同一完整词的类别与解析路径保留并集。未匹配部分继续参加原 BM25 查询，不改写 query；观测位置记录本次实际检索 query 的 UTF-16 区间（工具层已 trim，识别函数对未 trim 输入自行校正偏移）。
5. 多关键词分支只接纳至少两个字符的干员名、技能名、技能组、阵营及登记 alias/substring/combo；仅命中设施或职业的搜索词不在该分支自动展开，避免「制造站 生产力」拉取整站名单。同一完整词条若还命中其他类别，一旦准入，factsSearch 的全部路径仍保留，不做类别消歧。设施/职业查询仍可经规则 3 或显式 facts_search 使用。
6. 首版不识别未分隔自然句中的词条、不把逗号或加号强行当分隔符、不补删「组」字、不做近义改写或任意子串扫描。自然句实体提取另作候选评估，不与本版混入。

| rag_search 的 query | 候选行为 | 边界说明 |
|---|---|---|
| `温蒂` | 整词触发一次 facts 查询，同时保留 RAG 检索 | 不要求另一次显式工具调用 |
| `温蒂 自动化组 第三人` | 两个登记搜索词分别触发，同次合并去重 | 「第三人」不推导为某个干员或过滤条件 |

#### 查询、去重与展开边界

- 每个准入词最多调用一次现有 factsSearch；同一词的 exact/alias/substring/combo 按现有规则并集，保留全部解析路径。同名歧义不选单一卡，不用 BM25 排名替代 facts 的匹配契约。
- 候选检测使用同一 store 的只读词典，不为枚举候选预先对所有词执行完整 factsSearch；整词是否登记不等于是否有非空卡，零卡路径的准入、计数与送达分开。首次加载仍遵守 store 的惰性与失败回调，无模块顶层 IO；未获准的外部调用不触发任何内部查询。
- 多词结果按 canonical 去重，卡正文只渲染一次，同时保留每个触发词与命中卡的关联。顺序为 query 中词条首次出现顺序、词内沿用 store 的稳定卡顺序；不新增相关性打分或文档类别权重。
- 去重仅作用于本次响应，不因前轮或显式 facts_search 已返回同一卡而自动省略本次证据；跨调用复用会改变预算与可复核语义，本版不引入。重复送达比例作为成本观测，不能从外部调用统计中扣除。
- 只做一跳：combo 已登记成员可以直接返回；卡片 notes 中出现的其他名字、RAG 命中正文中的实体和附带结果中的新词不再自动触发。导航备注仍是供模型判断的线索，不升级为递归执行指令。
- 保留记录卡的条件、替换关系、命中路径与来源信息；不由宿主概括技能、不把多词并集解释成满足多个条件的交集或完整推荐名单。

#### 结果容量、预算与观测

- RAG 证据与附带 facts 在一次响应内分区呈现；RAG 正文沿用 `maxContextChars`（12,000），附带 facts 在该上限之外另给独立额度 4,000 字符（ADR-013 决策 4，2026-09-11 定稿），两部分不互相回收，合并 `data` 上限为 16,000，外层 JSON 单独观测；仍给 RAG 正文与续读入口保留其原有空间。离线统计触发词数量、去重卡数、整组序列化长度与未附带比例，用于复核额度，不先任意设卡数阈值。
- 容量装配可复现：facts 附带独立额度只计入分区头、未附带提示与卡正文，以单个触发词的完整匹配集合为原子单位逐个尝试剩余额度；首版不做 RAG/facts 互相回收，两部分各自计算实际送达状态后一次性返回，禁止最终统一 slice 截断已声明完整的卡或导航。RAG 极小上限沿用步骤 2 的明确容量错误，不无限压缩正文或无限增加提示。
- 首选容量规则以单个触发词的完整匹配集合为原子单位：去重后的新增完整卡与该词全部解析路径能放入时一起附带；放不下则该词整组暂不附带，返回完整可复制的词条及原因，供必要时显式 facts_search。允许后续独立词组继续尝试剩余空间；不截断卡正文、不挑一张卡消除同名歧义。跨词已返回的共享卡可复用，但该词自身全部成员和路径未齐时不得标记完整。
- 区分触发、匹配与送达：未命中、因容量未附带、完整附带分别记录；未附带原因给出整组所需与剩余额度。未附带不代表零匹配；开放组合即使已返回登记成员，也不表示穷尽游戏中所有适配成员。facts 分区头与未附带提示均计入 facts 独立额度，二者都放不下时不写入只含分区头的截断词条，也不回改 RAG 正文预算。
- 一次外部 rag_search 获准仍只计 1 次 attempt；执行无错误且 RAG/facts 任一部分实际送达非空证据才计 1 次 success，二者均无正文证据则 empty，提示与路径元数据本身不扣成功额度。内部 facts 查询次数不额外消耗工具额度，重复返回证据仍沿用 ADR-012 的扣点规则。
- 内部 facts store 加载或查询抛错时沿用当前工具执行错误的 fatal 语义，整次调用报 error、不扣成功额度；不静默降级成成功 RAG，也不增加隐式重试。空匹配、容量不足属可解释的结果状态，不是执行异常。
- 组装为原子过程：先计算全部分支并确认最终输出，再更新共享送达列表与 success 计数；分支抛错时不得留下本次未发送的 RAG/facts 注入记录。已计算但未发送的匹配只作失败诊断，不计实际送达。
- trace 保留一条外部 rag_search 调用；内部补充记录触发词、触发词在本次实际检索 query 的位置、解析路径、匹配/送达 canonical、未附带原因、字符数及耗时，并接入既有 facts store 使用/失败回调。统计分别报告显式 facts_search 次数、RAG 内部 facts 查询次数与实际附带次数，不伪造模型调用或 HTTP 次数。
- 既有 RAG hitIds/injectedIds 保持 chunk 语义；自动附带卡与原文扩展范围单独记录实际送达，不能混入一个无类型 ID 列表或把整个文件记为已注入。附带结果不能直接套用当前独立 factsResult 的 `complete: true`；新字段及 schema 版本在 ADR/plan 定稿时定义，旧运行缺字段表示不可用，不能补零。
- 费用仍按 provider 实际 usage 计量，含后续轮次携带这些证据的累计输入与缓存；减少一次显式工具调用不等于免除 token 费用。

#### 证据预期与登记边界

- 本轮预期：固定 S05 query 中的 `自动化组` 满足触发规则，现有 8 卡包含所需字段；只有整组结果实际装入响应，才可记为相应事实已送达，不能宣称三个必答项因此稳定答对。S07 的 `红松骑士团` **会触发**阵营查询，只是五张卡不包含薇薇安娜；相关 notes 可提供组合词线索，但不自动递归查询或补「组」。F05/G02 无准入词，自动附带不触发。实体标记只验证已提供名称/类型的表达，不能创造缺失线索，也不承诺修复这些取证缺口。
- 登记补全：本轮优先复用既有登记，不为历史题目追加短词或备注。后续确需补入口时，以正式名/别名/组合身份与语料来源为依据，明确同名和简称的目标集合；现有 alias/substring 只指向干员，组合简称不能硬塞进该结构或冒充阵营，需单独定义契约后再评估。沿用 docs/plan-facts-crossref-navigation.md 的来源审计口径，未分隔自然句及成员名全排列不作为本版强制覆盖目标。

- 待实现并验证的机械契约：完整词、空白关键词、长词含空格与重叠词边界、多词重叠去重、带内部标点的名字、单字名、设施/职业大集合、阵营与组合差异、未知短词、容量未附带、只 facts 非空、两路均空、内部异常且注入状态不残留、预算拒绝不查询、bm25 不触发、历史格式读取与计数分离；用构造词条验证机械契约。上述离线 store 查询不等于这些尚未存在的运行时功能已通过测试。

### 步骤 4 — 实体标记验证设计与试验承接（独立可选试验线）

目的：针对名称改写与干员/技能/阵营/组合混用，验证固定工具返回中的实体标记是否改变下一次响应的名称忠实度与词条选择。F02「卡缇卡」、F06「我知道能行」是在回答中发生的命名偏差，不能直接当作已发生的错误工具调用；探针分别观察回答与调用两种结果。S07 的阵营词合法，查询未返回组合外围成员也不等于类型错误。不改正式语料或生产默认渲染，不改 BM25 分词/排序。

工程验收只要求本节设计按当前协议收口、执行输入与授权边界明确。旧设计未执行，取消并保留历史于 docs/exp/exp-entity-marking-probe.md；新的试验在实际获授权后另建 docs/exp-*.md，按模板记录过程/结果/结论。未启动时登记「尚未执行」，不能为了 plan 全勾选把试验写成完成；独立 exp 的执行不阻塞主工程交付。

- 三组对照（只改返回片段的表示）：A 原文；B 名称边界；C 显式类型（干员、技能、阵营、组合）。同一范围内所有已核验实体统一标记，不能只标预期答案；B 包裹完整专名，C 根据既有事实标注类型，不删字、不补「组」。类型来自名册/技能索引/组合登记与标题职责；同名有多个类型时保留歧义，不依据期望答案选唯一类型；无法确定的片段在冻结前更换并记理由。禁止对 ID、URL、分页 offset 等协议字段加标记。
- 最小样本：6 个案例，其中红松、格拉斯哥为诊断例，另 4 个问题及证据片段在设计完成前未参与调优，用于留出观察，并覆盖技能、干员、阵营、带标点专名和组合/阵营差异。例子可以覆盖多个维度，但须预先登记允许的有据行为，不仅登记唯一工具名；不能拿 20 题的同一问法改写充当独立留出。每例三组各 2 次，共 **36 次逻辑模型调用**；HTTP 重试另计，失败不替换为追加成功样本。
- 冻结条件：执行前在 exp 明确 provider/model、thinking、temperature 是否发送、max_tokens、工具集合、system/user/assistant/tool 历史、代码基点、工具定义版本及 facts 结果版本。当前工具定义 v9、facts 结果 v5；若届时实现已变更，记录实际版本，不硬编码「当前 v5」。六组样本按 ABC/BCA/CAB 轮换，独立会话，保持 tool_choice=auto；一次只生成下一条响应，不启动 agent loop 或下一次模型调用。冻结请求、重试/超时规则与累计费用停止边界后才执行，不虚构预算数字。
- 渲染隔离：先取得同一原文证据范围，再生成三种展示副本；三组事实、实体集合、顺序、source ID、原文 offset 一致，仅标记不同。共同选择能容纳最长标记版本的证据范围，不能让某组额外截断，或把为适配共同范围而删去必要事实解释为标记效果。标记后的展示长度与原文坐标分开记录；探针不将展示 offset 用作 read_section 入参。
- 结果校验：模型返回 tool calls 时，复用已冻结版本的参数与调用 ID 校验，按实际参数在本地只读执行所支持的工具并记录命中对象；不自动去符号后执行，不追加模型响应。若返回 rag_search/read_section，不因为工具选择不同判错；根据固定可用目录、是否有已提供 ID、对象相关性判断。不允许调用已删除的 lookup/query_operators，也不新增不存在的 faction 参数。
- 记录：回答和工具参数的名称忠实度分别统计（完整规范名、删字/拼接/误改标点、符号污染）；facts_search 对干员、技能、阵营、组合统一接收完整 query，核查 exact/alias/substring/combo 路径与成员范围是否对应当前证据需求。阵营和组合是不同合法集合，不以「少了某成员」直接判名称错误。不调用工具分为有据作答/仍缺证据，不从分母隐去；分别记录逻辑调用、HTTP 尝试、失败/重试、usage 完整性、token、费用和延迟。
- 决策边界：B 的复制改善不能证明类型选择改善；C 的差异属于「符号+类型信息」整体，不归因于符号本身。36 次逻辑调用仅用于初筛，不证明稳定成功率，不以答对率作工程门槛。若提出采用，先明确符号污染、重复取证、额外 token 和证据送达方面的观察，再另行授权生产渲染变更及端到端对照；固定返回探针本身不改变分词/切块/召回。
- 产物：一次性脚本与输入集中在 dev-temp/work/entity-marking-probe/，任务结束、暂缓或交接前清理，不导出试验快照。

### 步骤 5 — 测量口径先定，观测随工程落地

保留 bench/gold.json 和 docs/spec/rag-answer-baseline.md 的事实要求与真源锚点，不以移除技能表为由删减分母。区分小节排序命中、扩展原文实际送达、附带 facts 实际送达与最终回答覆盖；明确过滤后的索引与 gold 解析目录之间的映射，runner/CLI hitrate 的范围配置一致。现有纯 BM25 hitrate 不自动升级为混合工具质量分数，跨粒度结果不直接横比。口径在对照前固定，历史格式与历史结论保留。

- gold 先在完整、未截断的定位目录解析；缺失的真源键仍报错，被策略排除但存在的键计未命中并保留 recall 分母。排序阶段只能把候选内块映射到稳定原键，不能对过滤数组下标直接套旧 gold；whole-file 扩展不抬高纯 BM25 hitrate。precision/nDCG 按原块相关性与全部 gold 定义，不把排除后的可达集合当作全部理想相关集合；输出范围与排除数量，跨策略比较如实标注可达性变化。
- 送达按实际字符区间和 canonical 分别记录，完整小节、部分小节、未送达区分；facts 匹配到干员卡只证明对象可达，必答字段还须核查其条件与完整内容。不要在运行时读取 gold/spec 或按题号记录特殊证据。
- 消费者检查覆盖 tool-executor→agent/trace→runner 的 injected/records/inputs/meta/answers，以及 report、snapshot 导出/读回。沿用旧 chunk ID 字段，新增有类型的范围/卡附带观测；历史字段缺失为不可用。保留旧 hitCount 口径并说明其局限，新增实际证据送达计数，避免 facts-only 成功被报告为没有任何证据。
- 输入固定项除工具配置外还包括 knowledge 与 facts curation 的可读版本基点、提示及 provider 参数；原技能表全部仍在真源，不因过滤而影响 facts 加载。首版默认关闭实体标记，四组工程对照保持相同指令与工具描述；若必须改提示才能表达模式差异，明确列为实验条件差异，不能宣称只改变检索变量。

### 步骤 6 — 对照设计与后续运行承接（主工程完成后另行 exp）

固定 provider 与其他配置，分开比较：现状 / 仅排除技能表 / 排除加原文扩展 / 再加精确词条附带 facts；实体标记作为独立变量单独对照（步骤 4 探针或端到端），避免同时变更而无法归因。文件级 BM25 与新词条登记另作变量。现有 20 题作为诊断/回归集，另设未参与调优的留出题。记录完成率、外部/内部 facts 查询次数、触发及容量未附带比例、预算触顶、实际送达、回答覆盖与实际 usage 费用。不因答错重跑追分，不将答对率设为默认工程门槛。

- **实际做法**：store.ts 新增只读 `entryDictionary`（六类词条与 alias/substring/combo 并集，提供 `categoriesOf`/`isCuratedEntry`），导出 `serializeCard` 与 `serializeResolutionPaths` 供独立 facts_search 与内部附带共用同一措辞；tool-executor.ts 新增 `recognizeEntryTriggers`（入口规则 3–6，整词优先、最长完整词边界、未准入不拆内部短词）与 `buildFactsAttachment`（独立额度 4,000、按触发词出现顺序原子装配、跨词 canonical 去重、未附带给原因）。rag_search 改为原子组装：先算完 RAG 与 facts 全部分支确认最终输出，再更新共享注入列表；附带观测经 `ToolExecutionResult.attachedFacts` → `TraceToolEvent.attachedFacts` 落 trace；`TOOL_SCHEMA_VERSION` 9→10。

- **后果**：hybrid 默认 rag_search 会（首次）加载 facts store 并按入口附带记录卡；RAG 与 facts 任一实际送达非空证据即计一次 success，提示与路径元数据不扣点；工具描述与 knowledge/AGENTS.md 首版不改（保持四组对照同一指令与工具描述），仅 schema 版本递增，`FACTS_RESULT_VERSION` 保持 5。

### 2026-09-11 — 步骤 5：测量口径与观测消费者收敛
- **plan 原文**：保留 gold/spec 事实要求与真源锚点，不以移除技能表为由删减分母；区分小节排序命中、扩展原文送达、附带 facts 送达与回答覆盖；明确过滤后索引与 gold 解析目录映射，runner/CLI hitrate 范围一致；保留旧 hitCount 口径并说明局限，新增实际证据送达计数；消费者检查覆盖 tool-executor→agent/trace→runner 与 report、snapshot；沿用旧 chunk ID 字段，新增有类型的范围/卡附带观测。

- **后果**：CLI `hitrate` 默认在排除技能表的 145 块上排序、以 749 块完整目录解析 gold，输出「定位目录 749｜检索范围 145｜排除 604｜被排除 gold 键 23」；历史 `runHitrate(index, chunks, …)` 调用（缺省 directoryChunks）保持单范围口径。观测消费者未改字段契约，仅收敛标签与范围输出。
