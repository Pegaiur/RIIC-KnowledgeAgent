## 目标

用「加工站、训练室」的小批试点，把「外部语料 → 本库 base 正文」的清洗链路与其配套自动化跑通：先落地一个只读的导入预检工具，辅助人工完成两篇设施机制正文和一篇共享建设升级正文的清洗与落位登记，再记录有效提示、误报漏报、人工步骤与耗时，判断哪些机械查找值得继续自动化。本轮交付范围为三篇正文与可靠的预检工具；共享篇仅承载两设施所需的建设数据，不扩展为全设施建设总表。结论限于内容导入与清洗流程，节省时间和问答收益分别需要相应证据，不能由扫描通过推定。

## 非目标

- 不做三批全量导入、不重核第二、三批清单；这些留在 docs/plan-knowledge-correctness.md，等本计划交付后再另行立项。
- 不搬迁现有 19 篇正文、11 份机械事实真源或现有上游留档；不导入操作编排、布局与用人攻略。存量路径迁移已去目标化，按本地可维护性另行评估；其他新增内容随后续导入批次实施，均不阻塞本批新增落位。
- 不做核查校验类自动化：正文行多重集合核对、spec 证据块锚点校验、跨 git 版本 hitrate 对照、题集外问法的 rag→read 送达探测均按用户决定靠后，不在本计划内。
- 不做模型 A/B 对照、不发起任何付费运行；docs/draft-prose-optimization-workflow.md 的分层验证与判分设计不构成本计划的授权范围，其文档类型与定稿另行收口。
- 不改检索实现、topK、预算、工具契约、prose-links 引用格式与查询 Agent 指令；不调整 gold、spec 与题集。
- 不恢复退役 raw、不做全库事实刷新、不维护重复的完整技能名单、持有者名单与数值表；技能数值及持有、解锁关系以 knowledge/facts 正式输入为准，设施机制的采用依据按步骤 2–3 核对并留存来源。
- 不自动改写或删段，不把对象名称命中视为事实覆盖证明，不扩展为自然语言消歧、事实断言核验或通用清洗框架。
- 不导入上游的 README、meta、external、skill 与系统提示词；顶层 skill/ 是上游新增的检索路由类文档，本计划不采用。
- 不新增哈希/指纹字段，不新增 ADR（除非施工中出现新关系类型或公共契约变化）。

## 架构分析

**内容缺口**：knowledge/base 现有 12 篇机制/物流语料，没有加工站与训练室机制；corpus-manifest 登记 19 篇。上游工作副本（dev-temp/work/corpus-supplement/arknights-base-vault）的 docs/1-基础设定/设施与进驻/加工站机制.md 与训练室机制.md 覆盖了两者的工作方式、心情与速度口径、特殊效果边界，配套的 docs/2-干员技能/释义/减半.md 是训练室「减半」的玩家侧释疑文。三份稿的子节与本库机制文的组织方式接近，适合作为试点切片。

**机械预检与人工判断的边界**：导入前可机械定位术语写法（上游写「精英 2」「精 2」，本库要求精零/精一/精二），并找出与本地技能名、干员标准名重合的候选位置。加工站与训练室稿的「技能作用机制」一节密集罗列技能名，但名称出现不能证明该段数值、条件或关系已由 facts 覆盖，是否采用仍需人工核对。现有 pnpm run check:prose-terms 只扫描 knowledge/base 与 knowledge/guides，是事后门禁，没有导入前入口；若在任务里另抄一份禁词表，两处会漂移。上游自带的 scripts/verify-combination-rosters.mjs 只校验组合成员，不覆盖上述导入预检。

**预期价值与限制**：共用术语表、按行定位候选可以减少重复查找；两篇设施机制正文和共享建设升级篇填补内容缺口并明确单一维护位置。冲突处理、条件保留、来源核实与关联判断仍是人工工作，不能按扫描命中数量估算节省工时，也不能凭本批试点推断后续批次都有同等收益。

**基准已过期**：上游已由 54e92d9 推进到 53cf2f7（137 文件、+7159/−2971）。草案「外部语料对象清单（2026-09-13）」以 54e92d9 为基准，其中第三批点名的 docs/3-组合库/单站组合/制造站组合.md、贸易站组合.md 与 docs/3-组合库/跨设施组合.md 已被删除，多个组合深稿被重写；同时本地语料在 2026-09-17 完成过一轮标题与结构重组（基建总览拆为四节），草案的「本地落位」列对应重组前的章节名。本试点切片的两篇机制稿在上游仍在且改动很小，不受影响；但清单基准必须改为 53cf2f7，其余落位列在后续批次立项时重核。

## 实施方案

### 1. 清洗自动化：外部语料导入预检

- **输入**：外部稿路径（1+ 个）、可选的对照设施名（决定读取 knowledge/facts/技能-<设施>.md）；干员名始终以 knowledge/facts/名册.md 对照。未指定设施时只跳过技能核对，报告明确说明仍核对干员名。
- **输出**：只读预检报告——① 外部稿 1–3 级标题与行号（选材、拆分与落点判断）；② 术语预检，命中本库禁词表（与门禁同表）与「导入期提示」（如「精 2」）；③「命中本地对象，待核对」候选，按源文件列出名称、对象类型、命中行号与该行上下文。报告说明对照范围和字面匹配局限，不使用「facts 已覆盖」作为结论。终端与 --json 表达同一口径，只输出结果、不写盘或修改正文。
- **落位**：scripts/lib/prose-terms.mjs（术语表真源，禁词与导入期提示分列）、scripts/tasks/knowledge/external-corpus-scan.mjs（只读任务）、scripts/tests/tasks/knowledge/external-corpus-scan.test.mjs 与 scripts/tests/prose-terms-check.test.mjs（断言调整）、scripts/INDEX.md（lib 模块表与范例 task 登记）。
- **依赖与实施约束**：本步骤采用 TDD（先写测试观察失败再实现）。原型测试通过不能代替新口径、定位信息与下列边界的验收；实施结果与验证记录写入本计划实施笔记。
- **边界要求**：front matter 只在文件开头识别，正文的普通 `---` 分隔线不得吞掉后续标题；同一位置的长名命中不重复算作其内部短名（如「斩业星熊」不另算「星熊」，短名在别处独立出现时仍可提示）；不按长度无条件排除所有单字名，明确独立出现的 `W` 应能提示，中文单字名等歧义按保守的字面边界处理并说明局限，不承诺自动消歧。名册或指定技能分片缺失时输出中文错误、退出 1，不静默视为无命中；多源文件的定位与上下文各自保留。
- **验收**：按上述边界及候选定位契约先补失败用例，再实现并通过新增与既有定向测试；pnpm run check:prose-terms 行为与改动前一致；node scripts/tooling.mjs list 可见新任务；`node scripts/tooling.mjs run knowledge/external-corpus-scan -- ...` 对三份稿输出报告，并核对文本、JSON 与未指定设施时的对照范围表述。
- **表格与重复输出优化**：按同一源文件的源行合并候选，行号和上下文只送一次；终端与 JSON 均采用该分组，不另保留逐候选重复的上下文副本。上下文保留完整命中行，不固定截取行首 80 字；规则的 Markdown 表格数据行可转为「列名：单元格内容」的表达，保留每个单元格及空值，去掉对齐填充。列数不一致、无法可靠识别或处于代码围栏中的文本保留原行，不猜测列关系。该投影仅用于预检，源文件不变。用长表格行后半段命中、转义竖线、空单元格、代码围栏与多源文件测试验证内容和归属；重跑三份稿核对候选身份、行号、置信标记、术语和大纲保持，字符数与 token 数分开报告。

### 2. 预检外部稿并产出采用清单

- **输入**：工作副本 53cf2f7 的 docs/1-基础设定/设施与进驻/加工站机制.md、训练室机制.md 与 docs/2-干员技能/释义/减半.md。
- **输出**：每份稿的采用段落与落位、术语处理结论、对象候选的人工核对结论，以及不采用的内容与理由（如上游「心情是唯一投入品」与本库同时列原料与加工费的表述冲突）。采用清单与理由写入本计划实施笔记，记录工作副本提交、文件与段落位置，不另建长期台账。
- **共享篇补充核对**：原三份稿的采用清单已完成。新增核对同一提交的 docs/1-基础设定/设施与进驻/罗德岛基建建设.md，仅选加工站、训练室所需的建造前置、升级消耗、电力与建材链边界，使用既有预检工具并人工核对来源和冲突。将原采用清单中的建设数据重新归属到共享篇，保留设施专属解锁与运行限制；在实施笔记追加采用范围和分工，不把原三稿的完成状态当作共享篇已核对，也不扩展原 204 条候选统计的口径。
- **验收**：术语命中项逐条有改写、不采用或误报说明；对象候选按上下文核对身份，再核对拟采用的数值、条件与关系，不以命中或未命中代替覆盖判断。允许保留解释机制必需的技能名、干员名、触发条件、失效条件与必要数值，并标明来源；不复制完整技能表、持有者名单或另养数值表。只有确认替代证据可取得且条件不丢失时，才移除重复事实段落；冲突或未证实内容保留不确定性，不提升为本库已确认规则。

### 3. 落位两篇设施机制正文与共享建设升级篇

- **输入**：步骤 2 的采用清单与 knowledge/base 既有机制文格式（来源行、设施基础表、核心机制、常见边界、事实分工指向）。
- **输出**：新增 knowledge/base/设施/机制-加工站.md、knowledge/base/设施/机制-训练室.md、knowledge/base/通则/机制-设施建造与升级.md。训练室篇合并减半的机制部分；共享篇集中维护两设施的建造前置与升级消耗，并收录解释这些数据必需的电力和建材链边界。设施篇保留工作机制、等级解锁与设施专属限制，建设数值以共享篇为单一维护位置，避免跨篇重复等级消耗表。目录只在实际创建正文时建立，现有平铺篇目可暂时并存；文件名须在整个 manifest 内唯一。
- **正文表达**：短小的数值对照可保留紧凑表格，不为视觉对齐填充大量空格；长说明表、混合多种机制的表格优先整理为带明确对象的小节或条目。改写时把原列名所承载的含义、数值单位、适用条件、例外、空值或未知状态带入相应条目，不能只删除竖线后拼接单元格，也不把空值补成零。一次阅读应能取得完整关系；不逐行机械重复冗长字段，不复制维护表格与散文两份相同事实。类别与歧义两份直出资料保持原格式；本批只规范三篇新正文，不改存量语料或 RAG/read。
- **验收**：正文使用规范术语，主语与设施明确，关系、条件、代价和例外在同一阅读单元内可理解；保留解释必需的对象名与条件，不导入完整技能／持有者名单或培养建议。减半等机制须说明适用对象、触发、兑现与失效时点，不能因去重只剩「参见 facts」。每个采用结论可追到上游稿对应段落或本库 raw 真源，推导公式可复算，来源不足或相互冲突的结论不作确定性表述。

### 4. 登记白名单与关联

- **输入**：三篇新正文。
- **输出**：corpus-manifest.json 由 19 篇增至 22 篇（base 12→15、guides 仍为 7）；gold 定位文件由 30 增至 33（仍含 11 份机械事实真源）。逐节按「解释是否依赖精确技能或概念事实」判断 prose-links 标注，沿用格式 v2。需要补足精确依据的减半、武道等段落按实际内容登记，skill 优先于宽 operator；没有组合对象不等于没有事实依赖，无需关联的段落可保持空关联并在采用清单中说明理由。关键词目录与标签仅在其真实输入或依赖变化时同步，新增子目录不自动产生新标签或查询分类。
- **验收**：node dist/cli.js validate 与既有关联检查通过，人工核对引用对象与正文用途匹配；检索块（当前 128）与定位块（当前 749）的变化数如实记录，并同步既有文件数／块数测试预期，不改 gold、spec 与题集。正文必要事实保留来源且没有独立维护的完整数值表，不能以删除必要条件来满足去重。

### 5. 链路验证与流程演练记录

- **输入**：本分支全部改动。
- **输出**：门禁顺序的检查结果；在既有实施笔记中按稿记录术语与对象候选的有效提示、误报及人工发现的漏报，给出必要例子与来源位置。记录选材、来源核对、改写、关联判断、复核等人工步骤及实际耗时（未计时则标未记录，不补造），指出工具减少了哪些查找、哪些工作仍需人工及未解决项。候选总量不等于有效提示量，已知漏报不等于完整召回率。
- **验收**：pnpm run check:prose-terms、pnpm run check:reference-projection、pnpm run typecheck、pnpm run test、pnpm run build 与 node dist/cli.js validate 全部通过；演练记录具体、可核查。无人工基准时只报告本次耗时和局部帮助，不宣称节省比例；不以扫描通过或内容入库推断问答质量提升，不设正确率或节时达标线。
- **收束**：先完成三篇正文与可靠预检工具，再从实际断点提出下一步候选（如本地落位对照），不在本轮扩建框架；多文件输入已属步骤 1，不再当作未交付的后续能力。存量目录迁移按 docs/plan-knowledge-correctness.md 的独立评估另行处置，本计划验收不等待迁移完成。临时产物按 scripts/INDEX.md 处理，保留物须有具体后续用途。

- **输出**：docs/plan-knowledge-correctness.md 更新工作副本 pin 为 53cf2f7、记录清单失效范围（第三批对象被删/重写）、指向本计划、登记工具交接与后续批次顺序建议；docs/inbox.md 的「语料补充与整理」条目补记路由。
