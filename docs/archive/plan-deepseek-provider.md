# DeepSeek 追加试验 provider 适配计划

> 创建日期：2026-09-09
> 状态：已完成

## 目标

支持用户指定 DeepSeek 型号的显式 off 调用与缓存计量，服务[追加试验](exp/exp-deepseek-capability.md)。

## 非目标

不改 Agent loop、检索、语料、评分、默认模型；不扩展图片输入或思考历史协议。

## 架构分析

沿用现有兼容接口；只需注册官方型号、支持缓存字段与 CLI 入口。当前消息历史不回传思考，DeepSeek 暂仅开放本次已授权的 off 模式，避免宣称支持未经验证的思考工具协议。

## 实施方案

注册 DeepSeek 官方端点与 secret/env 映射，显式 disabled 并拒绝未支持模式；兼容官方缓存命中字段，保留未知分项。注册高峰价为保守计价，试验单独核算分时实际估算。协议/计量回归通过后构建、dry，再由 exp 预检与主试验验证。

# 实施笔记：DeepSeek provider

> 对应 spec：[适配计划](plan-deepseek-provider.md)
> 开始日期：2026-09-09

## 决策偏离

沿用用户同配置要求，DeepSeek 显式 off；GLM low 为上一轮特例不推广。价格注册使用高峰价上界，exp 根据请求时间另核算空闲/高峰估算；不为此引入通用分时计价引擎。

## 实现调整

已注册 provider 并兼容 prompt_cache_hit_tokens；显式无效嵌套缓存值不被兜底掩盖。类型检查、355 项测试、构建、DeepSeek dry 通过，未修改查询消息历史。

## 债务记录

无新增。思考模式不在本轮支持范围，明确拒绝。

## 意外发现

官方接口缓存字段不同且采用分时价格，不能将缓存当0或套用其他模型单价。

## 阻塞与解决

提交复审按官方契约发现 DeepSeek 缓存命中/未命中为必需分项，不能沿用其他接口可省略为零的语义。解析器现按 provider 校验两分项、输入总量及嵌套缓存值的一致性，缺失或无效时费用不完整；完全未取得 usage 的缓存分项统一为 null。补充解析与 callLLM/HTTP 台账/总费用贯通回归，并保留其他 provider 有效 usage 中可省略缓存字段的原契约。历史试验独立检查过所有缓存分项，运行结果不变。

已完成两会话预检与 60 次正式会话；全部 180 次 HTTP 成功，未发生协议或用量阻塞。空闲时段总估算 0.7045248 元；runner 仍以高峰价格保守估算，差异已在[试验](exp/exp-deepseek-capability.md)明确。本轮结束前核验 121 个冻结文件无漂移；运行完成后仅去掉 CLI 文件末尾多余空行。工程验收完成，计划随未来发版工作流归档，本次不提交或合并。
