# 回答核查基线校正评估

> 日期：2026-09-08；状态：独立审查完成，答案口径已落实为 spec v4。下文初评保留用于追溯，最终取舍以文末“独立审查与v4定稿”及正式 spec 为准。
>
> 核查对象：`docs/spec/rag-answer-baseline.md` v3、`bench/questions.json`、`bench/gold.json`、manifest 白名单内对应 base / guides / references。
>
> 评估起点：仓库提交 `b008f80c00c05097856921da946fe344bcaed600`，开始时工作区干净。本报告只评估本地知识库快照的一致性和可判定性，没有重新核验游戏最新版本或上游数据。

## 结论

**需要校正。现有 spec 可作为核查提纲，但还不足以作为稳定、可重复判分的答案基线。** 20 题的主题和大部分核心方向可以保留，无需先推倒重建题集。最明确的事实错误是 F03 把订单获取效率公式写成订单处理效率；更普遍的问题是必答要点缺少数值和条件、建议阵容与机械触发门槛混写，以及答案要求与证据范围不闭合。

本轮不调整运行时提示、工具、检索、预算或 agent loop，不调用付费模型，不修改题集、gold 或 spec。下文给出可直接用于修订的内容，并区分确定性纠错与需定稿的判定设计。原历史核查的撤回汇总继续保持撤回，本次没有完成 40 份历史回答重评。

## 已确认的主要问题

### 1. F03 有直接影响判分的字段错误

v3 必须项写“普通订单处理效率按基础 `100% + X + Y` 理解”。[贸易站机制](../../knowledge/base/机制-贸易站.md#订单上限与订单获取效率)明确将其用于**订单获取效率**，每名工作干员提供 +1%，后勤技能提供 Y；订单处理时间是按订单类型与对应规则读取的另一指标。

建议替换成：

> 区分订单上限、订单获取效率和订单处理时间。普通订单获取效率为 `100% + n × 1% + Y`，n 为实际工作干员数，Y 为适用技能的订单获取效率；订单上限另行结算，只有技能明确读取上限时才发生转化。处理时间与订单类型按对应规则说明，不把上述公式命名为订单处理效率。

同时替换 F03 陷阱中的“订单处理效率”用词。[历史核查](review-facts-single-query-answer-quality.md)F03 行曾因 A 将公式放在获取段而提出负面评价，这一理由必须撤回；该行另有策略时点等遗漏，不能仅据术语纠正就判整题完整。应复读原答后重新裁定。

### 2. “必须覆盖”存在无法直接判定的占位表述

例如 F02 的“心情消耗按当前有效工作模型处理”、F06 的“具体数值以 base 为准”、S02 的“按其当前练度字段和效果回答”，给出了找资料的方法，没有给出核查答案所需的具体命题。审阅者可以接受泛泛而谈，也可以自行添加更严格条件，二者都难以从 spec 排除。

确定可补入的事实包括：

- **F02**：[制造站机制](../../knowledge/base/机制-制造站.md#生产力与心情消耗)明确每名工作干员 +1% 生产力；心情计量表为 `1-X-Y`，1/2/3 人对应 X 为 0/0.05/0.1，计量表未包含自身技能造成的变化。生产力和心情公式中的 X、Y 不是同一变量。容量不自动转效率，但不能禁止技能明确声明的容量转化。
- **F06**：[控制中枢机制](../../knowledge/base/机制-控制中枢.md#全局心情减免与作用范围)明确中枢工作干员每人减免 0.05 点/小时，人数项与技能分开；目标范围不包括中枢自身和加工站等瞬间结算设施。不能只要求“符合范围”而不列范围。
- **S02**：[中枢技能](../../knowledge/references/技能-控制中枢.md)确认火龙S黑角初始每名中枢小队成员提供木天蓼 +2，精二与小队成员同驻工作时贸易 +7%（同种取最高）；麒麟R夜刀初始木天蓼 +8、自身消耗 +0.5，精二同驻条件下制造 +2%（同种取最高）。[贸易技能](../../knowledge/references/技能-贸易站.md)确认调查团初始为效率 +5%、上限 +2、每木天蓼效率 +3%；[制造技能](../../knowledge/references/技能-制造站.md)为等级 30 解锁、容量 +8、生产力 +5%、每木天蓼生产力 +1%。调查团是一个干员实体，贸易/制造为不同进驻选择。原文只声明资源量被技能读取，不能将 spec 的“来源和消耗”解释成木天蓼必然按次扣除。
- **G01**：[散件指南](../../knowledge/guides/高效率散件.md#条件型贸易散件)与贸易技能均明确：吉星精二需另两名工作干员，伺夜精二需三级**会客室**，空弦精二需总宿舍等级 20。v3 用“办公室/宿舍等级”概括前三人的条件，至少应将办公室纠正为会客室。

哪些数值必须答、哪些是可选细节，需要在修订版明确一次，不能留给每次核查临时决定。

### 3. 计算模型漏掉适用前提，允许补充与必答边界也不稳定

[工休机制](../../knowledge/base/机制-心情与工休.md#单人工休模型)明确 `24/x`、`24/y` 适用于 `x>0`、`y>0`、速率不变及满心情工作/零心情恢复的假设；当前心情 m 应用 `m/x`，`x≤0` 时不能除以 x。v3 F07/F08 没有把这些边界写入可逐项检查的要点。

F07 已要求工休公式，却把单人工休模型列为允许补充；F08 问“计算方法”，必须项又只笼统要求“推导周期比例”。建议将 F07 聚焦实际净消耗与实际宿舍恢复的衔接，F08 固定检查窗口、周期和容量的计算方法；若保留 F07 的公式必答要求，就必须同步补其证据范围。此处涉及覆盖口径，不能借减少要求提高历史成绩。

类似问题还包括 F04 未明确“基础计时”是否必须给出 20 小时，F05/G02 未明确普通四人名单是必须列全还是举例即可。G02 在陷阱中把“遗漏单席位”列为错误，却未在必须项列出单席位。

### 4. 组合建议、技能事实和未知结论需要分开

- **推荐完整阵容不等于机械最低触发条件**：[制造站指南](../../knowledge/guides/制造站组合.md#红松林骑士组)推荐双中枢与至少两名精二制造成员；references 中焰尾精二是按每名制造侧红松骑士团干员产生 +10% 作战记录/-10% 贵金属效果，薇薇安娜精二按每名制造侧骑士 +7%。缺少推荐成员影响完整形态，不能据此声称任何局部技能都不生效。S01/S03/S04/S05/S07/S08 应明确回答的是推荐方案还是机械门槛。
- **S06 设施分工过宽**：v3 写“琴柳/夕及其他成员在控制中枢或宿舍”，容易允许夕进宿舍继续供给中枢技能。[跨设施指南](../../knowledge/guides/跨设施组合.md#感知信息组)明确琴柳中枢或宿舍、夕中枢、令中枢、爱丽丝/车尔尼/塑心宿舍；必须逐人列位置，效果只在实际设施与技能条件下成立。
- **不宜将有条件数值一律视为编造**：[类别规则](../../knowledge/references/类别.md)已有两个“特殊加成”条目，分别写深海猎人制造侧计数的 5%/45% 和 10%/90% 规则。S03 禁止无条件固定效率是合理的，但不能扩展为“当前库没有任何效率数字”。这两个同名条目与具体技能档位的对应、计数范围仍须核清，不能仅按排列顺序绑定 α/β。应分别标注原文已知值、条件推导、待核验映射。
- **名称规范与事实错误分开记录**：S03/S04/S06/S08 的旧名禁用要求反映当前 guide 的命名约定；清楚说明是旧称或同义解释且未混淆实体，不应与错误成员、错误设施判成同一类事实错误。名称规范可以单列检查。

### 5. spec 与 gold 结构对齐，不代表证据覆盖充分

20 题 spec 的“证据块”列表与 gold 当前逐题一致，现有完整性测试通过。但[完整性检查实现](../../bench/src/benchmark-integrity.ts)只确认题号、白名单及 gold 锚点有效等结构条件，不验证必须项是否由这些块支持。

具体缺口：

- **F07** 必答公式来自 `base/机制-心情与工休.md#单人工休模型`，该块不在 F07 gold 中。
- **F01** 把“达到上限停止充能”列为陷阱，依据在 `#充能上限与工作状态`，不在当前 gold 的 `#无人机充能速度` 中。
- **F02** 容量区别在当前 gold 块中未直接说明完整含义，需关联 `#仓库容量与制造流程` 或后勤结算的字段区分；不能仅因该题已命中生产力公式块，就推断所有答案要求均已送达。
- **S05** 要求第三人选择，但 guide 对制造第三人/发电/中枢配套描述笼统，森蚺技能和必要中枢条件也未全列入当前 gold。应先明确期望回答到什么深度，再补对应证据。
- **S03** 类别的成员表与“规则说明”是不同小节，gold 列的是成员表，不能把规则说明中的数值自动视作该 gold 已覆盖。

[hitrate](../../bench/src/hitrate.ts)按 gold 键计算 recall，按 gold 解析块计算 precision/nDCG。增加 gold 会改变指标口径；guide 与 references 可以提供同一命题的替代证据，扁平列表却没有表达这种替代关系。不能为追求“证据齐全”简单把所有参考文件都加成同等必需的 golden。

建议修订文档时先建立“必答命题 → 最小充分证据/可替代证据”的映射，再决定 gold 的检索标注是否需要独立调整。事实正确、答案覆盖、引用支持和检索命中四项分别判断；gold 外的白名单证据也可以支持正确回答。

以下是对基线的评估，不是对任何一次模型回答的评分。证据位置优先沿用现有 spec 的逐题入口，上文已列出需追加或区分的来源。

## 建议的修订与复核顺序

1. **先修确定性错误与歧义**：F03 字段、G01 会客室条件、S06 逐人设施；补 F02 容量例外和 F07/F08 公式前提。修订版递增版本，注明哪些结论依赖本地快照。
2. **将 20 题必答项拆成可核查命题**：每条只写一个事实或条件，给出实体、设施、练度、数值/关系与证据入口；用“任举一例”或“列全以下对象”消除名单要求歧义。guide 推荐条件单列，不冒充 references 的机械最小门槛。
3. **固定判定规则**：覆盖项记录满足/遗漏，额外陈述另记有证据/冲突/未证实；等价措辞与明确假设下的推导可接受。核心覆盖完整但夹带错误，不判为无错误完整答案。未证实与已证伪分开记录，知识不足时的正确保留也不当事实错误。
4. **审定证据映射后再处理 gold**：区分必需证据、替代证据和仅核查可选扩写的证据；gold 若改变必须说明指标不可直接与旧标注比较。既有完整性检查通过不能替代人工语义核验。
5. **同一修订版重评两份已有完整回答**：逐条保存原答摘录、命题判定和证据位置；有争议行单独复核。先重评所有40份，再汇总，不能只修对某次运行有利的行或复用已撤回总分。此步可利用现有快照，无需为校正规格付费重跑。

完成上述工作后，答案基线才具备“相同答案按相同规则可复判”的基础。是否指定某次运行为正式质量基线仍是另一个结论；这20题适合作为现有回归检查，后续获授权的质量优化还需要未参与调优的问题，不能把题集内改善直接解释为泛化提升。
