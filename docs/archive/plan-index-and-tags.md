# 索引与标签框架计划

> 创建日期：2026-09-13
> 状态：已完成

## 目标

为查询 Agent 提供完整主题关键词目录，明确每个词能查什么、使用哪个入口；确定最小事实对象语义，并在现有 facts 工具内提供标签反查。无需正文关联也能独立用于发现对象。

## 非目标

- 不维护正文→事实的关联元数据，不改变 read_section；相关能力归 docs/plan-prose-linked-knowledge.md。
- 不导入外部语料、重写全部散件或建立完整专题引擎；内容归 docs/draft-corpus-supplement.md。
- 不新增模型工具、图数据库、查询分类器、黑话词典、综合推荐分或全局计算模型。
- 不设置固定基线、全量真源更新等前置工作；本次计划转换不代表功能已经实现，不启动付费试验。

## 架构分析

现有事实包含干员、技能、grant、设施、标签、产物及引用术语，可用于建立索引。来源标签混合设施、功能和职业等维度，不能原样作为统一查询语义。描述相同组也不能直接证明完整效果等价；索引必须保留技能—持有者—解锁—替换关系。

三项工作共用既有 facts 对象读取与展示，不复制卡片系统。本计划负责事实对象含义及检索入口；关联计划负责正文引用格式和展开协议；语料计划负责正文与关联内容的判断。共享对象约定完成后，标签检索与展开能力可以独立实施，分别验收。

## 实施方案

### 外部参考输入

共用上游 [lejciy/arknights-base-vault](https://github.com/lejciy/arknights-base-vault) 的本地工作副本 dev-temp/work/corpus-supplement/arknights-base-vault（本次取得 main 分支提交 `54e92d9`；取得与保留约定见 docs/draft-corpus-supplement.md「外部输入与本地工作副本」）。重点查阅副本中的 docs/3-组合库/标签速查.md 与 docs/2-干员技能/技能等价组.md，借鉴标签组织与分组表达；关键词及标签实际覆盖以本库 knowledge/references 和现有登记为准，不用外部名单替换本地事实或据此认定完整技能等价。

### 1. 先确定共同语义

基于下方关键词盘点及现有事实，明确设施、产物/功能、机制条件、资源/类别/技能组和组合的目录层级。干员和全量技能名继续由精确索引承担；常驻目录覆盖全部已登记主题与类别，条目包含检索词、用途、当前入口及必要范围。

明确干员、技能和持有关系的对象含义，区分对象引用与搜索词：人工明确引用不走别名、子串和同名集合扩展。现有 skill/grant ID 随事实原文变化，不作为不变的跨版本人工锚点承诺。正文引用怎样保存、重建和解析由关联计划定义，复用这里明确的对象语义。

输出为可执行的词义/入口与对象约定，记录在本计划实施笔记；公共接口变更按既有判据先形成 ADR 再改代码。本步骤完成即可供关联计划实施，不等待标签查询、排序或全部语料迁移完成。

### 2. 交付 Agent 关键词目录

从现有事实登记、标签、类别和正文主题取得词条，人工维护规范词与范围说明，生成可随 knowledge/AGENTS.md 一起送达的目录。人工说明和机器汇总各保留一处维护位置；沿用现有指令装配通道，不新增工具或手写第二份长名单。

目录优先列出真实可用的 facts_search/rag_search 入口。标签尚未接通时如实标当前路径；RAG 词有语料不代表已验证召回排名。生成结果不包含本计划的维护过程、统计表说明或未上线能力。验证目录覆盖、生成一致性以及运行时实际送达，不以文件存在代替已注入。

### 3. 实施最小标签反查与事实展示

- 技能标签为源，派生标签→设施→技能→grant→干员；卡级标签去重聚合，同卡多命中保留依据。
- 先使用现有来源标签；规范检索词可不同于原始标签，但映射明确。缺标签不等于没有能力，已有精确/设施入口仍可用。
- 现有 facts 工具增加显式标签入口，保持普通 queries 的精确词条语义；不自动合并同名职业、设施和标签。参数及宽标签送达方式作为本步骤施工契约，编码前结合现有 schema 和实际体积确定并记录。
- 先确定候选，再补目标设施相关技能、替换链与必要术语；补证据不扩大候选。相关技能仍分别展示条件和产物，不自动计算综合收益。
- 描述相同与完整效果等价分开表达；逐项绑定技能名、持有者、解锁和替换。修改派生与展示逻辑，不手改生成文件。
- 首版保留完整卡并前置命中设施技能，按设施与名称稳定排序；不实现综合推荐排序。宽标签不静默 Top-N 或截断卡片，必要分页明确覆盖范围，具体分页契约在本步骤实施前确定。

本步骤用现有事实独立测试，不以办公室/源石专题、外部篇目或全部散件迁移作为验收条件。沿用计量与 trace，标签入口真正可用后同步目录。

### 4. 接受实际语料反馈并收束

docs/draft-corpus-supplement.md 方向的语料补充落地时，数据缺口按既有结构补齐；局部表达不足做最小调整。新增关系类型、标签语义或公共契约变化归本计划对应职责处理，关联协议变化归关联计划；超出已定范围的新需求从 inbox 起步。不因单个特殊机制预建完整图谱，也不要求先完成全部可选扩展才交付。

整体顺序为共同语义 → 用现有正文实现关联展开 → 逐批增加语料 → 按实际需要补齐索引。标签能力可在共同语义明确后与展开独立推进，后续语料无需等全部标签功能完成。三份计划分别定稿、实施和验收；开发中按既有实施笔记记录决策和偏离。

### 实施输入：关键词盘点（2026-09-13）


先给 knowledge/AGENTS.md 配备可用检索词目录：让 Agent 知道有哪些词、各自能查什么、用哪个入口。以下是实施输入盘点；当前尚未注入 Agent 指令，实施时按实际可用入口生成目录。下面分组是词表组织，不执行问题分类，也不新增黑话映射。

范围：完整列出当前 9 个技能设施、44 个不同来源标签（跨设施出现共 45 项）、类别文件 81 条记录对应的 79 个不同名称、19 个已登记组合；补充现有 base/guides 的主题检索词。干员和全部技能名不在常驻目录逐项铺开，继续使用既有精确索引。现有 store 有 425 个干员名称、697 个技能名称入口；名称数不是技能事实数。

入口标记：F 表示当前 facts 的登记匹配类别已核对，可用 facts_search 查相关卡；R 表示 rag_search 的正文/术语检索词，有内容依据但未实跑验证召回排名。read_section 只使用工具实际返回的定位信息。标签本身尚无独立 facts 查询语义；同词碰巧命中职业或设施不能冒充标签查询。当前词表为范围与入口盘点，不承诺全量候选送达。

### 明确引用与搜索词的边界（沿用 ADR-010）

- **自然语言搜索词**：`facts_search` 的 queries 走 exact → alias → 已登记子串 → combo 路径，允许同名全部返回、登记别名与短名扩展，不消歧。
- **人工明确引用**：不走别名、子串或同名集合扩展；必须解析为唯一对象，缺失或歧义显式报告，不猜测迁移。
- 干员明确引用用 `operator:<canonical>`；技能/grant 明确引用用可读坐标（设施 + 技能名 + 持有者 + 解锁/替换），生成期解析到当前 `skill:`/`grant:` id，**不直接以内部 id 作跨版本锚点**。

- 常驻目录层级：设施 → 产物/功能 → 机制条件 → 资源/类别/技能组 → 组合。
- 覆盖全部已登记主题与类别；干员名（425）与技能名（697）不由常驻目录逐项铺开，继续走精确索引。

  - A：生成器放 `bench/src`（可直接读 facts 登记、`类别.md`、`TERM_CURATIONS` 等真源），生成物入库，经 CLI 子命令生成/检查；注入点扩展现有 `loadKnowledgeAgentInstructions`。
  - B：生成器放 `scripts/tasks/knowledge`，从 knowledge markdown 反推真源（组合名从 guides 标题取）。
- **决策**：选 A。理由：组合等真源在 TS（`bench/src/facts/curation/terms.ts`），scripts 与 bench/src 存在既有的分层/构建约定（间接依据见 scripts/tasks/bench/facts-evidence-observation.mjs 的 R5-10 债务注解、以及 update-reference-projection.mjs 自行重复声明设施而非 import），B 会造成真源漂移；A 可复用既有 curation 作为人工维护位置，生成物与真源在同一构建内保证一致。
- **影响**：新增 `bench/src` 目录生成模块与 CLI 子命令；新增门禁步骤（生成物一致性）；运行时 system prompt 增加目录段，`agentInstructionsSha256` 随内容变化。

### 2026-09-13 — 人工说明与机器汇总的维护位置

- **背景**：plan 要求「人工说明和机器汇总各保留一处维护位置」「不高手写第二份长名单」。
- **选项**：
  - A：人工说明单独一份 Markdown；B：人工说明进入 bench curation（与既有 `curation/*.ts` 同构）。
- **决策**：选 B。人工维护「规范词、范围说明、入口」等无法机器推导的部分，落在 `bench/src/facts/curation/` 下的说明模块；机器汇总（设施/标签/类别/组合的枚举与入口）由生成器从真源取得。两处职责不重叠。
- **影响**：新增 curation 说明模块；生成物只由生成器产出，禁止手改。

### 2026-09-13 — 标签反查入口协议（步骤 3 施工契约）

- **背景**：plan 要求「现有 facts 工具增加显式标签入口，保持普通 queries 的精确词条语义；不自动合并同名职业、设施和标签」，并把参数与宽标签送达方式留待本步骤编码前确定。
- **选项**：
  - A：复用 `queries`，靠同名类别自动识别为标签；B：新增独立可选参数 `tags`。
- **决策**：选 B。`facts_search` 增加可选 `tags` 字符串数组；`queries` 语义完全不变；同名职业/设施/标签不自动合并——走 `tags` 只返回标签派生结果，走 `queries` 只按六类精确词条/别名/子串/组合。派生链为 标签 → 设施 → 技能 → grant → 干员，卡级按 canonical 去重聚合，同卡多命中保留各命中依据。
- **影响**：facts_search schema 与结果协议版本递增；需按判据建立 ADR；`queries` 与 `tags` 至少提供其一。新增 ADR 必须显式界定本入口对既有条款的局部替代范围：ADR-015「不再保留单字符串入参或第二字段」与 ADR-010 §5「不新增参数」原为精简精确词条入口而设，本标签入口是 plan 明确要求的不同语义入口，需在 ADR 中说明其边界（仅标签派生，不改变 `queries` 精确词条语义、不自动合并同名职业/设施/标签）。

### 2026-09-13 — 宽标签分页契约（步骤 3 施工契约）

- **背景**：plan 要求「宽标签不静默 Top-N 或截断卡片，必要分页明确覆盖范围，具体分页契约在本步骤实施前确定」。
- **决策**：标签结果不做静默截断。新增可选 `offset`（非负整数，默认 0）与页大小上限；返回元数据给出命中总数、本页返回数、`next_offset` 与 `complete`；每张卡保持完整。**页大小取 20 张记录卡（`FACTS_TAG_PAGE_CARDS`）**，作为固定常量不单独配置：按真实来源标签复核，44 个标签中最大命中为「订单效率」73 张、共 12 个标签超过 20 张，取 20 既限制单次结果体积，又能用 `offset` 覆盖全部命中。
- **影响**：标签入口需携带分页元数据；不改变 queries 路径（queries 仍一次完整返回）。

### 2026-09-18 — 关键词目录交付的收束判断（暂不投入压缩，方向保留）

- **背景**：第 2 步交付的常驻目录在 2026-09-14 的两轮压缩中均未复测费用与质量，用户判断该压缩与目录当前的表现都不好、收益未被证明。
- **决策**：暂不投入压缩与目录形态优化；承载两轮压缩及相关过程文档的暂存改动于 2026-09-18 删除，不恢复。但不否定该方向：生成器、人工说明、生成物与默认关闭的开关按现状保留，标签反查入口（ADR-019）不受影响。
- **影响**：本计划第 2 步交付以其原始形态（未压缩、默认不注入）成立，验收清单相应条目不变；「关键词目录重复文本过多」不再是待办方向，改记为「目录注入收益未证明、暂不投入（方向保留）」，详见本文债务记录。入口盘点与生成一致性测试仍有实践价值，可作后续重启的起点。
