# 标题上下文与按小节读取优化计划

> 创建日期：2026-09-08
> 状态：已完成
> 需求入口：[inbox](../inbox.md)

## 目标

让查询 Agent 在搜索定位后，能识别片段所在的文档层级，并按证据缺口读取指定小节。首轮交付标题上下文、小节导航和 `read_section` 工具，不把历史报告审定作为开发前置。

## 非目标

不改变 BM25 分词、排序、topK、现有切块与 chunk ID；不重写知识事实，不调预算或模型，不加向量库、reranker、强制多阶段流程或二次审核模型。回答格式优化另行处理。本次先提交设计文档，不启动实现或付费运行。

## 架构分析

现有 `corpus.ts` 按 H2/H3 切块，`clampTexts` 对长块保留首尾；H4–H6 可能留在块正文中。`rag_search` 返回文件、当前标题、行号和正文，缺少完整祖先层级和可直接读取的小节标识。`facts_search` 只接受精确词条，不能代替机制文档阅读。

因此不能把现有 chunk 当作完整章节，也不应为新增阅读能力改变检索切块。新增小节目录从同一语料 manifest 的原文建立，记录 H1–H6 的层级和行区间；搜索仍使用旧 chunks/index，展示层按来源行映射小节。复用既有预算、执行器、trace 和 inputs 记录，不再建设一套观测系统。

## 实施方案

### 1. 从白名单原文建立小节目录

在 corpus 模块或相邻 `sections.ts` 中建立运行级只读目录，复用 manifest 的文件解析和路径检查。每个文档仅在本次运行加载时读取；搜索、展示和阅读使用同一批原文快照，执行工具时不从任意路径重新读盘。

每个小节包含 `sectionId`、文件相对路径、原文标题、标题层级、祖先标题、标题/正文起止行、原文正文。范围从标题后到下一个同级或更高级标题前，包含下级小节；无标题文档提供文档根节点。标题识别忽略 frontmatter 与 fenced code 内伪标题。同名标题按文档出现序号区分。

ID 采用相对文件路径＋完整标题路径＋同路径出现序号的确定性编码；实现时固定一种编码并复用，用户和模型只复制工具返回的 ID。它在同一内容版本下稳定，不承诺文档改标题或重排后的跨版本稳定性；不替换现有 chunk ID。目录按原文顺序保留。

### 2. 在 RAG 结果中增加上下文与导航

仅对暴露阅读能力的模式（bm25、hybrid、both）增强 `rag_search`：每个命中片段显示 sectionId、完整祖先标题路径、既有来源行号和正文。grep_search 的结果格式本轮保持原样；both 中仍可由 rag_search 获得阅读入口。事实卡格式保持原样。

上下文采用可机械解释的规则：展示 H1→当前标题；另附最近父级从标题结束到第一个子标题前的引导正文，最多300字符。只取真实原文，不生成“适用产物/组合类型”等解释；若没有父级引导正文则省略。引导正文单独标明来源行和省略状态，不混成命中正文。

每个命中文档附一次小节导航，优先列命中小节的直接兄弟与子小节，去重后按原文顺序最多8项，每项仅ID和标题；超出时明确省略数量。本轮不做完整目录分页。

展示仍受 maxContextChars 的总文本上限约束：先容纳既有命中正文，再利用剩余空间依次放标题路径、父级引导和导航；空间不足可不附加，不挤掉原本能送达的命中正文。来源头计入长度，末项可截断并标明截断；以最终组装的真实内容同步 injectedIds，不能将目录或父级引导误记成新的完整命中块。父级引导仅在 writtenContent 中保留来源，不混入既有 chunk 覆盖计数。搜索排序不受展示字段影响。

### 3. 增加独立函数 read_section

输入为 `{ "section_id": "工具返回的ID", "offset": 0 }`：section_id 必填非空字符串，offset 可选、默认为0的非负整数，额外字段拒绝。offset 是该小节正文 JavaScript 字符串的 UTF-16 索引，不是文件行号；模型通过 next_offset 续读，无需自行计算。

每次读取原文小节的一页，正文最多6000字符，同时服从 maxContextChars 对工具 data 的上限；标题/来源及分页元数据占用的长度须先扣除，必要时在行边界缩短。输出沿用工具 envelope，并在 data 中以固定格式给出 sectionId、标题路径、实际行范围、offset、next_offset（读完为null）、complete 和原文文本。原文保留标题与条件，不做摘要；不得静默跳过长小节中段。offset 等于正文长度返回成功、空正文、complete=true；大于长度返回 invalid_params。

合法但目录中不存在的 ID 返回 empty，说明本运行没有该小节，不回退为模糊搜索；参数非法返回 invalid_params。只访问加载目录的 ID，不接收文件路径或任意文件读取请求。每次准入调用包括续页占1点，共用现有每题5点预算、call ID 和超额拒绝语义；不强制模型调用。

工具在 bm25、hybrid、both 暴露，facts 和 grep 模式不暴露。`TOOL_SCHEMA_VERSION` 由5递增至6；更新 ToolId、工具列表、参数校验、执行路由、trace/report 的工具识别以及 inputs 中实际 schema 的捕获。保留旧 schema/旧工具名称快照可读，facts 结果版本不变。

read_section 不参与检索 hitrate；其结果的 hitIds/injectedIds 不伪装成 chunk ID，使用空数组，状态与执行计数按实际阅读记录。阅读送达证据由 trace 的 sectionId/行范围/正文及 complete 定位，report 增加或复用按工具调用统计即可，不增造新的质量指标。若现有命中统计按 hitIds 判定，须明确阅读操作不进入搜索命中率分母，避免成功读取被当作搜索未命中。

### 4. 接入运行和简短决策指令

runner 为使用阅读能力的模式加载目录并传给执行器；直接 runQuery 的调用方可通过可选 context 接入，测试 fixture 显式提供目录。无目录时 read_section 明确返回本运行无对应小节，不能偷偷加载另一份语料。既有无阅读场景保持兼容。

现有 inputs 增加可选的小节源内容指纹与目录版本，指纹覆盖本次阅读能返回的原文，不仅覆盖被 clamp 的 chunks；不保存一份新的全库副本，不改变旧字段含义。工具 trace 沿用现有 writtenContent 记录分页状态和正文。

`knowledge/AGENTS.md` 仅补一条取证决策：已定位文档且缺某个条件/边界时，可按导航 read_section；缺具体对象事实时继续 facts_search；证据已足够直接作答。不要重复完整工具参数说明，也不要求每题先搜索再阅读或至少使用几次工具。

### 5. 有限验证与交付

测试集中覆盖四组实际契约，不另建大量微小断言：

1. 层级与目录：重复标题、代码块内伪标题、父级引导、无标题文档及现有 chunk/排序不变。
2. 展示与阅读：同一来源快照、长节连续分页无中段丢失、预算内真实送达、未知ID/非法offset，以及阅读与搜索命中统计分开。
3. 工具集成：三个开放模式、两个关闭模式、共享预算/同批调用与 trace 来源一致、旧快照可读。
4. 离线使用样例：选择4个开发问题覆盖“已有证据足够”“同文档缺一小节”“长小节续读”“具体词条仍走facts”；通过现有 executor 模拟搜索和阅读，核对新增证据及字符量，不调用模型、不按题号写运行时分支。

实现收束时运行一次 typecheck、test、build、hitrate、doc-check 和 diff 检查；修复后只重跑受影响检查，最终内容变更时按提交技能执行必要审查。静态 hitrate 应保持原结果；工具输出允许因新上下文增加字符。观测工具行为和证据可达性即可验收实现，不设回答正确率门槛。

模型是否会正确使用新能力需另做少量端到端实跑；准备好4题当前/新方案的比较配置后再取得真实调用授权，不以实跑未启动阻塞代码交付，也不在本计划中宣称质量提升。已有6题已被分析，不再称为未见测试集；无需为本轮开发重新复核40份历史回答。

实施从本计划创建对应 notes，记录实际接口选择和结果即可；一次性样例放 dev-temp/work/section-navigation，按 scripts/INDEX 收尾。最终更新 inbox 与文档导航。本次计划提交时验收项未勾选是待施工事实，D1 属预期施工提示，不伪勾选、不修改门禁；实施完成后再全部核实通过。

# 实施笔记：标题上下文与按小节读取优化计划

> 对应 spec：docs/plan-section-navigation.md
> 开始日期：2026-09-08

## 决策偏离
> spec 中没有提到，但在实施中做出的重要决策

### 2026-09-08 — 小节 ID 编码采用哈希前缀
- **背景**：spec 要求「相对文件路径＋完整标题路径＋同路径出现序号的确定性编码」，但未规定具体形式；ID 需唯一、可复制、跨运行稳定。
- **选项**：
  - A: 可读路径编码（如 `file::H1 > H2#2`），便于人工识别，但标题含分隔符时存在歧义。
  - B: 哈希编码 `sec-<sha256 前16位>`，无歧义、长度固定，但不可读。
- **决策**：B。输入为 `file\0标题路径\0出现序号`，取 SHA-256 前 16 位十六进制，前缀 `sec-`。测试通过目录返回的 ID 定位，不依赖可读性。
- **影响**：模型与用户只复制工具返回的 ID；ID 不进入 chunk ID 体系，不承诺跨版本稳定。

### 2026-09-08 — 无标题文档根节点的处理边界
- **背景**：spec 要求「无标题文档提供文档根节点」，但未说明有标题文档的前言（首个标题之前的内容）如何归属。
- **选项**：
  - A: 为所有文档建立根节点，前言归入根节点，H1 作为根节点的子节点。
  - B: 仅无标题文档建立根节点；有标题文档前言不进入小节目录（检索仍由 chunk 覆盖）。
- **决策**：B。避免根节点与 H1 同时作为层级起点造成重复，且前言通常为 frontmatter 或引言，不属于「按小节读取」的目标。
- **影响**：有标题文档的前言不进 read_section；现有 chunk 分块不受影响。

### 2026-09-08 — 小节正文统一按 UTF-16 索引分页
- **背景**：spec 规定 offset 为「正文 JavaScript 字符串的 UTF-16 索引」。
- **决策**：分页与续读全部以 `String.length` / `slice` 的 UTF-16 语义实现，不按字节或码点切分。
- **影响**：next_offset 可能落在代理对中间，由模型按返回的 next_offset 续读，无需自行计算。

## 实现调整
> spec 中有描述，但实际实现方式不同

### 2026-09-08 — RAG 展示的字段落位
- **spec 原文**：「每个命中片段显示 sectionId、完整祖先标题路径、既有来源行号和正文」；「先容纳既有命中正文，再利用剩余空间依次放标题路径、父级引导和导航」。
- **实际做法**：来源头保持既有 `【file | heading | Lx-y】`；sectionId、标题路径、父级引导与导航合并为命中正文之后的「【小节上下文】」段，仅使用剩余预算，超限时截断末项并标注 `…（截断）`。injectedIds 只记录真实送达的 chunk，不记录目录或上下文。
- **原因**：标题路径与导航体积可变，按 spec 优先级降为可选，避免挤占正文；sectionId 随上下文段送达，预算不足时不追加（详见下方「验收违约修正」）。
- **后果**：无目录或预算不足时不追加【小节上下文】；来源头始终不含新增字段，正文送达范围与实现前一致。

### 2026-09-08 — read_section 输出格式与越界 offset 语义
- **spec 原文**：`read_section` 在 data 中以固定格式给出 sectionId、标题路径、实际行范围、offset、next_offset、complete 与原文；offset 大于长度返回 invalid_params。
- **实际做法**：data 前三行固定为 `【read_section】{id}`、`标题路径：…`、`行范围：Lx-y｜offset：n｜next_offset：m|null｜complete：bool`，空行后接原文页；分页按 UTF-16 索引，必要时在行边界截断并由 next_offset 续读。越界 offset 归入 invalid_params，`executed=false`（与解析期参数错误一致），但仍已占用 1 点共享预算。
- **原因**：固定文本行便于模型与离线样例解析，也避免 JSON 转义原文；越界属参数问题而非执行结果，按既有 invalid_params 语义处理。
- **后果**：read_section 的 hitIds/injectedIds 恒为空数组，不进入搜索命中统计；`TOOL_SCHEMA_VERSION` 由 5 递增至 6，report 按 `isObservedTool` 计入 read_section 调用次数。

### 2026-09-08 — 运行接入与 inputs 小节指纹
- **spec 原文**：runner 为使用阅读能力的模式加载目录并传给执行器；inputs 增加可选的小节源内容指纹与目录版本，指纹覆盖本次阅读能返回的原文。
- **实际做法**：runner 仅对 bm25/hybrid/both 调用 `buildSectionDirectory`，同一实例同时传给 `runQuery`（执行器上下文）与 `createRunInputs`；`inputs.sections` 记录 `version`、`sectionCount`、`sectionsSha256`（覆盖目录内全部原文，含长节与被 clamp 的 chunk 之外的正文）、`orderPreserved`。grep/facts 不加载目录，inputs 不含 `sections` 字段。
- **原因**：目录与检索共用白名单来源但各自独立读取一次；指纹单独记录，不保存第二份全库副本，也不改变旧字段含义。
- **后果**：`knowledge/AGENTS.md` 增加一条取证决策；旧 inputs/snapshot 缺少 `sections` 仍可读取。

### 2026-09-08 — 导航生成口径与极端预算兜底
- **spec 原文**：每个命中文档附一次小节导航；read_section 服从 maxContextChars 对工具 data 的上限。
- **实际做法**：同一文件多个命中小节时，导航以该文件首个带小节的命中块生成一次（其直接兄弟与子小节）；read_section 在分页元数据无法容纳或剩余正文放不下 1 字符时返回 `status=error`，不静默突破上限（详见下方「验收违约修正」）。
- **原因**：导航是「每文档一次」的有限补充，按首个命中小节即可覆盖该文档层级；分页必须服从 data 上限，不能以放宽上限换续读。
- **后果**：默认 `maxContextChars=12000`、页上限 6000，正常配置不触发；上限过小时模型收到明确错误并可改用其他工具。

### 2026-09-08 — 验收违约修正：正文优先与元数据超限报错
- **spec 原文**：附加信息只用剩余空间，不挤掉原本能送达的命中正文；read_section 同时服从 maxContextChars 对工具 data 的上限。
- **实际做法**：来源头恢复为不含 sectionId 的既有格式；sectionId、标题路径、父级引导、导航全部移入正文之后的「【小节上下文】」，仅在剩余预算内追加。read_section 在分页元数据无法容纳（或剩余正文放不下 1 字符）时返回 `status=error` 并说明 maxContextChars，不再强制返回 1 字符。
- **原因**：首轮验收发现两处违约——sectionId 置于来源头会挤占正文（同一输入、12000 上限下正文由 11965 降至 11942 字）；read_section 在 80 上限下返回 94 字却标为成功。
- **后果**：新增回归断言锁定「截断预算下 data 等于旧基线切片」「元数据超限返回 error」；正文送达范围回到首轮实现前。

### 2026-09-08 — 收束校验记录
- **实际结果**：`pnpm run typecheck`、`pnpm run test`（35 文件 340 例）、`pnpm run build` 全通过；`node dist/cli.js hitrate` 的 recall@3/5/10 = 48.9%/56.2%/64.5%，与实施前一致（检索分词、排序、topK、切块均未改动）；`node scripts/doc-check.mjs` 勾选验收项后无错误；`git diff --check` 无输出。
- **离线样例**：dev-temp/work/section-navigation/offline-sample.mjs 用现有 executor 模拟，无模型调用；4 场景结果——已有证据足够（读 1 页/951 字）、同文档缺一小节（读 1 页/642 字）、长小节续读（干员名册 11343 字/2 页）、具体词条仍走 facts（facts_search success 1 卡；同题另读 16219 字/3 页），全部完整且逐字无损。
- **后果**：验收清单 6 项全部勾选；发版收束时由 `release/archive-plan` 合并本笔记并归档。
