## 按设计契约调整策略（2026-09-07）

后续用户已将方向收敛为 [facts 工具优化](archive/plan-facts-tool-optimization.md)。本节保留为方向演进记录；具体范围、缺陷分级与测试方案以该 facts 计划为入口，不继续展开通用 agent 调整。

用户要求不依赖测试结果评估调整方向。本节依据当前接口和决策契约提出建议，不从某题失败、工具调用比例或费用变化推导修改。之前“效果证据不足”的结论只约束收益声明，不应升级为实现缺陷或要求强行增加 lookup 使用。功能与契约是否成立、性能改善是否已获证明，是两个问题。

**独立工具设计保留**：函数名选择能力、arguments 只传业务参数，消除与业务无关的协议封装；该理由不依赖跑测成绩。固定 auto、共享预算及 call ID 关联与工具拆分正交，无须同时调整。没有充分设计依据提高预算、退回 required、增加强制 facts 调用或固定多阶段工作流。

**优先调整证据路由的表达**：工具是取证手段，不是必须逐个使用的流程。已知精确对象但缺技能事实时用 lookup；需要筛选候选集合时用 query_operators；需要机制或组合关系时用 RAG。问题混合多种证据需求时按缺口继续取证，已有直接、明确的证据足够则回答。RAG 当前也能返回 references 原文，所以不能要求涉及人物就再做一次 lookup。建议将“具体人物优先某工具”收敛为“按尚缺证据及匹配方式选择”，不在宿主硬编码路由或调用次数。

**结果契约优先于更复杂的输入 schema**：当前 facts 零匹配会返回占位文本，executor 又按文本是否为空决定 success/empty；从接口语义上，零命中应该显式为 empty，不能靠模型理解占位文本。候选调整是用实际命中集合生成状态，保留 executed、来源、预算和必要的缺证说明；历史记录不重写。该问题有独立代码依据，不以答题表现为修复前提。本节只提出建议，不顺带修改返回协议。

**取消“单次空结果即终止”的暗示**：当前知识指令第 7 条将空结果、预算耗尽和证据不足并列为直接作答条件。单次精确查询空查只说明本次匹配失败，余额尚有且存在有依据的其他查询路径时可以继续；预算耗尽或确无可查路径时才收束为已有结论与未知项。不得把缺证外推为不存在，也不循环改写同一无依据查询。

**schema 保持小而准确**：保留扁平参数、必填、类型、额外字段限制及分类 anyOf；明确分类多条件为 AND、termQuery 为子串、lookup 为精确匹配及当前索引边界。room/profession 只有在已有权威且封闭的值域可直接复用时才增加 enum；不为名称/阵营塞入大名单，也不添加置信度、计划或自评字段。schema 负责描述可调用能力，本地校验负责执行边界，不能假定服务端强制校验。

**收束指令重复**：knowledge/AGENTS.md 第 5/9 条、第 6/10 条分别重叠；第 3 条又重复 schema 参数说明。建议保留一份短决策契约（领域、取证、事实冲突、数值边界、停止条件），具体参数形状由工具 schema 唯一承载，可用工具与预算由运行能力块生成。保持原有约束含义，不靠持续增加禁止句增强约束。

建议顺序：先明确路由与停止条件，再统一空结果语义，最后做指令去重和必要的 schema 描述校正。采纳依据是职责清晰、语义一致、调用路径可解释；测试仅验证实现未违反这些契约，跑测仅用于描述实际效果，不负责决定设计方向。上述策略调整仍待明确实施任务，不自动启动留出题、重复对照或更多付费调用。
