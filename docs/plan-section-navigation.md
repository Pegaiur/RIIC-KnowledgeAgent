# 标题上下文与按小节读取优化计划

> 创建日期：2026-09-08
> 状态：待实施
> 需求入口：[inbox](inbox.md)

## 目标

让查询 Agent 在搜索定位后，能识别片段所在的文档层级，并按证据缺口读取指定小节。首轮交付标题上下文、小节导航和 `read_section` 工具，不把历史报告审定作为开发前置。

## 非目标

不改变 BM25 分词、排序、topK、现有切块与 chunk ID；不重写知识事实，不调预算或模型，不加向量库、reranker、强制多阶段流程或二次审核模型。回答格式优化另行处理。本次先提交设计文档，不启动实现或付费运行。

## 架构分析

现有 `corpus.ts` 按 H2/H3 切块，`clampTexts` 对长块保留首尾；H4–H6 可能留在块正文中。`rag_search` 返回文件、当前标题、行号和正文，缺少完整祖先层级和可直接读取的小节标识。`facts_search` 只接受精确词条，不能代替机制文档阅读。

因此不能把现有 chunk 当作完整章节，也不应为新增阅读能力改变检索切块。新增小节目录从同一语料 manifest 的原文建立，记录 H1–H6 的层级和行区间；搜索仍使用旧 chunks/index，展示层按来源行映射小节。复用既有预算、执行器、trace 和 inputs 记录，不再建设一套观测系统。

## 实施方案

### 1. 从白名单原文建立小节目录

在 corpus 模块或相邻 `sections.ts` 中建立运行级只读目录，复用 manifest 的文件解析和路径检查。每个文档仅在本次运行加载时读取；搜索、展示和阅读使用同一批原文快照，执行工具时不从任意路径重新读盘。

每个小节包含 `sectionId`、文件相对路径、原文标题、标题层级、祖先标题、标题/正文起止行、原文正文。范围从标题后到下一个同级或更高级标题前，包含下级小节；无标题文档提供文档根节点。标题识别忽略 frontmatter 与 fenced code 内伪标题。同名标题按文档出现序号区分。

ID 采用相对文件路径＋完整标题路径＋同路径出现序号的确定性编码；实现时固定一种编码并复用，用户和模型只复制工具返回的 ID。它在同一内容版本下稳定，不承诺文档改标题或重排后的跨版本稳定性；不替换现有 chunk ID。目录按原文顺序保留。

### 2. 在 RAG 结果中增加上下文与导航

仅对暴露阅读能力的模式（bm25、hybrid、both）增强 `rag_search`：每个命中片段显示 sectionId、完整祖先标题路径、既有来源行号和正文。grep_search 的结果格式本轮保持原样；both 中仍可由 rag_search 获得阅读入口。事实卡格式保持原样。

上下文采用可机械解释的规则：展示 H1→当前标题；另附最近父级从标题结束到第一个子标题前的引导正文，最多300字符。只取真实原文，不生成“适用产物/组合类型”等解释；若没有父级引导正文则省略。引导正文单独标明来源行和省略状态，不混成命中正文。

每个命中文档附一次小节导航，优先列命中小节的直接兄弟与子小节，去重后按原文顺序最多8项，每项仅ID和标题；超出时明确省略数量。本轮不做完整目录分页。

展示仍受 maxContextChars 的总文本上限约束：先容纳既有命中正文，再利用剩余空间依次放标题路径、父级引导和导航；空间不足可不附加，不挤掉原本能送达的命中正文。来源头计入长度，末项可截断并标明截断；以最终组装的真实内容同步 injectedIds，不能将目录或父级引导误记成新的完整命中块。父级引导仅在 writtenContent 中保留来源，不混入既有 chunk 覆盖计数。搜索排序不受展示字段影响。

### 3. 增加独立函数 read_section

输入为 `{ "section_id": "工具返回的ID", "offset": 0 }`：section_id 必填非空字符串，offset 可选、默认为0的非负整数，额外字段拒绝。offset 是该小节正文 JavaScript 字符串的 UTF-16 索引，不是文件行号；模型通过 next_offset 续读，无需自行计算。

每次读取原文小节的一页，正文最多6000字符，同时服从 maxContextChars 对工具 data 的上限；标题/来源及分页元数据占用的长度须先扣除，必要时在行边界缩短。输出沿用工具 envelope，并在 data 中以固定格式给出 sectionId、标题路径、实际行范围、offset、next_offset（读完为null）、complete 和原文文本。原文保留标题与条件，不做摘要；不得静默跳过长小节中段。offset 等于正文长度返回成功、空正文、complete=true；大于长度返回 invalid_params。

合法但目录中不存在的 ID 返回 empty，说明本运行没有该小节，不回退为模糊搜索；参数非法返回 invalid_params。只访问加载目录的 ID，不接收文件路径或任意文件读取请求。每次准入调用包括续页占1点，共用现有每题5点预算、call ID 和超额拒绝语义；不强制模型调用。

工具在 bm25、hybrid、both 暴露，facts 和 grep 模式不暴露。`TOOL_SCHEMA_VERSION` 由5递增至6；更新 ToolId、工具列表、参数校验、执行路由、trace/report 的工具识别以及 inputs 中实际 schema 的捕获。保留旧 schema/旧工具名称快照可读，facts 结果版本不变。

read_section 不参与检索 hitrate；其结果的 hitIds/injectedIds 不伪装成 chunk ID，使用空数组，状态与执行计数按实际阅读记录。阅读送达证据由 trace 的 sectionId/行范围/正文及 complete 定位，report 增加或复用按工具调用统计即可，不增造新的质量指标。若现有命中统计按 hitIds 判定，须明确阅读操作不进入搜索命中率分母，避免成功读取被当作搜索未命中。

### 4. 接入运行和简短决策指令

runner 为使用阅读能力的模式加载目录并传给执行器；直接 runQuery 的调用方可通过可选 context 接入，测试 fixture 显式提供目录。无目录时 read_section 明确返回本运行无对应小节，不能偷偷加载另一份语料。既有无阅读场景保持兼容。

现有 inputs 增加可选的小节源内容指纹与目录版本，指纹覆盖本次阅读能返回的原文，不仅覆盖被 clamp 的 chunks；不保存一份新的全库副本，不改变旧字段含义。工具 trace 沿用现有 writtenContent 记录分页状态和正文。

`knowledge/AGENTS.md` 仅补一条取证决策：已定位文档且缺某个条件/边界时，可按导航 read_section；缺具体对象事实时继续 facts_search；证据已足够直接作答。不要重复完整工具参数说明，也不要求每题先搜索再阅读或至少使用几次工具。

### 5. 有限验证与交付

测试集中覆盖四组实际契约，不另建大量微小断言：

1. 层级与目录：重复标题、代码块内伪标题、父级引导、无标题文档及现有 chunk/排序不变。
2. 展示与阅读：同一来源快照、长节连续分页无中段丢失、预算内真实送达、未知ID/非法offset，以及阅读与搜索命中统计分开。
3. 工具集成：三个开放模式、两个关闭模式、共享预算/同批调用与 trace 来源一致、旧快照可读。
4. 离线使用样例：选择4个开发问题覆盖“已有证据足够”“同文档缺一小节”“长小节续读”“具体词条仍走facts”；通过现有 executor 模拟搜索和阅读，核对新增证据及字符量，不调用模型、不按题号写运行时分支。

实现收束时运行一次 typecheck、test、build、hitrate、doc-check 和 diff 检查；修复后只重跑受影响检查，最终内容变更时按提交技能执行必要审查。静态 hitrate 应保持原结果；工具输出允许因新上下文增加字符。观测工具行为和证据可达性即可验收实现，不设回答正确率门槛。

模型是否会正确使用新能力需另做少量端到端实跑；准备好4题当前/新方案的比较配置后再取得真实调用授权，不以实跑未启动阻塞代码交付，也不在本计划中宣称质量提升。已有6题已被分析，不再称为未见测试集；无需为本轮开发重新复核40份历史回答。

实施从本计划创建对应 notes，记录实际接口选择和结果即可；一次性样例放 dev-temp/work/section-navigation，按 scripts/INDEX 收尾。最终更新 inbox 与文档导航。本次计划提交时验收项未勾选是待施工事实，D1 属预期施工提示，不伪勾选、不修改门禁；实施完成后再全部核实通过。
