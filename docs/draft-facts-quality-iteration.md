# facts-first 质量闭环与后续迭代草案

> 创建日期：2026-09-04
> 状态：草案（draft）
> 上游：`docs/archive/plan-hybrid-facts.md`（facts-first 基础设施已收口）
> 前置：`docs/archive/plan-rag-prose-cleaning.md`（先完成 RAG 散文清洗与白名单切换）

## 目标

在确定性记录卡与查询工具基础上，后续逐步补齐事实表达质量、语义备注全量治理和可复核的答案评测；本草案不作为当前基础设施合并的前置条件。散文清洗完成后，对全部已审定 base、guides 及待消费知识入口逐项判定，将适合 facts 的干员/技能局部条件与边界完整纳入 curation，不采用抽样试点。

## 非目标

- 不回滚或扩大当前已合并的 facts-first 运行时边界。
- 不把 dry run、工具链路测试或单次真实冒烟误当作答案质量结论。
- 不在没有明确真源和判定口径前批量填充人工优化内容。
- 不要求每张记录卡都必须有备注；“全量覆盖”是全量审阅并记录纳入或排除结论，只为确有局部语义缺口的对象写入备注。
- 不把完整组合成员表、组合总效率推导、缺员降级路线、培养优先级或体系评价复制到 facts；这些内容继续由 guides/支持文档承载。
- 不让 facts 运行时反向依赖 base、guides 或其他散文；散文仅用于发现候选，最终备注必须能够由 `knowledge/references/` 的原文事实或其确定性关系直接支持，无法从 references 证明的机制判断与组合结论留在支持文档。

## 架构分析

当前记录卡的机械字段、技能事实、持有关系、类别与等价组已经由 `knowledge/references/` 确定性解析并通过全量门禁；人工 curation 批次仍为空，`docs/spec/rag-answer-baseline.md` 也仍是旧散文语料背景下的 v2 基线。后续工作需要先重建判定口径，再把语义修订和真实答案评测分开留痕，避免用工具覆盖率替代答案质量。

现有 `notes` 通道能够表达代偿备注与歧义提示，但批量录入前仍有三个结构性缺口：`GrantCuration.notes` 当前被汇总为无作用域的卡片备注，设施与技能上下文会丢失；`OperatorCuration` 没有与技能/持有关系等价的来源复核约束；记录卡输出存在 1000 字符上限，长备注可能挤占核心技能字段或被静默截断。因此本轮不是把散文原文直接搬入卡片，而是先固定字段归属和预算，再做全量判定与短摘要录入。

## notes 收录边界

- `SkillCuration.notes`：所有持有者共享、且能从对应 references 技能事实直接确认的计算条件和容易误读的作用边界。
- `GrantCuration.notes`：特定干员的解锁、升级、替换与共存关系；输出时必须保留对应技能和设施上下文，不得再并入无作用域的卡片总备注。
- `OperatorCuration.notes`：仅承载跨技能仍成立的身份歧义、同名边界或干员全局提示；依赖具体技能原文的内容不得放在此处。
- 组合内容只收录当前干员的局部角色、成立条件和“组合值不等于单人固定值”等误用警告；完整组合解释与总效率只保留在支持文档。
- 每条备注使用当前玩家侧统一术语，保持可独立理解；不得复制长篇原文或在多名成员卡中重复同一段组合说明。

## 全量覆盖证明

实施时新增机器可读的 `bench/facts-notes-review.json` 作为全量审阅矩阵，并由 facts 静态校验纳入测试。矩阵在开始审阅时冻结输入快照：

- `sourceFiles` 显式列出本轮纳入的全部 base、guides、最终知识入口和其他支持文档，不使用目录隐式放行；每个文件记录内容哈希。
- `sourceSections` 以稳定的 `文件路径#标题块标识` 为键，记录 `include`、`support-only` 或 `no-note`，并在 `include` 时列出目标 facts ID。重复标题由切块器生成的稳定序号消歧。
- `skills`、`grants`、`operators` 分别以全部当前 `skillId`、`grantId`、`operatorId` 为键，记录 `include`、`support-only` 或 `no-note`、理由及关联来源。
- 校验必须拒绝缺项、重复项、孤儿 ID、未登记来源文件、文件哈希漂移和 references ID 集变化；因此后续新增、删除或改名都会触发重新审阅，而不能静默维持“全量覆盖”。

审阅矩阵只证明消费范围和处置结论，不成为 facts 的事实来源；`include` 项仍须绑定对应 references 技能/持有关系或相关事实 ID 的指纹。完整矩阵随版本维护，不以 12+5 题评测代替。

## 实施方案

1. **P0.4 参考要点重制**：以当前可核验的 `knowledge/references/` 为 facts 判定依据，以 base/guides 为机制和组合回答的支持材料，重制 F01-F10/G01-G02 的参考要点和陷阱点；明确每条要点的来源边界，更新 spec 版本并人工终审。
2. **notes 模型收口**：修正 grant 备注的投影归属，保留技能与设施上下文；Skill 备注在前、Grant 备注在后按确定顺序合并并做规范化精确去重，不得互相覆盖。Operator curation 从按设施批次中拆为唯一的全局集合，并通过关联的 references facts ID 与指纹复核。定义单条备注与单卡输出预算：身份及机械技能字段优先于备注，所有审定备注必须完整输出；超过 1000 字符时校验失败并要求缩短备注，不得静默裁掉审定内容。补齐 raw/curated、房间作用域、合并去重、指纹失效和序列化测试。
3. **冻结审阅输入**：在 `bench/facts-notes-review.json` 的 `sourceFiles` 中显式登记散文清洗完成后的全部 base、guides、最终知识入口和本轮批准的其他支持文档，并生成全部文档标题块、技能事实、持有关系和干员卡的待判定项；输入清单经人工确认后开始全量审阅。
4. **语义备注全量判定**：逐项完成审阅矩阵，为每个来源标题块、技能事实、持有关系与干员卡记录 `include`、`support-only` 或 `no-note` 及理由。全量是判定范围，不以凑齐备注数量为目标；12+5 题只用于答案质量评测，不承担覆盖证明。
5. **curation 全量录入**：把所有能够由 references 直接支持、符合收录边界的 `include` 项写入对应 curation；同一组合只在各成员处保留其局部角色和条件，不复制总效率与完整推导。录入时保留 references 指纹、来源定位和修订理由，并逐项人工复核；无法由 references 支持的候选一律标为 `support-only`。
6. **查询/裸查对照**：定义 12 个事实题加 5 个组合题的固定题集，使用同模型、同参数分别运行查询组与无工具裸查组；题集覆盖 notes 的直接返回、房间作用域和组合值误用风险，运行结果、失败项和成本信息落盘。
7. **人工判定与结论**：按重制后的 spec 逐题核查答案，落盘判定表；分别报告工具命中、notes 使用正确性、答案覆盖、错误外推、编造、成本和已知局限，不把结论外推到未测 provider。
8. **v3 规划**：根据核查结论登记 S 类、`minEff` 数值效率、结构化组合模型和 references 再生脚本等后续工作；散文清洗已前置到 `docs/archive/plan-rag-prose-cleaning.md`，不再重复登记；范围稳定后将本草案转为正式 plan。

## 验收清单

- [ ] F/G 参考要点已按当前真源重制，spec 已递进版本并完成人工终审
- [ ] grant 备注已保留对应技能和设施上下文，不再汇总为无作用域的卡片备注
- [ ] operator 备注已有明确的来源复核约束，Skill/Grant 备注继续通过原文指纹快速失败
- [ ] Skill/Grant 备注按确定顺序合并、去重且不互相覆盖；operator curation 只有一个全局归属
- [ ] 单条备注与单卡输出预算已有静态校验，身份、机械技能字段和全部审定备注均不会被静默截断
- [ ] `bench/facts-notes-review.json` 已冻结全部批准来源文件及哈希，并完整枚举来源标题块、技能事实、持有关系和干员卡
- [ ] 全量覆盖校验能拒绝缺项、重复、孤儿、来源漂移和 facts ID 集变化
- [ ] 全部审阅项均已有 `include`、`support-only` 或 `no-note` 结论及理由，纳入与排除结果可复核
- [ ] 所有符合边界且通过真源核对的候选已写入对应 curation，不存在仅因取消试点而遗留的待录入批次
- [ ] canonical lookup 能返回目标备注，`room + termQuery` 只命中对应设施备注且不跨设施串线
- [ ] raw 模式不含人工备注，curated 模式只叠加已审定备注
- [ ] 组合值未被写成单人固定值，完整组合说明、总效率、缺员路线和培养判断未复制进 facts
- [ ] 12+5 题查询/裸查两组运行完成，结果与成本信息已落盘
- [ ] 答案人工判定表已落盘，判定口径和异常项可复核
- [ ] 结论与局限已记录，v3 后续工作已登记
