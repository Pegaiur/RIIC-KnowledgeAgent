# 语料清单重核与缺口补强计划

> 创建日期：2026-09-18
> 状态：施工中
> 范围来源：docs/inbox.md「语料补充与整理」与 docs/draft-corpus-supplement.md 的下一实施切片。本批交付「固定版本清单轻量校准＋怪猎组合一节」；其余批次与存量迁移继续由草案承载。
> 与前一计划的关系：docs/plan-corpus-cleaning-and-pilot.md 已交付外部语料导入预检工具及加工站、训练室、共享建设升级三篇正文。本计划沿用该工具链。
> 修订说明：2026-09-18 — 按用户要求调整批次范围、内容采用边界与校核方式，依据见 docs/plan-corpus-rebase-and-gaps-notes.md；本次修订未实施语料导入。

## 目标

以工作副本 53cf2f7 校准旧采用清单、登记新增候选，在 guides 补齐怪猎组合的设施分工、生效条件与缺人后的剩余效果。清单只提供后续选材入口，本批只审定实际采用的怪猎内容。

## 非目标

- 存量路径迁移与其余内容另行立项；旧释义素材共 16 篇，其中减半已导入，剩余 15 篇仍为候选。上游新增篇目单列候选，不自动纳入本批，也不开展全量事实刷新。
- 不修改清洗预检实现、术语表、检索策略、工具契约、关联格式与查询 Agent 指令；不新增校核框架、断言台账或哈希字段。
- 不改既有散件参考线、名单及关联，不顺带改写其他组合或设施正文。关系与限定语的通用改写仍归 docs/draft-prose-optimization-workflow.md。
- 不复制完整技能表、持有者名单或另养数值表；正文保留解释必需的名称、条件和练度，技能事实以 knowledge/raw 与 facts 为准。
- 不做付费运行、A/B 对照或正式质量基线，不改 gold、spec 与 bench/questions.json；题集只用于诊断缺口，不作为导入答案或措辞的来源。

## 架构分析

**旧清单需要校准，也需补上新增候选**：草案按 54e92d9 核对，当前工作副本为 53cf2f7。旧第三批点名的 16 个文件路径全部仍在，删除的 5 个文件均属原「本轮不新增导入」清单；前一实施笔记将第三批概括为被删失效不准确，但其中多篇内容确有变化。上游还新增了彩虹小队、维什戴尔组、孑释义等对象。目录差异足以登记这些变化；内容采用判断留到相应主题批次，不在本批审定全部 91 篇。

**怪猎是本批优先补齐的明确缺口**：knowledge/guides/类别.md 已有怪物猎人小队成员与木天蓼定义，raw 已有技能事实，但 guides 尚无组合分工、练度与取舍的解释正文。这足以支持本批新增，不据此宣称它是全库唯一缺口，也不以上游 canonical 标记替代本地采用判断。

**采用前须纠正上游的条件混写**：上游把三名成员写成「缺一即关」，本地技能原文却区分初始解锁的木天蓼生成与精二解锁的中枢光环；调查团缺席不等于两名中枢干员的光环失效。完整推荐阵容、单项技能生效与是否值得保留岗位应分开表达。

**校核沿用已有能力**：清洗预检、术语门禁、真实语料关联检查与完整性检查均已具备。采用段落仍需人工核对语义；本批只补一次新节读取核对，不重复前置试点的逐候选统计与耗时评估。上游来源稿按已确认分类新增至 knowledge/raw/upstream，存量留档继续等待独立迁移。

## 实施方案

### 1. 轻量校准清单与登记新增候选

- **输入**：工作副本 dev-temp/work/corpus-supplement/arknights-base-vault（固定 53cf2f7）、草案旧对象清单、本地 knowledge/ 与 manifest。
- **做法**：对上游 docs/ 做一次 54e92d9 → 53cf2f7 的文件级差异核对，记录存在、变更、删除与新增；结合本地目录及标题校准已有落位。同主题可合并记录，仍保留来源路径；原本排除的目录按范围记一条，不逐篇核验。只对本批怪猎稿细读内容差异与采用段落，其余对象的内容变化标为待主题批次核对。
- **输出**：在草案原清单旁补当前版本对照（来源对象／路径现状／本地已有落位或待定／本批采用或后续候选）。新增对象单列候选，含彩虹小队、维什戴尔组、孑释义等，不预先批准导入；不另建长期台账或在 notes 复制整表。历史陈述保留并加更正说明。
- **验收**：旧清单对象有明确去向，新增候选未漏出路由范围；第一批已完成内容、剩余 15 篇旧释义候选与新增素材分开记账。对照注明固定版本，后续同版本直接复用，更新版本时只核对相关差异。

### 2. 上游稿转存与怪物猎人小队的预检、采用清单

- **输入**：工作副本 53cf2f7 的 docs/3-组合库/跨设施体系/怪猎中枢.md；对照知识 knowledge/raw/技能-控制中枢.md、knowledge/raw/技能-贸易站.md、knowledge/raw/技能-制造站.md、knowledge/raw/名册.md。
- **来源留档**：转存为 knowledge/raw/upstream/上游稿-怪猎中枢.md，头注写明上游地址、路径、完整提交号、读取日期及「未做术语统一、未逐条核对事实」。去掉新增头注、统一换行后核对正文一致；未登记 manifest，不进检索与模型阅读目录。
- **预检与采用**：运行 `node scripts/tooling.mjs run knowledge/external-corpus-scan -- --source <怪猎中枢.md> --room 控制中枢 --room 贸易站 --room 制造站`，在实施笔记按主题记录采用段落、落位及改写理由。名称命中只帮助定位，实际采用的关系、条件与练度对照 raw 核对；重复 wikilink、模块编号等按类别统一说明，事实冲突单列依据，不要求逐候选交账。
- **内容边界**：
  - 说明黑角、夜刀在中枢与调查团在贸易站或制造站的完整推荐形态，同时说明缺人后哪些技能仍可生效；不采用「缺一即全部关闭」。
  - 区分木天蓼生成技能的初始解锁、中枢光环的精二解锁及同驻条件；调查团贸易站技能初始可用、制造站技能需 30 级，不把所有用途统一成精二门槛。
  - 木天蓼增益要求生成端与受益端同时在岗，表述为资源数值与技能读取，不写成按小时消耗的库存。调查团两设施岗位互斥，贸易站优先属于结合当班阵容的建议，不写成硬限制或跨产物效率比较结论。
  - 保留夜刀的额外心情代价、光环同种取最高、组合别名与游戏内「怪物猎人小队」集合的区别；必要数值示例连同条件、公式与来源保留，不复制整张技能表。
- **验收**：采用主题能追到上游段落或本地真源；完整阵容、部分生效与推荐取舍分开，已识别冲突有处理结论。来源留档与正文改写分别核对，不由扫描通过推定事实正确。

### 3. 落位正文并同步登记与记账

- **输入**：步骤 2 的采用清单、转存稿与 knowledge/guides/跨设施组合.md。
- **正文落位**：默认在 knowledge/guides/跨设施组合.md 追加一个自包含 H2，说明成员、设施分工、条件、用法与边界。若实际采用内容需要独立篇章，可改为 knowledge/guides/组合/怪猎中枢.md 并登记 manifest，在 notes 记录粒度理由；不为容纳新节迁移既有文件。
- **关联**：prose-links.json 沿用格式 v2 与 section 范围，覆盖正文实际依赖的木天蓼生成、中枢光环和调查团两设施技能；需要的集合与资源定义按 guides/类别.md 的实际标题及 term 定位，避免宽 operator 引用带入无关技能。
- **记账同步**：默认追加小节时文件数保持 22（base 15、guides 7）、定位文件数 33；若拆篇则按实际 manifest 调整，不将这些数量写成固定上限。先依据采用内容确定新增／调整的小节，再核对实测计数并同步 benchmark-integrity.test.ts，文件集合变化时同步 corpus-allowlist.test.ts；机械真源不变，定位文件比 manifest 多 11 份、定位块比检索块多 621 的关系保留。
- **验收**：正文与关联的对象、条件和设施用途相符；现有白名单、关联与完整性检查通过。不因数据更新新增一套重复门禁，文件名仍须在 manifest 内唯一。

### 4. 读取核对、现有门禁与回填

- **输入**：本批正文、关联与计数变更。
- **读取核对**：从现有目录取得新节 ID，离线调用既有 read 路径，确认实际返回正文及所需技能、概念定义；有分页时按返回入口续读。只记录新节定位、取得的证据与发现的问题，不运行 LLM、不设检索名次或回答正确率门槛；此检查不证明问答质量提升。
- **现有门禁**：`pnpm run check:prose-terms`、`pnpm run check:reference-projection`、`pnpm run typecheck`、全套 `pnpm run test`、`pnpm run build`、`node dist/cli.js validate`、`node scripts/doc-check.mjs`。validate 负责完整性，真实关联检查由既有 prose-links 测试承担；调整计数属于数据更新，预期来自批准内容与分块规则，不直接照抄输出。仅当引入新的运行时行为或修复契约缺陷时，按测试约定先写失败用例。
- **记录与回填**：notes 只记录采用决定、冲突处理、读取与门禁结果及未解决项；前置工具已验收，本批不强制重做逐候选有效性统计、漏报率或耗时评估。工具若暴露影响本次采用的具体问题，记录例子并按职责处理。草案回填清单与采用进度，inbox 回填路由状态，不在多处复制完整清单。
- **收束**：按 scripts/INDEX.md 处理本轮临时报告，工作副本保留供后续选材。后续顺序见草案「当前执行顺序」：本批后独立迁移存量路径，再按设施主题合并处理释义与组合增量；其余机制、组合与操作布局分别定范围。本批验收不等待后续批次完成。

## 关联 ADR

- ADR-013 — 检索范围、原文扩展与 RAG 内部 facts 附带契约；新增语料沿用既有白名单与送达边界，不改检索范围定义。
- ADR-020 — 散文小节关联事实的引用、提示与显式展开契约；新增节如需标注沿用既有格式。
- ADR-021 — facts 真源目录归并与事实出口；上游留档转存 raw 不递归消费、不进 RAG。
- ADR-022 — 沿用关联格式 v2、scope 与精确技能／概念引用；对象存在性不替代正文相关性判断。
- 本计划不新建 ADR；若施工中出现新关系类型、标签语义或公共契约变化，按判据另行建立。
