# 面向渐进检索的散文优化工作流草案

> 创建日期：2026-09-17
> 状态：未定稿（范围与方案讨论中）
> 需求入口：docs/inbox.md

## 目标

让人工散文既能在未命中时提供可辨认的标题入口，又能在有限阅读中交付完整、易于正确采用的证据；用分层观测决定每批改写是否值得保留和扩大。

## 非目标

本草案不改检索算法、Agent 指令、工具预算或评分标准，不启动新一轮付费测试，不把答案错误自动转成开发缺陷。机械事实仍以 knowledge/raw/ 为准；guides/类别.md、guides/歧义.md 直出层保持原格式。查询别名、实体消歧和检索策略的改变仍归各自需求。

## 背景与依据

docs/exp/exp-prose-title-expansion.md 记录了 17 篇人工散文的扩大优化：本批修改 15 篇、89 个标题，另拆分总览混合表；default top5 recall 55.3%→52.8%，top10 61.3%→63.0%。在固定的原 20 题 query 下，50 处可检索 gold 位置均在目录中可见；12 条题集外人工选读成功。它们分别说明排序变化和人工可达性，不能代替真实 Agent 的自主选读结果。

docs/exp/exp-title-optimization-20q-answer-check.md 的真实三轮及此次定向复核进一步说明：

- 未命中标题确实可以引导整篇补读；宿舍恢复范围的标题三轮可见，但实际正文只在一轮读入。
- 同一问题可同时出现两种失败：贸易站相关正文在第二轮已到仍漏答，第三轮则未读到对应小节。
- 后勤技能结算三轮整篇已读，仍遗漏资源关系并出现技能归属错接；红松小节已经交付，但推荐人数与每人技能的触发条件仍被混淆。
- 原质量计分有漏判与执行者差异；费用下降伴随缓存比例升高，输入 token 和工具字符却增加。现在不能确认总体质量或上下文效率改善。

由此形成的工作假设是：标题负责辨认入口，分段负责让一次阅读覆盖完整关系，正文负责绑定对象、条件和例外。三者需分别验证。该假设不是已经测得的提升结论。

## 候选方案与评估

| 做法 | 可能收益 | 代价与证据边界 | 当前倾向 |
|---|---|---|---|
| 继续全库加长标题 | 未命中时暴露更多概念 | 已有 top5 下降；聚合标题依然可能不含目标实体；无法处理已送达后的误解 | 不作为下一批默认方向 |
| 重组完整证据单元，并局部改写首段和限定语 | 减少公式与适用条件分离、推荐与机制混淆、相似技能错接 | 尚未验证；需维护事实来源、关联对象及块边界，可能增加单次阅读长度 | 优先做按失败类型选择的小批对照 |
| 增加查询别名、调整检索或指令 | 可能改善实体失配与不补读 | 会同时改变运行策略，无法单独评估散文贡献 | 另行立项，不混入语料批次 |

扩大的对象应是可泛化的失败类型，而非仅按答错题逐句补标准答案。可以跨文档应用同一规则，但一批只检验一类主要假设，保留未改区域作为回归参照。

## 实施方案（候选）

### 1. 先确定断点与稳定证据单位

输入为真实 query、实际返回给模型的文本、readDelivery、facts 结果、最终答案及对应真源。按「对象—关系—条件—例外—来源」列出本批需交付的证据，直接放在本批 exp 正文中；不要用可变标题或 gold 键的数量替代语义覆盖。

每个证据单位检查以下环节，必要时给出短引文和原文范围：

| 环节 | 判定依据 | 失败时优先检查 |
|---|---|---|
| 来源存在 | base/guides 的明确陈述与 raw 的机械事实 | 语料缺口或事实尚未确认；不能由模型答案补事实 |
| 入口可见且可定位 | 实际 query 返回的标题、命中 ID、doc: 入口或 facts 实体入口 | 名称、标题、聚合层级及 query 是否换了实体；必须区分未命中标题与可直接 read 的 ID |
| 目标正文与事实送达 | 命中预览的实际字符范围，或 read 正文/facts 分页及各条事实内容 | 补读选择、范围、分页、关联对象；标题、导航和文件名引用不计正文 |
| 关系正确进入答案 | 答案逐项覆盖对象、条件、例外，且无额外错误 | 首段重点、限定语位置、同名对象区分与跨句错接 |

记录实际采用的取证路径，但不要求每题必须 read：预览或 facts_search 已提供完整证据时，无 read 不属于失败。也不能凭 body_complete=true 宣称证据齐全，它只表示当前请求范围完成，不保证已读其他必需小节或 facts 后续页。

输出是一张断点表，每项允许同时出现多个断点。例如 F03 的不同轮次分别卡在选读与答案采用，不能用一个全局“检索失败”标签覆盖。

### 2. 把散文组织成可独立采用的证据单元

先选覆盖同一失败类型的少量文档，核对真源后再改写。建议每批 2–3 篇；数量是控制变量和审阅成本的建议，不是质量验收线。

**标题**使用规范对象名加机制、关系或适用边界。对象名尽量在前，保留既有核心检索词；标题长度由辨认需求决定，不穷举正文、不机械堆叠同义词。检查它独立出现在目录中时，是否能与相邻小节区分。只有所属文档进入返回目录时，这种优化才有机会发挥作用。

**小节**围绕一项可以正确使用的关系组织。公式应与变量定义、适用条件及影响计算的关键例外相邻；推荐方案与技能最低触发要求明确分层；跨设施关系写清生成者、资源、读取者和作用范围。避免把主规则留在热门命中块，却把必要限定单独放入难以补读的相邻块。

**首段**先说明该节的主要关系和关键限制，再放推导、举例和较长名单。当前 RAG 命中预览通常只显示前 100 字，检查实际截断结果：它应帮助模型决定是否继续读，而不能因限制被截断而呈现为无条件规则。不要求把整个答案挤进预览。

**限定语**紧邻所限定的对象。“同种取最高”“每名”“同驻”“替换”“不包含设施数量”等必须有明确主语；不要用相同排除词将两个不同技能暗示为同一机制。对比关系可使用紧凑表格，例如「对象／读取什么／产生什么／条件与例外」，但保留自然语言解释，不强制全库改成表格。

**依赖与事实**用既有 prose-links、facts 来源及范围精确关联。必要规则若只能经跨篇读取才能闭合，明确依赖对象并验证当前工具能否取到；只写文件名不能当成依赖已经送达。正文重述已确认的关键限制可以作为改写候选，但必须保留来源，避免复制整段、全量 facts 或维护另一份事实真源。

选取阅读范围时兼顾相关性与字符成本：共同父级确实包含全部关系时可以使用；整篇作为可用路径，不把全库整篇读取当作目标。若一个证据单元仍跨分页，需要分别检查正文与 facts 是否完整。

### 3. 改写前固定验证设计

每批先在 inbox 路由，并在 exp 说明基准版本、候选版本、唯一主要假设、修改文件、固定配置、观测指标、题目范围和停止边界。正式实施沿用 docs/archive/plan-prose-title-optimization.md（标题与结构）与 docs/draft-corpus-supplement.md（语料增量）的授权范围，新增范围另行收口；本草案本身不表示后续批次已经实施。

准备三类问题：已知失败用于诊断；相邻但未改的主题用于回归；未参与选文和措辞调整的新问题用于泛化验证。新问题应覆盖新的条件组合或应用情境，单纯替换原题同义词只能验证问法鲁棒性。先确定来源与判定要点，再看候选版本结果，不按结果挑选保留问题。

已有 20 题不能重新宣称为未参与调优集。若新问题结果又用于修改语料，该批问题转为诊断集，后续另选未参与改写的问题。运行时与散文中不写题号特判或评分答案。

标题或分段改变时，维护旧新定位映射与同一语义单位；gold 键合并导致分母变化必须单独报告。不要通过降低必答要求、删除困难问题或只保留成功重跑使指标改善。

### 4. 分层验证，分别回答三个问题

| 层次 | 执行方法 | 主要观测 | 能回答的问题 |
|---|---|---|---|
| 结构与来源检查 | 检查事实依据、术语、定位映射、prose-links、facts 范围与现有完整性检查 | 断链、事实改变、条件丢失、正文/facts 分页 | 改写是否仍满足数据与工具契约 |
| 固定 query 离线对照 | 同一组 query 在基准和候选语料上检索，包含原问与预先选定的真实 Agent 改写 query；人工选读另列 | 默认 top5、辅助 top10、语义证据入口覆盖、人工可达性、读取字符 | 排序与阅读路径发生什么变化 |
| 模型自主对照 | 相同 provider、配置、指令和预算，运行基准与候选；预先限定轮次并交错执行 | 实际 query、入口可见后的补读、完整证据送达、答案覆盖与额外错误、费用与耗时 | Agent 是否会用新结构，以及答案是否受益 |

若下一批开展模型对照，建议把每侧三轮作为诊断起点，采用预先写定的 A/B 交错顺序，报告全部轮次和逐题配对结果；三轮本身不保证统计显著性。需要更强效应估计时另定样本量和不确定性分析，不以“继续跑到改善”为停止规则。

标题、分段、首段或条件表述若同批一起改变，只能报告组合改动的结果。若要归因，另设仅标题、仅结构或仅正文的消融候选；先选择需要回答的问题，再决定是否值得增加运行成本。

机械检查使用 package.json、scripts/INDEX.md 及既有门禁入口：文档变更先运行 node scripts/doc-check.mjs，术语运行 pnpm run check:prose-terms；语料关联与定位检查沿用既有 validate/测试。涉及运行时或测试改动时先读 docs/rules/testing.md 并遵循 TDD；修改测试后执行完整 pnpm run test，不能用定向通过代替。不要为纯文档流程新增镜像测试或新计量基础设施。

### 5. 用同一判定方法区分收益与代价

质量复核先用少量固定正反例校准「明确覆盖」「部分覆盖」「额外断言」边界，再将前后答案隐藏版本、混排审阅。每项留判定、答案短引文、来源与送达状态；无对应文字不能只凭整体印象判满足。逐项结论直接写入 exp 正文，汇总由明细计算，避免另存长期试验附件。

同一执行者也可能有偏差，因此争议项和一部分非争议项宜另行复核；若执行环境未授权独立审查，明确写未经独立复核，不把自动分数当作最终事实。推荐人数与最低触发、初始解锁与精二替换等歧义，先统一解释再汇总全部轮次。

至少并列报告以下指标；每项先写清分母，不能相互替代：

- 固定 query 的默认 top5 命中、title-only 可见和完全不可见的语义证据单位数量；raw 事实不混入散文召回率。
- 实际 Agent query 下的证据入口与最终正文/facts 送达数量；对 title-only 单元单列“可见且需补读”与“随后取得完整正文”的比例，同时报告其他路径取证成功数。
- 已送达单位的答案采用情况、必答项完整覆盖与额外冲突/未证实断言；相同来源多次读取去重后计算覆盖。
- read 次数、正文字符、附带 facts、工具总字符、总输入/缓存输入/输出 token、费用与耗时；正文重复读取和无关范围另作样本分析，不仅看 read 是否成功。

未命中标题补读率只有在基准和候选都采用相同语义单位、可见性定义时才可比较；分母随排序变化时，额外报告全部所需证据的最终送达率。费用变低但输入变多，应同时解释缓存，不称作内容压缩。无显著差异或样本不足时如实写不确定，不把“未发现退化”写成等效证明。

### 6. 按结果决定保留范围并收尾

结构、事实和引用的工程契约必须通过。回答正确率属于观测结果，不预设本项目没有约定的达标分数。对预先提出的机制假设分别作出支持、未支持或证据不足的结论，保留负面题目与全部轮次。

若只改善目录辨认而未改善自主补读，记录这种局部价值，不自动扩大到全库；若已送达后持续混淆，下一批候选转向正文关系和限定语；若工具协议或数据读取违反已有契约，再在授权范围内另立实现修复。是否保留或回退改写应比较观测收益、事实维护负担与阅读成本，不以最好一轮定夺。

每批最终交付为语料及必要定位变更、工程检查结果、exp 中的必要证据和结论。临时文件按 scripts/INDEX.md 核对后用显式清单清理，文内留下足以理解判断的短引文与范围，不承诺清理后的完整重放。

## 待定事项

- 下一批候选可选「公式与限制分离」「推荐与触发混淆」「相似技能错接」中的一类；先按全库同类结构选文，再用新问题验证，不按题号部署补丁。
- 后续验证需要选择基准/候选版本、独立问题及运行轮次；当前只有流程提案，没有启动模型对照或新一轮改写。
- 现有三轮初检总分若要作为质量比较依据，需先完成统一重评。它不阻止采用已确认的 trace 事实设计下一批，也不能代替下一批的受控对照。
