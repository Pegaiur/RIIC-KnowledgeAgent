### 2026-09-18 — 术语表下沉 scripts/lib，门禁与预检共用同一真源

- **选项**：

  - B：把禁词表下沉 scripts/lib/prose-terms.mjs，门禁与预检共同 import。
- **决策**：选 B。lib 约定要求「基础逻辑出现两个真实消费者时下沉」，此处正好满足；同时把「导入期提示」（门禁漏检的带空格写法，如「精 2」）与禁词表并列放在同一文件，避免再出现第二份术语真源。

- **发现**：首轮独立代码审查未放行：列表内四空格缩进围栏的表格被投影、普通围栏内井号文本进入大纲、非法 CLI 参数输出英文堆栈且退出 1。文档批首轮审查通过；本次补记与代码修复后重新审查最终范围。
- **实际做法**：先补回归用例并观察 9 例失败，再补源路径为目录的读取错误用例，观察 10 例失败、24 例通过。大纲与表格共用正文行判定，排除文件头元数据、反引号／波浪号围栏以及四空格或制表符缩进的不确定区域；不能解析的上下文连同缩进保留原行。围栏须同类且长度足够才闭合，闭合后的正文正常识别。非法选项、缺值和位置参数统一中文提示、退出 2；文件读取失败给出中文提示，退出 1。

### 2026-09-18 — 按源行合并候选，表格上下文携带列名

- **plan 原文**：步骤 1 新增表格与重复输出优化；步骤 3 约定两篇新正文按内容选择紧凑数值表或自包含条目。
- **实际做法**：先修改及补充测试，观察定向测试 9 例失败、19 例通过，再修改实现；修复后定向 28 例通过（预检 24、术语门禁 4）。终端每个源行只展示一次完整上下文，候选按类型列出；JSON 改为 `factCandidateGroups: [{ line, context, candidates: [{ name, type, confidence }] }]`，不再发送重复的扁平 `factCandidates` 字段。可靠识别的表格数据行输出「列名：单元格」，去除对齐填充，空单元格标为「（空）」；转义竖线保留，列数异常、不能可靠识别的表格及代码围栏内的行保留原文。该变化限于尚未提交的预检原型输出，仓库内消费者与测试已同步，未改 RAG/read。
- **真实源稿核对**：工作副本仍为 53cf2f7，三份稿与步骤 2 输入相同，同时使用加工站、训练室两份技能分片。候选名称、类型、顺序、行号与置信标记逐项保持；加工站 69 条合为 21 行，训练室 113 条合为 34 行，减半 22 条合为 14 行，共 204 条候选合为 69 个源行。大纲与术语预检结果保持。此前有 66 条候选的 80 字符截断上下文不含命中名称，现为 0 条；这只验证证据展示，不证明候选语义或事实覆盖正确。
- **字符测量**：同一源稿、路径与对照集下，合并文本报告由 18,918 降至 9,221 字符（减少 51.3%）；两空格缩进 JSON 由 50,438 降至 43,793 字符（减少 13.2%）。口径为 JavaScript 字符串长度，文本使用 `renderScan` 返回值、不含 CLI 追加的末尾换行，JSON 含末尾换行。比较同时包含完整上下文恢复、列名补入和去重；未测 token 或模型回答效果。
- **验证与交接**：`pnpm run typecheck`、全套 `pnpm run test`（52 个文件、782 例）、`pnpm run check:prose-terms` 通过；`node scripts/doc-check.mjs` 仍以 1 退出，仅报本活动计划的 8 项未勾选验收（D1），未出现其他文档错误，全批次验收随导入完成后再核对。多源 CLI 测试验证源文件不变，真实上游工作副本仍干净。步骤 1 验收恢复完成；两篇机制正文尚未导入，其表格清洗规则已纳入步骤 3。此次测量通过内联命令完成，未新增临时文件；既有工作副本保留供步骤 2–3 使用。

### 2026-09-18 — 预检任务按修缮后的边界重做为「命中本地对象，待核对」

- **plan 原文**：步骤 1 要求候选按源文件列出名称、对象类型、命中行号与该行上下文；front-matter 只在文件开头识别、正文分隔线不得吞标题；长名命中不重复算其内部短名；不按长度无条件排除单字名（独立出现的 W 应能提示，中文单字名按保守边界处理并说明局限）；名册或指定分片缺失时报中文错误、退出 1；未指定设施时只跳过技能名核对，报告说明仍核对干员名。
- **实际做法**：先按新契约补失败用例（12 例失败）再实现。候选对象改为 `{ name, type, line, confidence, context }`；单字 ASCII 名按 ASCII 词边界匹配、中文单字名要求两侧都不是中日韩字符，两类标 `low` 置信；多字名按位置覆盖抑制其内部短名；front-matter 只认首行 `---`（未闭合时整篇按 front-matter 处理）；名册与分片缺失均抛中文错误、退出 1；`renderScan` 与 `--json` 共用同一段对照范围与局限说明。此前「干员名一律要求长度 ≥ 2」与「已有事实对象（facts 已覆盖，勿抄）」的旧口径作废。
- **原因**：名称字面命中不能证明该段数值、条件与关系已由 facts 覆盖；用长度一刀切会同时漏掉 W 这类单字名，并使报告口径与事实边界不符。
- **后果**：报告改称候选并附行号与上下文，结论仍需人工核对。中文单字名（年、令、夕 等）按保守边界多数不命中，属已知漏报，须在步骤 5 的记录中说明，不得当作完整召回。
