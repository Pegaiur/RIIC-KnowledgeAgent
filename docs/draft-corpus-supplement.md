## 目标

逐批补充机制、技能释义与组合解释，按已交付的关联格式标注必要事实对象。用真实内容检验关键词、标签和展开能力，及时反馈局部不足，不以功能框架不断扩展拖住内容交付。

## 非目标

- 不定义工具协议、索引算法或关联格式；分别归 docs/archive/plan-index-and-tags.md 与 docs/archive/plan-prose-linked-knowledge.md。
- 不开展全量事实刷新，不恢复退役 raw，不整库复制外部材料。
- 不做查询分类、黑话词典、组合命名结构重整、排班求解或综合推荐分。
- 不实施散文断言机械校验，不建立人工数值副本。
- 不承担标题定位与结构优化；该范围归 docs/archive/plan-prose-title-optimization.md（已交付两批，后续批次见 docs/draft-prose-optimization-workflow.md）。

## 背景与依据

本地已吸收部分外部同源 guides 与机制正文；加工站、训练室及配套建设升级正文已由首个试点交付。后续按实际主题缺口补充，正文保留解释与选择依据，必要事实通过既有工具或显式关联取得。

本方向维护正文内容以及「该小节关联谁」的判断；索引计划提供可搜词与事实对象语义；关联计划提供引用格式和展开协议。三者分别验收，语料不因缺少可选标签或图谱抽象而停止。

## 候选方案与评估

### 启动顺序与依赖

先完成 docs/archive/plan-index-and-tags.md 的共同语义，再用 docs/archive/plan-prose-linked-knowledge.md 的现有小节样本打通展开，随后按下列批次正式补充并标注语料。标签检索和展开能力可独立推进；不依赖新增能力的资料核对和正文整理可先做，正式删除重复事实段落须等替代证据能够送达。

本方向不等待索引计划所有标签功能完成。依赖关联的标注使用已交付格式；未受相关调整影响的正文可继续，不把每批内容绑定到全部框架扩展完成。

### 当前执行顺序（2026-09-18 修订）

旧三批清单继续提供来源线索，执行按下列切片收束；设施主题批次不要求先导入全部释义、再重复核对一遍组合。

| 顺序 | 范围 | 实施归属与边界 |
|---|---|---|
| 当前小批 | 固定版本清单轻量校准＋怪猎组合一节 | docs/plan-corpus-rebase-and-gaps.md；清单补新增候选，仅审定本批实际采用内容，不修改散件参考线 |
| 下一批 | 存量正文与上游留档的路径迁移 | 按「承载分类与实施归属」独立定计划，只改路径及必要引用；当前小批可先向既有组合篇追加，新来源稿直接使用 raw/upstream |
| 后续主题批 | 贸易、制造等设施的释义与组合增量 | 每批一起处理同主题的机制解释、组合分工与必要关联；具体先后和篇目仍按采用清单确定，避免为保持旧三批顺序重复选材 |
| 其余补缺 | 办公室／宿舍、活动室／信赖、其余建设与资源、新增组合、操作及布局 | 分别确定范围，不因登记候选自动批准导入；新增组合不以旧清单已覆盖为由排除 |

清单校准采用一次文件级差异核对；详细事实核对只覆盖当批采用段落。前置试点已交付的预检工具继续复用，每批无需重做逐候选统计、漏报率或耗时评估；记录影响采用的具体问题即可。每批按实际变更运行既有门禁，并核对新增内容与必要关联的实际读取，不新增语料断言台账或重复校验框架。

### 原三批素材安排（历史选材分组，非当前执行顺序）

输入为现有 base/guides 与外部相关主题。采用具体段落前核对来源、条件及现有内容，不扩展为全量上游刷新工程。

原分组如下；已完成部分及后续归属以「当前执行顺序」和实施补记为准：

1. 补充加工站、训练室独立机制正文，覆盖工作方式、心情/速度口径及特殊效果边界。
2. 补充特殊技能释义，优先解释生效条件、替换、归零、订单类型等关系，不复制全量技能表。
3. 扩写组合的设施分工、缺人变体与互斥条件，按独立主题拆分过长的跨设施汇总并保留导航。
4. 整理散件正文，减少同篇中不同设施信息混杂。精确技能数据由 facts 承接，人工正文解释取舍；需要查表时从事实派生，不另养手写数值表。

输出为 base/guides 的新增或更新正文及 corpus-manifest 登记。外部未证实的统一结算顺序、固定班表和内部矛盾数值不直接转为本库规则。术语遵循 docs/rules/rag-prose-terminology.md。

完成依据：采用内容有具体来源，公式可复算，重复主题和冲突版本已处理，检索入口指向实际正文。采用对象见下节；落位按表执行，篇幅过长时按设施或独立主题拆分并更新 manifest。

## 实施方案（候选）

### 1. 维护关联内容并反馈框架

作者根据正文用途登记必要对象，旁挂元数据只保存关联计划规定的引用；不把名字出现即视作相关，也不复制技能数值。批次中分别检查：关键词是否可搜、需要的对象能否表达、相关证据能否一起取得。

- 已有类型的数据缺口：在对应维护位置补关键词、标签或引用数据。
- 局部表达或派生问题：给出具体例子，在所属计划实施笔记中记录调整并核对已有对象。
- 新关系类型、标签语义或公共契约变化：分别回到索引或关联计划处理，超出已定范围的需求登记 inbox，不在语料任务中暗改工具。
- 不支持的特殊机制继续用清楚正文表达，不强行编码，不把一个例外变成全局规则。

### 2. 逐批收束

每批完成来源核对、主题去重、术语整理、关联内容与 manifest 登记；明确设施、对象、条件和代价。检查实际送达后再删被替代的重复事实段落。加工站、训练室与共享建设升级篇按当前试点计划落位；活动室/信赖及其他建设内容留后续核对。组合只扩写采用清单内主题和所列分工/缺人/互斥边界，不重整全库命名。

沿用文档和散文术语检查；关联形式检查使用关联计划提供的能力，关联是否恰当仍人工判断。质量观察按 exp 流程，包含未参与调整的同类问题；不以当前题目答对率作为固定验收值，付费运行另行明确范围。
