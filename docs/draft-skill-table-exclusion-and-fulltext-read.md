# 技能表退出检索、机制全文读取与 RAG 精确词条附带 facts 草案

> 创建日期：2026-09-11
> 状态：草案（未定稿，scope 讨论中）
> 修订日期：2026-09-11（基础数据纠正；新增自动附带 facts 候选规则，尚未实施）

## 目标

收缩 rag_search 的检索候选池，并探索机制/指南语料按文件扩展原文返回，改善必要小节送达；技能表类证据由现有 facts 查询能力承接。新增候选：rag_search 中符合入口规则的精确搜索词自动触发内部 facts 查询，随本次结果附带记录卡，无需模型额外显式调用 facts_search。独立 facts_search 保留。起点是 2026-09-11 GLM-5.3-Flash low 单轮 hybrid 核查暴露的送达缺口，见 docs/archive/exp/exp-glm-low-20q-hybrid-recheck.md。本轮仅修订草案，不代表已授权实施或付费运行。

## 非目标

- 不改 agent loop、ADR-012 的外部调用双上限与扣点规则、knowledge 事实真源。定稿实施时允许同步工具描述与 knowledge/AGENTS.md 的工具选择说明，使其准确描述 RAG 附带 facts 的行为；不借机调整作答策略。
- 不引入向量检索、rerank、字段/文档类型加权等新打分层，也不改 BM25 参数——单列为另一条线，另行评估。
- 不针对题集做特判或改写；优化须可泛化，并用未参与调优的问题验证。
- 不新增哈希/指纹字段（编码核心约束 #10）。

## 架构分析

### 现状

- 检索只有单塔 BM25，见 bench/src/retriever.ts：索引字段为 `anchor + heading + text` 单字段，k1=1.5、b=0.75，无文档类型先验，按 topK 硬截断。
- rag_search 直接返回 topK 命中，无二次排序与配额，见 bench/src/tool-executor.ts。
- 分块只切 `##`/`###`，见 bench/src/corpus.ts；base 机制文件按 `##` 每节成块，`####` 不切。
- 语料共 749 块：base 61、guides 49、references 639（约 85%）。references 内九份 `技能-*.md` 占 604 块，其余 35 块来自技能等价组（10）、类别（7）、名册（7）、歧义（4）、数据源（7）；技能表按干员切块（`### 干员名`），单文件可贡献数十块。
- facts_search 为精确词条匹配（干员名/别名/技能名/技能组/设施/阵营/职业 + 人工 alias/substring/combo），返回完整记录卡；notes 不进匹配索引，仅随命中卡渲染，见 bench/src/facts/store.ts。

### 痛点证据（2026-09-11 GLM low hybrid 单轮）

- 107 条注入中 49 条（46%）为 references/技能-*.md；20 题里 13 题至少命中 1 条技能表条目。
- 15 个遗漏中 10 项属必要证据未送达，其中 5 项为机制小节被挤出 topK：F04.1、F07.2、F09.1、F10.3、G02.3。
- gold（bench/gold.json）共 69 个键，23 个（33%）为技能表条目，且全部集中在 S 题。

### 可行性复算（离线）

- 按当前工作区、原始分块、bigram、entityBoost=0、topK=5 复算：仅排除九份 `references/技能-*.md` 后为 **145 块**（base/guides 110 + 其他 references 35）。**110 块对应排除全部 references**，两种范围不能混用。
- 使用该轮模型原始 query：仅排除技能表时，F04.1 的「线索搜集速度」、F07.2 的「心情恢复公式」、F09.1 的「练度、技能等级与解锁档位」分别排 **4/4/1**；排除全部 references 时才是原草案的 **3/3/1**。仅排除技能表时，F10.3 的「取最高与可叠加」排 6，G02.3 所需的「刷新次数与招募位」排 10；相关文件已有其他小节进入 top5，支持评估命中后扩展全文，不构成必须改成文件级 BM25 的证明。
- base/guides 共 **17 个文件**，原文件字符串按 UTF-16 长度计最大为 `guides/高效率散件.md` 的 **2,835 字符**。原草案的 **18,507 字符**来自 `references/技能-训练室.md`，不属于本次拟全文返回对象。原文件长度与去除 frontmatter、标题后的目录正文长度须区分。
- 对历史 22 条 rag_search query 做静态模拟，保留其他 references，topK=5：小节 top5 命中后按文件去重扩展 base/guides 正文，最大 12,200 字符，1 条超过 12,000；base/guides 改按 H1 正文整文建索引（其他 references 仍按块），最大 14,404 字符，3 条超过 12,000。仅计正文和来源头，不含导航及工具 JSON，也未启用本草案新增的 facts 附带。两者均不是模型行为或实际费用结果。
- 23 个技能表 golden 全部可按干员名 facts_search 命中（23/23）；组合入口的缺员发现链由本轮落地的 17 条导航备注承接（docs/plan-facts-crossref-navigation.md），实测 `红松骑士团`→焰尾卡指向薇薇安娜、`标准化类技能`→水月卡导航、`深海猎人`→斯卡蒂/乌尔比安卡导航成立。
- 已知未覆盖：docs/plan-facts-crossref-navigation-notes.md 记录的组合成员名/技能名/问法全排列、combo 名与阵营名差一字（如 红松骑士团 与 红松骑士团组）、5 个零命中入口（喀兰贸易/人间烟火/自动化/感知信息/喀兰）。

### 关键风险

- facts_search 只吃精确词条、不解析自然语言。自动附带可以减少符合入口规则时的额外显式调用，但不会自动补齐模型未提出的词条；组合、设施等入口可一次返回多卡，不能把取证成本等同于逐人调用数。默认 5 次成功额度是否够用仍需行为验证。
- 增加同次返回内容可能减少后续调用，也可能增加无关证据、截断与累计输入 token；调用次数下降不能替代费用测量。现有独立 facts_search 返回完整卡，不受 RAG 的 maxContextChars 限制；自动附带必须单独明确容量契约。
- 现有 runHitrate 在 gold 无法解析时会报错，不只是 recall 下降；只改 runner 的过滤又会让 CLI hitrate 继续测旧范围。gold/spec 的事实要求不因技能表退出而删减，检索排序与实际送达需要分别计量。

## 实施方案

### 步骤 1 — 范围与排除落点

首选候选范围为九份 `references/技能-*.md`；其余 references 保留。倾向在检索装配层过滤，不改 knowledge 真源与 corpus-manifest 语义；分块真源与原文目录仍可用于证据定位。定稿前明确 bm25 是否同步排除技能表或维持旧范围作对照，避免模式名相同却范围不可辨识。检索返回契约与 facts 跨模块接口变更应新建 ADR，定稿时登记，不在本次草案修订中提前宣告决策已实施。

### 步骤 2 — 机制语料文件级/全文返回（依赖步骤 1）

首选候选为保留小节 BM25：取 topK 命中，base/guides 按文件去重并扩展到原文目录的文档范围；顺序取首次命中位置，不在去重后自动补满 K 个文件。其他 references 仍按原块返回。文件级 BM25 另列候选，其词频、文档频率与长度归一化都会变化，不与全文扩展视为同一变量。

单文件当前均小于 12,000，但多结果、来源头、导航和 facts 附带的总量可能超限。定稿时约定合并结果上限与 RAG/facts 的空间分配；超限不承诺整文一次送达，须保留完整可调用的读取入口与明确的未送达状态，不能把命中文档等同于全部证据已注入。当前 read_section 正文另有 6,000 字符分页上限，单改 maxContextChars 不会改变此上限；保留原分页契约为首选，是否修改另作显式决策。

### 步骤 3 — RAG 精确词条自动附带 facts（依赖步骤 1–2）

以下为可评审的首版候选规则，尚未实现。目标是在一次 rag_search 返回中附带相关事实；实现复用 store.factsSearch，不在 agent loop 内伪造一次额外 facts_search 调用，不引入额外 LLM 请求。

#### 入口识别

1. 仅在 hybrid 的 rag_search 启用；bm25 保留纯 RAG，不暗中取得 facts 能力。独立 facts_search 的单完整词条协议保持原样。
2. 词典来自现有六类 facts 词条与已校验的 alias/substring/combo 登记，与 factsSearch 使用同一套数据；不另建题集词表，不从 notes、技能效果散文或 BM25 分词结果推导入口。store 可提供只读候选词访问能力，派发层不自行重建另一套事实解析规则。
3. query 只做首尾 trim，保留内部标点、大小写与空白。先尝试**整条 query 精确匹配**：所有现有合法词条类别均可触发，单字正式名也可；若成立，不再扫描其内部短词。
4. 整条未匹配时，可识别**由空白边界隔开的完整登记搜索词**：词条两端必须为字符串边界或空白，词内字符必须原样相等。含内部空格的登记长词整体匹配；同起点优先最长词，已消费范围不再触发短词，其他非重叠词按 query 中出现顺序处理并去重。未匹配部分继续参加原 BM25 查询，不改写 query。
5. 多关键词分支只接纳至少两个字符的干员名、技能名、技能组、阵营及登记 alias/substring/combo；仅命中设施或职业的搜索词不在该分支自动展开，避免「制造站 生产力」拉取整站名单。同一完整词条若还命中其他类别，一旦准入，factsSearch 的全部路径仍保留，不做类别消歧。设施/职业查询仍可经规则 3 或显式 facts_search 使用。
6. 首版不识别未分隔自然句中的词条、不把逗号或加号强行当分隔符、不补删「组」字、不做近义改写或任意子串扫描。此边界保证精确入口可解释；自然句实体提取若需要，另作候选评估，不与本版混入。

| rag_search 的 query | 候选行为 | 边界说明 |
|---|---|---|
| `温蒂` | 整词触发一次 facts 查询，同时保留 RAG 检索 | 不要求另一次显式工具调用 |
| `温蒂 自动化组 第三人` | 两个登记搜索词分别触发，同次合并去重 | 「第三人」不推导为某个干员或过滤条件 |
| `温蒂的生产力怎么算` | 仅执行 RAG | 不从连续自然句中抽取温蒂 |
| `制造站 生产力` | 仅执行 RAG，除非其中存在其他符合规则的登记词 | 设施词不在多关键词分支展开 |
| `制造站` | 整词触发现有设施查询 | 大集合是否附带受容量规则约束 |
| `令` / `令 心情条件` | 前者可触发；后者不以单字词触发 | 防止单字普通用法引发自动查询 |
| `红松骑士团` / `红松骑士团组` | 分别按已登记阵营/组合路径解析 | 不自动补「组」，不把两者视为同一成员集合 |
| `喀兰贸易` / `人间烟火` / `自动化` / `感知信息` / `喀兰` | 当前不因相似于组合名而触发 | 既有零命中短词不是自动补全依据 |

#### 查询、去重与展开边界

- 每个准入词最多调用一次现有 factsSearch；同一词的 exact/alias/substring/combo 按现有规则并集，保留全部解析路径。同名歧义不选单一卡，不用 BM25 排名替代 facts 的匹配契约。
- 多词结果按 canonical 去重，卡正文只渲染一次，同时保留每个触发词与命中卡的关联。顺序为 query 中词条首次出现顺序、词内沿用 store 的稳定卡顺序；不新增相关性打分或文档类别权重。
- 只做一跳：combo 已登记成员可以直接返回；卡片 notes 中出现的其他名字、RAG 命中正文中的实体和附带结果中的新词不再自动触发。导航备注仍是供模型判断的线索，不升级为递归执行指令。
- 保留记录卡的条件、替换关系、命中路径与来源信息；不由宿主概括技能、不把多词并集解释成满足多个条件的交集或完整推荐名单。

#### 结果容量、预算与观测

- RAG 证据与附带 facts 在一次响应内分区呈现；字符上限及两部分空间分配待定稿，必须给 RAG 正文和续读入口保留空间，不能因自动附带完全挤出机制证据，也不能依赖「一般不会太长」默认不限量。定稿前离线统计触发词数量、去重卡数、整组序列化长度与未附带比例，决定具体额度，不先任意设卡数阈值。
- 首选容量规则以**单个触发词的完整匹配集合**为原子单位：去重后的新增完整卡与该词全部解析路径能放入时一起附带；放不下则该词整组暂不附带，返回完整可复制的词条及原因，供必要时显式 facts_search。允许后续独立词组继续尝试剩余空间；不截断卡正文、不挑一张卡消除同名歧义。跨词已返回的共享卡可复用，但该词自身的全部成员和路径未齐时不得标记完整。
- 区分触发、匹配与送达：未命中、因容量未附带、完整附带分别记录。未附带不代表零匹配；开放组合即使已返回登记成员，也不表示穷尽游戏中所有适配成员。若连完整的未附带提示都放不下，应先收缩证据正文为其留位，不能写入截断词条。
- 一次外部 rag_search 获准仍只计 1 次 attempt；执行无错误且 RAG/facts 任一部分实际送达非空证据才计 1 次 success，二者均无正文证据则 empty，提示与路径元数据本身不扣成功额度。内部 facts 查询次数不额外消耗工具额度，重复返回证据仍沿用 ADR-012 的扣点规则。
- 内部 facts store 加载或查询抛错时沿用当前工具执行错误的 fatal 语义，整次调用报 error、不扣成功额度；不静默降级成成功 RAG，也不增加隐式重试。空匹配、容量不足属于可解释的结果状态，不是执行异常。
- trace 保留一条外部 rag_search 调用；内部补充记录触发词、原 query 位置、解析路径、匹配/送达 canonical、未附带原因、字符数及耗时，并接入既有 facts store 使用/失败回调。统计分别报告显式 facts_search 次数、RAG 内部 facts 查询次数与实际附带次数，不伪造模型调用或 HTTP 次数。
- 既有 RAG hitIds/injectedIds 保持 chunk 语义；自动附带卡与原文扩展范围单独记录实际送达，不能混入一个无类型 ID 列表或把整个文件记为已注入。附带结果不能直接套用当前独立 factsResult 的 `complete: true`；新字段及 schema 版本在 ADR/plan 定稿时定义，旧运行缺字段表示不可用，不能补零。
- 费用仍按 provider 实际 usage 计量，含后续轮次携带这些证据的累计输入与缓存；减少一次显式工具调用不等于免除 token 费用。

#### 登记补全与验证边界

本轮优先复用既有登记，不为历史题目追加短词或备注。后续确需补入口时，以正式名/别名/组合身份与语料来源为依据，明确同名和简称的目标集合；现有 alias/substring 只指向干员，组合简称不能硬塞进该结构或冒充阵营，需单独定义契约后再评估。沿用 docs/plan-facts-crossref-navigation.md 的来源审计口径，未分隔自然句及成员名全排列不作为本版强制覆盖目标。

验证包括：完整词、空白关键词、多词重叠去重、带内部标点/空格的名字、单字名、设施/职业大集合、阵营与组合差异、未知短词、容量未附带、只 facts 非空、两路均空、内部异常、bm25 不触发、历史格式读取与计数分离；使用构造词条验证机械契约，质量验证使用未参与调优的问题。

### 步骤 4 — 口径与基线（依赖步骤 1–3）

保留 bench/gold.json 和 docs/spec/rag-answer-baseline.md 的事实要求与真源锚点，不以移除技能表为由删减分母。区分小节排序命中、扩展原文实际送达、附带 facts 实际送达与最终回答覆盖；明确过滤后的索引与 gold 解析目录之间的映射，runner/CLI hitrate 的范围配置一致。现有纯 BM25 hitrate 不自动升级为混合工具质量分数，跨粒度结果不直接横比。口径在对照前固定，历史格式与历史结论保留。

### 步骤 5 — 对照运行（依赖步骤 1–4）

工程定稿及运行获授权后，另行路由 exp；固定 provider 与其他配置，分开比较现状、仅排除技能表、排除加原文扩展、再加精确词条附带 facts。文件级 BM25 与新词条登记另作变量，避免同时变更而无法归因。现有 20 题作为诊断/回归集，另设未参与调优的留出题；记录完成率、外部/内部 facts 查询次数、触发及容量未附带比例、预算触顶、实际送达、回答覆盖与实际 usage 费用。不因答错重跑追分，不将答对率设为默认工程门槛。
