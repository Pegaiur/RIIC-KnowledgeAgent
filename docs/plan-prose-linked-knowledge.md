# 散文关联知识与按需展开计划

> 创建日期：2026-09-13
> 状态：施工中

## 目标

为现有正文小节登记关联事实对象，RAG 返回可展开入口，Agent 主动选择后通过现有 read_section 一步取得关联事实。无需新增标签或改写正文即可独立验证这项能力。

## 非目标

- 不扫描命中正文名字后自动附带 facts，不新增查询分类、关键词路由或模型工具。
- 元数据不参与 BM25 正文、分词、切块或排序；不以关联改善召回分数。
- 不改写正文或复制数值，不维护推荐名单；关键词目录归 docs/plan-index-and-tags.md，正文与标注内容归 docs/plan-corpus-supplement.md。
- 不实施散文断言与事实的机械校验，该事项独立留 inbox。
- 关联载荷的新增体积优化与分页策略推迟另议；既有原文阅读/分页契约保留，不借此取消现行工具限制。
- 本次只完成计划转换，未开发功能或启动付费试验。

## 架构分析

质量观察中存在散文已给出候选、精确条件与代价未送达的情况，见 docs/exp/exp-agent-quality-baseline.md。现有 ADR-013 按实际 rag_search query 的登记词触发附带，覆盖干员、技能、技能组、阵营与登记组合等，并非只识别干员；它不等于从正文取得作者明确登记的关联对象。

检索块、原文小节目录和按文件扩展的送达范围不同。人工标注应定位文件及标题小节，再让检索结果携带对应入口，避免切块变化强迫重写标注。事实层现有 skill/grant ID 依赖原文内容，更新后会变化；不能仅靠保存当前内部 ID 宣称引用长期稳定。

本计划负责引用格式、解析、展开协议和机械形式检查，复用 facts 读取/展示。作者判断关联是否恰当，语料计划维护正式内容标注；格式合法不证明相关性，也不证明散文断言正确。

## 实施方案

### 外部参考输入

共用上游 [lejciy/arknights-base-vault](https://github.com/lejciy/arknights-base-vault) 的本地工作副本 dev-temp/work/corpus-supplement/arknights-base-vault（本次取得 main 分支提交 `54e92d9`；取得与保留约定见 docs/plan-corpus-supplement.md「外部输入与本地工作副本」）。查阅副本中的 meta/协作与引用规范.md、meta/templates/组合库写作规范.md、meta/templates/tpl-特殊技能释义.md 及对应正文示例，参考正文与事实引用的职责划分，不直接照搬上游图谱字段或将上游标识作为本库对象 ID。首批能力验证仍使用本库现有小节，引用契约由本计划按共同语义确定。

### 1. 依共同语义确定引用契约

输入为 docs/plan-index-and-tags.md 第 1 步明确的事实对象含义与明确引用/搜索词边界，不依赖完整标签检索或全部语料迁移。

人工关联使用可读的明确对象引用。干员定位到规范对象；细化到技能或 grant 时结合设施、技能及持有/解锁信息确定目标，解析必须明确，不能用自然语言搜索返回的同名并集代替。生成时再解析到当前内部 ID；事实更新触发重新解析，缺失或歧义明确报告，不猜测迁移，不新增哈希字段。

在 knowledge 数据层旁挂关联元数据，人工定位使用文件与标题路径；同路径重复标题须明确消歧。生成期连接现有小节目录和检索结果，不把人工记录绑定到检索块序号。首版只标明确小节，不做篇级自动继承。具体文件名和可读引用字段在本步骤记录为施工契约，并为 read_section 扩展及相关公共接口按判据建立 ADR，再进行运行时改造。

### 2. 登记关联与机械检查

- 关联只保存对象引用，不保存数值、效率或条件原文。
- 用少量现有小节作为能力验证样本（办公室联络选择、源石制造及含替换关系的对象），仅新增旁挂标注，不改正文或新增标签。
- 人判断该小节应关联哪些对象；生成器检查定位、引用存在性/解析唯一性及映射一致性。
- 无标注或空关联合法；不追求所有正文都有标注，也不把此作为发布阻塞条件。非空标注的无效引用应显式报告并修正。
- 事实重建后重新解析；小节迁移或改名时更新对应标注。校验不扩展到散文数值抽取、阈值与练度断言。

### 3. 提示展开入口

rag_search 继续按现有正文范围返回，额外给出对应小节的可展开提示和可调用定位。即使原文被按文件扩展，也保留关联所属小节，不能把整篇所有事实默认并入命中小节。提示只负责导航，不自动返回关联事实，也不改变现有 query 触发的 ADR-013 附带语义。

元数据与原文分离装配，原文分词、切块与排序输入保持一致。目录及工具说明告知展开能力，不把所有逐段关联复制到 knowledge/AGENTS.md。

### 4. 通过 read_section 显式展开

保留默认读原文行为；增加显式选择关联事实的能力。Agent 可读取原文，也可只展开关联事实，不强制重复返回已取得的整篇原文。复用现有工具而非新增图遍历工具。

展开直接解析登记引用，复用 facts 对象读取及卡片展示，不经过别名、子串或同名全部返回入口；后者继续只服务自然语言搜索。关联对象即本次展开范围，不因证据中的其他名字递归扩张。

响应区分原文与关联事实，标明关联小节和实际返回对象。技能保持持有者、设施、解锁、替换、产物、条件与代价的对应，不因同卡关联而相加。沿用实际工具调用、成功/空结果与费用观测，提示本身不冒充已取得事实。

### 5. 独立验证与交接

用现有正文和旁挂标注验证提示可见、主动选择有效、事实解析正确；比较开启前后的正文分词/检索输入及既有阅读行为，确保元数据没有暗改召回。给语料计划提供标注格式和操作说明，后续语料只维护关联内容。

本计划不等待标签检索完成，不要求批量新增语料，也不将模型一定选择展开作为机械验收条件。体积/分页改进与散文断言校验另立范围，不作为本能力交付前提。
