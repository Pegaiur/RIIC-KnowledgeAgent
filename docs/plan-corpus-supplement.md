# 语料补充与整理计划

> 创建日期：2026-09-13
> 状态：施工中

## 目标

逐批补充机制、技能释义与组合解释，按可用关联格式标注必要事实对象。用真实内容检验关键词、标签和展开能力，及时反馈局部不足，不以功能框架不断扩展拖住内容交付。

## 非目标

- 不定义工具协议、索引算法或关联格式；分别归 docs/plan-index-and-tags.md 与 docs/plan-prose-linked-knowledge.md。
- 不开展全量事实刷新，不恢复退役 raw，不整库复制外部材料。
- 不做查询分类、黑话词典、组合命名结构重整、排班求解或综合推荐分。
- 不实施散文断言机械校验，不建立人工数值副本；本次只转计划，尚未导入语料或运行付费试验。

## 架构分析

本地已吸收部分外部同源 guides 与机制正文；加工站和训练室机制仍有独立增量。散件中的大量内容是 facts 的重新组织，正文应保留解释与选择依据，必要事实通过既有工具或显式关联取得。

本计划维护正文内容以及“该小节关联谁”的判断；索引计划提供可搜词与事实对象语义；关联计划提供引用格式和展开协议。三项分别验收，语料不因缺少可选标签或图谱抽象而停止。

### 1. 启动顺序与依赖

先完成 docs/plan-index-and-tags.md 的共同语义，再用 docs/plan-prose-linked-knowledge.md 的现有小节样本打通展开，随后按下列批次正式补充并标注语料。标签检索和展开能力可独立推进；不依赖新增能力的资料核对和正文整理可先做，正式删除重复事实段落须等替代证据能够送达。

本计划不等待索引计划所有标签功能完成。依赖关联的标注使用已交付格式；未受相关调整影响的正文可继续，不把每批内容绑定到全部框架扩展完成。

### 2. 按批补充与整理语料


输入为现有 base/guides 与外部相关主题。采用具体段落前核对来源、条件及现有内容，不扩展为全量上游刷新工程。

实施顺序：

1. 补充加工站、训练室独立机制正文，覆盖工作方式、心情/速度口径及特殊效果边界。
2. 补充特殊技能释义，优先解释生效条件、替换、归零、订单类型等关系，不复制全量技能表。
3. 扩写组合的设施分工、缺人变体与互斥条件，按独立主题拆分过长的跨设施汇总并保留导航。
4. 整理散件正文，减少同篇中不同设施信息混杂。精确技能数据由 facts 承接，人工正文解释取舍；需要查表时从事实派生，不另养手写数值表。

输出为 base/guides 的新增或更新正文及 corpus-manifest 登记。外部未证实的统一结算顺序、固定班表和内部矛盾数值不直接转为本库规则。术语遵循 docs/rules/rag-prose-terminology.md。

完成依据：采用内容有具体来源，公式可复算，重复主题和冲突版本已处理，检索入口指向实际正文。采用对象见下节；落位按表执行，篇幅过长时按设施或独立主题拆分并更新 manifest。

#### 语料表达约定

- 每个检索块明确主语、进驻设施与作用对象；效果、条件、代价和数值口径一起出现，不依赖上一节的指代。
- 将内容分为事实、组织规则和建议：技能数值/解锁来自 facts；需要组织视图时，范围与成员选择有明确依据；培养去重、多身份展示优先等消费策略不作为候选缺席的原因。
- 单一维护不等于送达时只给链接。必要事实可从同一来源派生并随解释送达；不另维护人工数值副本。
- 释义只解释原文不能直接消除的误读；短主题不强套多节模板，不重复写同一条件。事实缺口仍应保留必要的不确定性，维护过程移至过程文档。
- 借鉴外部 meta/协作与引用规范.md、meta/templates/组合库写作规范.md 和 tpl-特殊技能释义.md 的自包含与职责划分，不照搬其图谱字段、整套章节及引用格式。玩家术语继续遵循本库规则。

### 3. 维护关联内容并反馈框架

作者根据正文用途登记必要对象，旁挂元数据只保存关联计划规定的引用；不把名字出现即视作相关，也不复制技能数值。批次中分别检查：关键词是否可搜、需要的对象能否表达、相关证据能否一起取得。

- 已有类型的数据缺口：在对应维护位置补关键词、标签或引用数据。
- 局部表达或派生问题：给出具体例子，在所属计划实施笔记中记录调整并核对已有对象。
- 新关系类型、标签语义或公共契约变化：分别回到索引或关联计划处理，超出已定范围的需求登记 inbox，不在语料任务中暗改工具。
- 不支持的特殊机制继续用清楚正文表达，不强行编码，不把一个例外变成全局规则。

### 4. 逐批收束

每批完成来源核对、主题去重、术语整理、关联内容与 manifest 登记；明确设施、对象、条件和代价。检查实际送达后再删被替代的重复事实段落。建设/活动室/信赖按清单并入总览和控制中枢，新增加工站与训练室独立正文；组合只扩写表内主题和所列分工/缺人/互斥边界，不重整全库命名。

沿用文档和散文术语检查；关联形式检查使用关联计划提供的能力，关联是否恰当仍人工判断。质量观察按 exp 流程，包含未参与调整的同类问题；不以当前题目答对率作为固定验收值，付费运行另行明确范围。

### 5. 标题定位证据的小范围试点（2026-09-17 追加）

用户授权作为本计划延伸，先处理 knowledge/base/机制-贸易站.md 与 knowledge/guides/跨设施组合.md。以「隐藏正文后，仍能从标题树判断证据主题与阅读范围」为组织目标；标题保留对象，明确关系或必要边界，不把标题改成评测问题或堆入完整答案。

- 贸易站按获取效率与上限、心情消耗、订单确定时点、普通订单属性、概率、特殊订单属性继承、设施等级分别组织，拆开原来混在同节的独立机制。

### 6. 扩大标题定位与结构优化（2026-09-17 追加）

用户进一步授权扩大范围。覆盖白名单中全部 17 篇人工维护散文，包括已完成的两篇试点；类别与歧义两份参考表保留原格式。以既有正文表达的事实与推荐条件为依据，机制标题说明参数、状态或作用范围，组合标题保留规范名并补充分工、转化或成立条件，培养与散件标题说明用途和取舍。
