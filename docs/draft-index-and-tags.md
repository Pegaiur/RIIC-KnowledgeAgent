# 索引与标签框架草案

> 创建日期：2026-09-13
> 状态：未定稿（范围与方案讨论中）
> 需求入口：docs/inbox.md

## 目标

先基于现有 facts 明确索引对象、标签语义和最小关联方式，复用现有工具取得候选及必要证据，为后续语料补充提供可调整的组织基础。

## 非目标

- 不在本草案导入外部语料、重写全部散件或建设完整专题体系；语料工作见 docs/draft-corpus-supplement.md。
- 不新增面向模型的工具，不引入图数据库、通用图查询语言、任意多跳推理或综合推荐分。
- 不做查询分类、玩家问法映射、自动意图路由；查询侧去歧义与黑话词典仍独立留 inbox。
- 不新增固定基线或全量事实真源更新前置阶段，不要求框架一次覆盖所有机制。
- 当前仅草案，未实施，未启动付费试验。

## 背景与依据

- bench/src/facts 的现有事实已有设施、标签、作用产物、引用术语及 grant 解锁/替换关系，可用于派生索引；实际可用字段以实现时读取为准。
- knowledge/references/技能等价组.md 把多个技能名与持有者分开列出，并由正文相同推为同效，容易造成对应关系和等价范围的误读。
- 散件正文常是事实的重新组织，未必需要逐篇人工重复数值。标签查询、明确关联和按需派生视图可以减少重复，但不必为此预建完整图谱。
- 先前按 425 张卡估算，办公室联络标签完整卡约 5.8 千字符，贸易站订单效率约 1.14 万字符；仅供首版输出体积讨论，不作为现行容量或验收值。
- 2026-09-13 用户明确先定本框架，再加语料，在语料添加过程中及时审视并调整；框架可独立定稿和验证，不等待语料批次完成。

## 候选方案与评估

| 方案 | 判断 |
|---|---|
| 仅卡级标签集合 | 可用于候选检索，但不足以解释命中哪条技能及解锁替换关系 |
| 标签反查加现有事实关联 | 首版倾向；保留标签→技能→grant→干员，并按需附带证据 |
| 预建完整关系图、专题规则引擎 | 暂不采用；具体语料尚未证明需要这些抽象 |

使用现有对象标识与映射表即可。专题、组合分工和正文关联作为后续实际语料可能提出的扩展方向，不作为首版必建节点、必开入口或固定 schema。

## 实施方案（候选）

### 1. 明确索引对象与标签语义

- 从 SkillFact.tags、技能设施和持有关系派生标签反查；卡级标签为技能标签去重集合，保留具体命中依据。
- 同一干员多条技能命中时，候选卡去重、技能依据保留；不把多个解锁档当成多个干员。
- 标签表示已登记的事实属性，不自动表示推荐等级、完整适用范围或问法分类。缺少标签不等于没有该能力，既有精确/设施入口继续可用。
- 标签和同名职业/设施的查询语义明确区分，不对一个字符串自动取所有语义的并集。
- 首版从已有来源标签开始。新增语料暴露标签缺口时，再根据具体对象决定补数据还是调整标签设计，不预先造全套标签分类。

### 2. 保留最小事实关联

| 关联 | 作用 |
|---|---|
| 干员 → grant → 技能 | 绑定持有者、技能及解锁 |
| grant → 被替换 grant | 表达提升替换，不把被替换档合并计算 |
| 技能 → 设施、标签、产物、引用术语 | 选候选及取得必要条件解释 |
| 描述相同组 → 技能 → 持有者 | 展示归组依据及逐项对应，不推导整卡可互换 |

优先派生已有关系，不在本阶段全量抽取特殊机制关系。新增人工关系若确有需要，只登记引用、关系、条件和来源，不重复技能数值；存储位置与格式在具体需求出现时确定。

描述相同与完整效果等价分开表达。集群狩猎 α/β 正文相同却有提升替换关系，不能仅凭文字相同断言全部作用等价。输出绑定技能名、干员、解锁及替换，调整派生/展示逻辑而非手改生成文件；既有等价组入口兼容方式待定。

### 3. 复用现有工具查询与展示

现有 facts 工具扩展显式标签查询，普通 queries 维持既有精确词条语义；具体参数待定，不新增工具。先确定候选，再补候选在指定设施的相关技能、替换链和必要术语。

补证据不会自动扩大候选集合。同设施的多条技能仍需区分产物与成立条件，关联存在不代表可以相加。例如褐果命中源石专项技能后可带出标准化技能，仍分别展示技能与解锁关系，不把通用制造所有持有者自动加入专项标签结果。

- 返回查询范围、候选数量、命中依据，并绑定干员—技能—练度—效果—条件/代价。
- 首版以设施分组、名称稳定顺序为默认，不从百分号自动计算推荐排名。
- 完整卡前置相关技能与设施投影两种格式待比较；投影须保留解释当前能力所需的技能和替换关系。
- 不默认静默截取 Top-N；按实际输出量决定是否分页并明确覆盖范围。
- 沿用现有工具说明、计量及 trace。RAG 暂沿用既有附带机制，文档→专题自动附带不作为本框架首版前置工作。

### 4. 先定框架，再由语料反馈调整

先用现有事实检查标签反查、候选去重、跨设施与解锁替换关系，确定首版语义及消费方式。框架定稿后转入 docs/draft-corpus-supplement.md 的逐批语料整理，不以外部篇目、办公室/源石两个专题或全部散件迁移作为框架验收条件。

添加语料时及时检查：现有对象能否表达；标签是否恰当；必要证据是否能一起送达。数据缺口按既有结构补齐，局部不足做最小调整；只有具体内容证明需要时，才讨论专题、正文关联或新的关系类型。公共契约变化在框架侧明确修订，代码调整按测试约定验证；不要求先积累完所有问题再统一返工。

两份草案互相引用但分别定稿、实施和验收。未受框架调整影响的语料可继续推进；讨论期直接修订 draft，实施期按现有 inbox、笔记及 ADR 流程承接，不新增反馈台账。

## 待定事项

1. 显式标签参数与现有 queries、等价组入口的兼容方式。
2. 标签命名/设施范围、来源标签缺口的最小维护方式。
3. 完整卡或设施投影的首版输出，以及必要证据展开范围。
4. 按实际宽标签体积确定分页方式；不预设综合排序或专题引擎。

## 验收清单

以下为首版候选条目，定稿后转 plan。

- [ ] 标签反查与卡级聚合一致，保留技能命中及持有关系，候选去重正确。
- [ ] 标签与职业/设施同名语义明确，候选选择与证据展开分开。
- [ ] 描述相同与完整等价区分，技能—持有者—解锁—替换逐项绑定。
- [ ] 现有 facts 工具能够消费索引，输出范围、条件与代价明确，不静默丢弃候选。
- [ ] 框架可用现有事实独立验证，不绑定语料批次、完整专题体系或新工具。
- [ ] 运行时改造按 docs/rules/testing.md 先观察行为测试失败再实现，通过 pnpm run typecheck 和全套 pnpm run test。
- [ ] 文档通过 node scripts/doc-check.mjs；后续质量试验另按 exp 流程，不新增固定基线门槛。
