## 适用范围与效力

新增、导入、改写或审阅 knowledge/base 与 knowledge/guides 的人工散文前，仓库 Agent 必须读取并遵循本 spec 与配套术语 spec。下述写作要求及示例中的「必须保留」共同构成审阅依据；按实际主题适用，句式、条目数量、表格与篇幅由内容决定。

knowledge/guides/类别.md、knowledge/guides/歧义.md 为直出层，保留原格式，不套用玩家散文改写要求；这不豁免其来源、定位及指令冲突审阅。knowledge/raw、代码字段、历史归档不适用本 spec。规范约束本次任务范围内的写作与审阅，不要求为采用规范批量重写存量。

本 spec 面向语料编写与维护，不注入 knowledge/AGENTS.md 的运行时查询指令，也不登记到语料 manifest。示例用于说明表达要求；具体游戏结论仍须结合来源版本与适用条件审阅，示例不是新的 facts 来源。

## 事实与游戏理解的分工

[arkntools/arknights-toolbox-data](https://github.com/arkntools/arknights-toolbox-data) 的解包数据是 facts 的唯一上游真源，机械正确性校验控制其与 facts 条目的映射及转换。正式 facts 与 raw 的存储职责见 ADR-024；维护输入时按对应实施计划核对实际位置与迁移状态。结构检查通过不能代替上游映射的一致性验证。

[lejciy/arknights-base-vault](https://github.com/lejciy/arknights-base-vault) 的散文是明确采用的知识来源，按主题整理、去重与改写后纳入本库。外部总结与本地撰写的散文均承载基于解包数据和游戏实践形成的理解，由人类与 Agent 联合审阅；不要求逐句绑定数据字段，不为正文正确性建立严格机械断言。

审阅区分直接技能事实、机制解释和实践建议。出现矛盾时核对版本、适用条件与具体依据；实践结论由联合审阅判断，不要求现有技能资料裁决建设、操作等全部主题。facts 暂缺不自动排除相关散文，采用时明确可用依据与关联缺口；不得从散文或模型输出反向补填机械事实。来源采用记录保留仓库、提交和篇目，本地实践记录必要条件与判断依据，统一写入对应实施笔记。

## 写作要求

### 标题与阅读单元

标题使用规范对象名，或正文已明确定义且无歧义的组合名、别名，并交代主要机制、关系或用途；使用组合名、别名时，本节首次提及应写清正式对象或成员关系。保留辨认主题所需的词，避免堆叠同义词或穷举正文。独立出现在目录时，应能与相邻主题区分。

每个小节围绕一项可独立理解的关系组织，明确主语、设施和作用对象；先交代主要关系与影响使用的关键条件，再展开例子、推导或较长名单。结合实际检索块与 read 小节的正文范围，确认必要条件与所限定的结论能够一同取得，不依赖上一节的指代。

### 分工、条件与取舍

组合先交代成员怎样安排，再解释协作作用；跨设施资源关系写清生成者、资源、读取者与受益范围。机制、操作等主题按自身关系组织，无须套用成员模板。

练度、同驻、计数范围、替换、同种取最高等限定必须紧贴对应对象或效果；影响采用结论的代价与例外一并说明。公式与变量含义、适用条件和单位相邻，不能把组合示例写成单人固定收益。

明确区分技能最低触发条件、推荐完整形态和可选增强。培养去重与岗位优先级属于建议，应说明用途或取舍依据。缺人后的剩余作用与回退安排，只在影响该主题使用判断时展开；保留必要的不确定性，不用相邻对象外推结论。

### 正文与关联事实

正文承载关系、用法与取舍；已有技能事实通过既有 prose-links 精确关联。本地 facts 输入发现来源或转换疑点时，回到唯一上游核对，不以散文覆盖。raw 中的来源稿、摘录及加工中间稿仅用于添加过程，采用完成后按添加工作流清理；正式正文不以临时路径作为来源或关联的唯一定位。

确认必要关联能够实际送达后，可省略重复的技能全文与逐项数值。影响理解和安排的阈值、关键数值及示例条件仍须留在正文；不能为精简删掉必要的解锁、同驻、替换或例外条件。只写文件名、链接或登记对象不等于证据已经送达。跨篇依赖按所需范围核对，分页时分别确认正文与事实是否完整。

### 简洁表达

直接说明怎么用、何时生效、有什么取舍。重复条件合并表达，短主题不强套多节结构；平行内容可用短条目，对比关系或必要数值可用紧凑表格，均保留必要说明。

来源冲突、采用理由和审稿过程写入过程文档。玩家正文只保留影响使用判断的提醒，避免将每条审阅意见都改写成否定句或穷举无关风险。篇幅和压缩比例不设固定验收值，表达精简不等于问答质量已提升。

## 组合散文示例

以下摘句示范不同写作任务，适用时必须保留其表达的关系与条件；不要求逐字复述，也不把三个示例拼成每节必备模板。

### 示例一：成员与设施分工

来源：knowledge/guides/组合/贸易站组合.md「格拉斯哥帮组：同站成员计数与中枢协作」。

> 摩根与推进之王进驻同一座贸易站，戴菲恩进驻控制中枢。

**必须保留**：明确每名成员进哪里，以及同站还是跨设施的关系。组合名称不能代替分工说明。怪猎小队可沿用这一写法，先交代两人进控制中枢、调查团在贸易站或制造站择一工作。

### 示例二：练度与技能成员条件

来源：knowledge/guides/组合/制造站组合.md「水月标准化组：技能成员条件与中枢分工」。

> 核心：水月精二。
>
> 制造侧再有任意两名具备标准化类技能的成员。

**必须保留**：练度归属明确，成员数量与资格条件完整；最低解锁、推荐培养目标和可选搭配分开表达。怪猎小队分别交代精零生成木天蓼、各自精二解锁光环，以及调查团两个岗位的解锁要求，不逐项复述技能全文。

### 示例三：缺人后的剩余作用

来源：knowledge/guides/组合/贸易站组合.md「深巡＋乌尔比安：贸易站与基建挂件分工」。

> 缺少乌尔比安时，深巡按自身技能判断。

**必须保留**：指出缺少谁、哪项关系受影响、剩余作用如何判断。若概括不足以支持安排，就补必要结果：怪猎小队说明中枢只留一名成员时的木天蓼与光环变化，而不反复辩驳「缺一即关」。

## 执行与维护

添加、导入及临时材料处置必须读取并执行 skills/corpus-addition/SKILL.md，从确定范围到清理完成再收束批次；普通措辞修订或单独审稿按本 spec 与术语 spec 执行，不因此加载完整添加流程。

写作前确定本次主题、来源、采用范围和所需关联；完成后按本 spec 的适用要求与术语 spec 审阅。新增、导入或改变机制解释、适用条件、使用建议等实质内容的批次，由未参与编写的 Agent 独立复核来源、边界与表达。人类参与采用目标、实践判断和争议取舍，Agent 负责整理依据与审阅意见；已有明确的范围与决定直接沿用，待裁决的实质判断提交人类处理，不要求逐句批准。

普通错字、格式或不改变含义的措辞修订由当前 Agent 自查即可，不强制第二名 Agent 复核或整批重审。发现具体偏离就在当前范围修正，复核集中于受影响内容。采用理由、冲突处理与审阅结论写入既有实施笔记，不另建逐条证明台账。

验证沿用现有术语检查、文档检查与实际受影响的数据检查。新增或变更必要关联、据关联删减重复事实、或分节改变读取范围时，离线读取相关范围确认实际送达；普通措辞修订不因此强制重复读取。术语检查与 doc-check 不判断文风或 Agent 是否读过规范，检查通过不能代替按条款审阅。日常写作不以 A/B、付费运行或回答正确率作为前置条件；获授权的效果试验另按试验流程开展。

本 spec 是写作要求与示例的唯一维护处，活动草案按名称引用；术语表继续只在配套术语 spec 中维护。修改适用范围或规范含义时递进版本并注明变更，示例调整同步核对来源；生效版本不随实施计划发版归档。
