## 判断

值得做小规模验证，但不能把三次lookup空查统称为自造词。最近运行中“红松林骑士”偏离语料标题“红松林骑士组”；“红松骑士团”和“格拉斯哥帮”均为 references/名册.md 的真实阵营值，只是被用在lookup精确索引上。前者涉及名称边界，后者涉及实体类型和工具选择，单纯加粗不一定解决后者。

当前 guides 已用 Markdown 加粗核心/分工等字段，部分干员名也有加粗；模型接收的是文本符号。只加粗全部专名可能强化显著性，却仍无法区分干员名、阵营名和攻略组合标题。实验不预设标记有效，更不据空查自动修订事实或索引。

## 最小流程

1. 选择6个案例：2个已观察案例仅作诊断（红松、格拉斯哥），另外4个未用于本轮设计的案例覆盖干员、阵营、带标点专名、组合名与阵营名不同。每例固定一个问题和一个足以识别名称/类型、但可能需要补充目标事实的检索片段。不得为迫使调用删掉原文已有答案；若证据已足够，直接回答也允许。
2. 冻结当前提示词、schema v4、Qwen3.7-Flash/off/temperature=0。在临时探针中构造相同的system、user、assistant rag_search调用及tool结果，只替换tool.data内的实体标记；片段ID、次序、正文事实和其它envelope字段均保持一致。三组都不添加额外“照抄标记”指令。
3. 不重新检索、不改正式knowledge，不改变BM25分词/排序；这是固定证据后的下一步决策探针，不冒充完整端到端运行。
4. 每例三组各2次，共36次模型请求；按案例轮换ABC/BCA/CAB顺序，使用独立会话，保留重试与失败。每请求只生成一次后续模型响应，不循环。维持auto，不强迫模型调用工具。
5. 返回tool calls时仅在本地校验参数并查询store记录结果；返回正文时检查其中的名称。候选预期从真源预先登记，独立保存，不送给模型。复用现有provider/计量接口，不另建宿主loop。

## 记录什么

- **名称忠实度**：是否复制完整规范名、有无删字/拼接/误改标点。复制了标记本身（如term="〔干员：焰尾〕"）单列为符号污染，不自动去符号后视为调用成功。
- **类型与路由**：干员或技能精确名是否送lookup；阵营枚举是否用query_operators.faction；攻略组合标题是否被误当干员。允许有依据的termQuery或RAG继续查证，不机械规定唯一工具。
- **有效查询**：参数是否合规、执行后是否命中以及命中的对象是否与所问相关。高命中数不自动算好；空查不等于名称虚构。
- **不调用工具**：单独记录证据充分直接作答/证据仍不足；不从分母隐去不调用样本，不把它全部计为失败。
- **成本**：输入/输出token、费用、HTTP尝试、延迟；不把字符数当token，不据单次耗时归因。

每案例列A/B/C两次原始结果，区分2个诊断例与4个留出例，不设答题固定通过线。若B只改善复制而不改善路由，则不宣称它解决阵营混用；若C更好也只能说明“符号+类型信息”整体有帮助，不能归因为符号本身。36次是初筛，不能证明稳定成功率。

## 决策与后续边界

若标记带来符号污染、重复无收益或使已有证据充分时仍多查，暂不采用；若留出案例同样呈现明确改善且没有明显代价，再评估将标记加在检索返回渲染层。正式语料加标记可能改变分词、切块及召回，应另做端到端对照，不能由本探针直接授权全库改写。references直出层保持真源格式。
