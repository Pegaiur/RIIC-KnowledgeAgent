# 实施笔记：查询 Agent 单一指令源与 facts notes 分层

> 对应 spec：docs/plan-agent-facts-knowledge-layering.md
> 开始日期：2026-09-04

## 决策偏离

### 2026-09-04 — 从常驻知识扩展改为短决策契约
- **背景**：首版实现后复核发现 AGENTS、system prompt 与 SKILL 仍重复证据约束和工具路由，且常驻事实并不等于工作方法。
- **选项**：A：继续扩写常驻知识；B：只保留无法机械强制、能预防重复错误的查询契约。
- **决策**：采用 B；设施百科和具体游戏事实继续按需查询，根 AGENTS 的开发流程不进入查询上下文。
- **影响**：所有检索模式共享同一人工规则，历史对照由运行结果与新记录的内容哈希区分。

### 2026-09-04 — 以迁移范围代替全量治理台账
- **背景**：原草案要求枚举全部文档、事实和记录卡，超出本轮知识分层目标。
- **选项**：A：保留全量矩阵；B：只验证实际迁移内容与运行边界。
- **决策**：采用 B；不新增台账类资产。
- **影响**：后续若扩大 notes，只随具体需求增加测试和 curation，不预先记录所有未修改对象。

## 实现调整

### 2026-09-04 — 删除 SKILL 与 rules-prefix 指令入口
- **spec 原文**：保留缩减后的 `knowledge/SKILL.md`，历史 BM25/grep 模式不注入 AGENTS。
- **实际做法**：删除无运行时消费者的 SKILL 和已证伪的 rules-prefix；所有模式注入同一 AGENTS，模式能力由代码生成。
- **原因**：保留任一平行行为说明都会破坏单一人工指令源，rules-prefix 的归档实测也未证明质量收益。
- **后果**：`agent.ts` 不再维护角色、证据和表达规则的模式分支，运行元数据新增 AGENTS 内容哈希。

### 2026-09-04 — base 保留完整细节
- **spec 原文**：迁移完整的 base 从 RAG 白名单移除。
- **实际做法**：AGENTS 只提炼高频基础，base 原文继续进入 RAG。
- **原因**：总览中的队列规则和各稀有度常见门槛不适合全部常驻，但仍需可检索。
- **后果**：常驻提示保持精简，hybrid 仍能查询完整机制。

### 2026-09-04 — 结构化事实不写重复备注
- **spec 原文**：具体干员机制进入 facts notes。
- **实际做法**：升级替换关系直接由 `replacesGrantId` 渲染；只有跨技能解释进入 Operator notes。
- **原因**：notes 不应代偿工具遗漏的已有机械字段。
- **后果**：温蒂显示替换关系，巫恋和孑返回语义备注。

## 意外发现

### 2026-09-04 — 根 AGENTS 不会注入查询 Agent
- **发现**：查询 system prompt 完全由 `bench/src/agent.ts` 构造。
- **影响**：新增独立的 `knowledge/AGENTS.md`，后续收敛为所有检索模式共用的唯一人工指令源；根 AGENTS 只做开发规则与结构导航。

### 2026-09-04 — AGENTS 正文与运行哈希绑定同一快照
- **发现**：若运行开始时计算哈希、每道题重新读取正文，长跑期间文件变化会让元信息与实际提示不一致。
- **处理**：benchmark 启动时只读取一次正文，对该字符串计算哈希并传给所有题目。
- **结果**：同一次运行不会混用提示版本，元信息哈希可准确标识实际注入内容。
