## 目标

把候选篇目按五批完成逐篇评估、增量采用、正文与关联落位、联合审阅、验证与临时材料清理，并补齐散文主题分类。前四批已交付，第五批「用人与布局」继续在本计划内实施；采用判断以本地缺少的内容增量和来源依据为准，不以导入篇目数量或上游目录规模为目标。

## 非目标

- 不重做已交付内容：加工站、训练室、设施建造升级、怪猎组合节、清单校准及贸易、制造、基础与辅助设施三批成果直接复用，同源新段落只补增量。
- 不接入 facts 派生管道或刷新正式 facts（见 docs/inbox.md「facts 派生接入与正式刷新」）；不实施 facts 迁出与存量 raw 清理（见 docs/plan-facts-storage-and-raw-cleanup.md）。
- 不整库复制上游，不导入 meta、external、skill、README、镜像与治理材料；不以目录或篇目数量为导入目标。
- 不改检索算法、查询指令、工具预算、查询分类与评分，不实施排班求解。散文目录按本计划分类表整理；布局比较、用人取舍与有条件的收益估算属于采用范围，不据此宣称全局最优。
- 不建立散文逐句断言、手写全量事实表、重复校验框架或哈希指纹字段；不从散文反向补填机械事实。
- 不因问答答错触发修复，不设定正确率达标线；日常添加不要求付费运行。
- 不为候选登记长期保留 raw 原稿：每批交付后按 corpus-addition skill 清理本批材料，仅候选登记或笼统未来待办不构成保留理由。

### 为什么分拆

剩余候选涉及五个主题、数十篇来源对象，且每篇是否采用取决于与本地既有承载的增量比较，属于逐篇判断而非批量转换。候选登记若继续留在已完成的知识正确性计划中，会与该计划的收口口径混在一起，也不便于独立跟踪采用进度与清理时点。因此候选范围整体移出，按主题分为五批在本计划独立验收；原知识正确性计划的三批交付状态已固定，不再回改。

### 逐篇评估采用只读子代理分批

候选篇目数量大且彼此独立，逐篇「读取来源 → 对照本地承载 → 判断增量与冲突」适合并行分派只读子代理：子代理只做评估、不写文件，按批（批内对象较多时再按来源目录分组）输出结构化逐篇清单。子代理结论是采用输入而非采用结果，抽出的数值与关系不因清单出现就视为已核对；主代理须对每批亲自复核关键篇目（高影响、高冲突、与既有正文口径可能矛盾者）。评估子代理与写作 spec 要求的独立审阅子代理职责不同，互不替代，评估通过不免除联合审阅。

## 实施方案

### 0. 散文分类整理（第五批正文落位前）

- **输入**：上述分类表、当前 manifest 中的 24 篇正文及其实际路径消费者；本步只整理 18 篇现有文件的位置。
- **做法**：先按目标路径调整既有白名单、定位及关联测试预期并观察旧路径失败，再移动文件；正文语义、标题和分节不变，正文内受影响的路径引用同步更新。同步 corpus-manifest.json、prose-links.json（含概念引用路径）、facts curation 的 evidence、当前 gold/spec、测试及仍在使用的文档入口。文件名保持全局唯一，不留同名副本或旧路径回退；类别、歧义的固定入口保持原样。
- **定位与验证**：路径参与 chunk 与 section 标识，迁移后按实际目录重建，核对受影响正文和关联可读；仅路径整理时仍为 24 篇 / 191 检索块 / 35 定位文档 / 812 定位块。运行既有类型、全套测试、构建、完整性、术语、投影、目录一致性与文档检查；保持题号、证据含义和评分不变，历史运行、快照与历史实施记录不回改。
- **输出与衔接**：分类整理单独提交，随后第五批按稳定后的目标路径落位；新增正文的数量另按实际采用计算。facts/raw 迁移仍由独立计划负责，两者同步路径时各以实际消费者为准，不互相宣称已经完成。

### 1. 固定来源并逐篇评估（只读子代理分批）

- **输入**：固定来源提交 53cf2f7、上表五批对象、本地 knowledge/ 与 corpus-manifest、既有采用记录与来源说明。
- **取材**：按实际所需重新取得固定提交的来源材料，或读取可访问的同版本副本；只取本批对象，不复制整个外部库。来源定位（仓库、提交、篇目与采用段落）随采用结果记入 notes，raw 不作为唯一溯源位置。
- **评估**：按批派生只读子代理，逐篇输出结构化清单——来源对象、采用内容或增量、与本地既有承载的关系、冲突与依据、建议落点、不采用项与理由、未决项。批内对象较多时按来源目录再分组并行，同批不因分组拆成多个验收单元。
- **主代理复核**：每批亲自抽核关键篇目（高影响、高冲突、与既有正文口径可能矛盾者），对照来源核对拟采用的数值、条件与关系；不把子代理清单当作已核对事实，也不因评估完成即认定采用成立。
- **输出与验收**：每批的逐篇清单、主代理复核结论、冲突处理方向与未决项记入 docs/plan-corpus-candidate-batches-notes.md；不以候选总量或评估篇数替代实际采用判断，不新增逐条证明台账。

### 2. 按批采用与落位

- **输入**：步骤 1 的采用清单与固定来源篇目。
- **改写前验证**：预计改变分块、manifest 或定位计数时，按 corpus-addition skill 先更新相应完整性测试预期并观察旧语料失败，再改写正文与登记；不在落位后补做测试先行。
- **执行**：每批使用 skills/corpus-addition/SKILL.md，从选取段落推进到改写、落位与现有正文去重。内容批次之间不设硬前置；跨批共用段落在首次涉及时确定落点，后续补增量。第五批正式落位使用步骤 0 整理后的路径，其选材评估可先行；facts 映射与 facts/raw 迁移不是内容采用的共同前置。
- **承载**：按分类表优先补既有正文，确需独立阅读再拆篇；新增文件须登记 corpus-manifest，文件名在 manifest 内全局唯一。目录归类不作为采用依据或收益证明。
- **改写边界**：外部链接改成本地定位或自包含表述，去除目录编号、治理指令与外部元数据；保留操作步骤、先后关系、适用条件与必要不确定性，移除 draft 标记不等于结论变为确定。段落、条目或紧凑表格由内容决定，不统一删除步骤或短段。
- **输出与验收**：增量正文落位，采用内容可追到来源篇目或本地真源；既有冲突按来源版本与适用条件联合审阅处理，不默认本地或上游总是正确。

### 3. 关联与记账同步

- **输入**：本批新增或改动的小节。
- **做法**：按 ADR-020 与 ADR-022 的既有格式逐节判断是否登记 prose-links，必要时补精确技能或概念引用；同步 corpus-manifest 与实际受影响的文件数、检索块、定位文档与定位块，并核对是否满足改写前确定的 benchmark-integrity 等完整性测试预期。
- **验收**：`node dist/cli.js validate` 与既有关联检查通过；不新增重复门禁，不以对象存在替代正文相关性判断，不新增哈希或指纹字段。

### 4. 联合审阅与适用验证

- **审阅**：按 docs/spec/rag-prose-writing.md 组织复核与人类参与；实质变更交未参与实现的隔离子代理完整审查，实质变化后原结论失效须重新审查。步骤 1 的评估子代理不承担该职责。
- **验证**：`pnpm run check:prose-terms`、`pnpm run check:reference-projection`、`pnpm run typecheck`、全套 `pnpm run test`、`pnpm run build`、`node dist/cli.js validate`、`node scripts/doc-check.mjs`；按写作 spec 的触发条件离线核对相关正文与必要事实的实际送达，记录结果。
- **边界**：检查通过不替代联合审阅，也不代表问答质量改善；不设正确率门槛，不做付费追分运行，不据此提高工具预算。

### 5. 清理临时材料并收束

- **清理**：每批交付后按 corpus-addition skill 第 6 步确认正式成果、来源定位与审阅结论已落位，再按明确文件范围清理该批 raw 原稿与中间稿；已采用与未采用材料均不因「以后可能有用」长期保留。dev-temp 临时产物按 scripts/INDEX.md 的显式清单流程处置。
- **收束**：全部批次完成后核对候选评估、各批采用与散文分类整理记录，更新 docs/inbox.md 的候选和分类条目及受影响入口；按变更类型执行既有门禁，文档部分运行 doc-check 与差异检查。未完成项保持未勾选；本计划完成包含散文分类整理与各批临时材料清理，facts 派生接入、facts/raw 迁移和存量 raw 清理按各自计划验收。
- **遗留**：五批以外的对象继续留在 docs/inbox.md，另定范围再实施，不阻塞本计划验收。
