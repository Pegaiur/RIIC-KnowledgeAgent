## 目标

明确事实与散文的来源、核查职责和采用流程，支持继续吸收基于解包数据与实际游戏经验形成的知识。

本计划交付范围限定为：长期规范落位、facts 到唯一上游解包数据的映射评估、存量路径迁移处置结论。后续散文主题批次继续推进，分别确定篇目与采用内容；不以完成未定范围的全部导入作为本计划验收条件。

## 非目标

- 本计划不重建 facts 派生管道，不开展全量事实刷新；映射评估形成后续实施边界。
- 不对散文的数值、练度、条件、机制解释或推荐结论建立严格机械断言、逐句映射或第二份手写事实表。
- 不以外部目录、篇目数量或 canonical 标记作为本库必须对齐的目标；不整库复制来源文件。
- 不调整检索算法、查询 Agent 指令、工具预算、查询分类或评分口径；日常内容采用不依赖付费运行或正确率门槛。
- 标题与结构效果优化沿用 docs/draft-prose-optimization-workflow.md；工具协议与关联格式沿用既有 ADR。

## 架构分析

### 来源与知识分工

| 对象 | 来源与职责 | 核查方式 |
|---|---|---|
| 上游解包数据 | [arkntools/arknights-toolbox-data](https://github.com/arkntools/arknights-toolbox-data)，facts 的唯一上游真源 | 固定所用提交，核对源文件、对象、字段与 facts 条目的对应及转换 |
| 本地 facts 输入 | knowledge/raw 中的名册、技能分片×9、技能等价组，共 11 份；继续作为当前运行时输入 | 沿用现有结构与关系校验；到解包数据的映射尚待评估，不能宣称已获完整保证 |
| 散文来源 | [lejciy/arknights-base-vault](https://github.com/lejciy/arknights-base-vault) 中基于解包数据和游戏经验总结的语料，按主题整理、去重和改写后纳入本库 | 人类与 Agent 联合审阅来源、适用条件、解释和使用建议；不作正文正确性的机械校验 |
| 本地散文 | knowledge/base 与 knowledge/guides 中的机制理解、组合关系与实践取舍，包括外部采用与本地撰写内容 | 遵循 docs/spec/rag-prose-writing.md 与术语规则，联合审阅；保留现有格式和送达检查 |

“唯一真源”指 facts 的上游数据权威，不排斥其他人对数据与实际游戏经验的总结进入知识库。散文可以解释数据未直接表达的游戏行为和使用取舍，不要求每句都能回指某个字段。实践结论与明确的技能事实有冲突时，核对具体版本、条件和依据，由人类与 Agent 处理；不要求 11 份技能资料裁决建设、操作等全部主题。

RIIC-Web 镜像与 arknights-base-vault 的 scripts/clean-riic-skills.mjs 可帮助理解既有清洗方式，属于中间产物与实现参考，不另立为 facts 真源；它们的存在也不证明当前 11 份输入已能从指定解包版本完整复现。

### 现有检查的实际边界

- facts 解析与关系检查覆盖输入结构、对象及替换关系等既有契约；尚不能证明每个条目与解包数据一致。
- check:reference-projection 当前只检查技能分片的公共练度说明投影，不检查全部技能正文或上游到 facts 的完整派生。
- prose-links 检查对象与范围等关联契约，离线 read 确认正文及关联能否取得；二者不裁决游戏理解是否正确。
- check:prose-terms、validate、doc-check 继续检查术语格式、文件与分块完整性、文档一致性等各自契约。保留这些检查，不把通过结果解释为散文正确性的机械证明。
- typecheck、test、build 按实际变更选择；不为纯文档修订增加整套运行时检查，也不新增重复校验框架。

## 实施方案

### 1. 落位来源与联合审阅规范

- **输入**：用户的来源决策、既有写作 spec、术语规则及怪猎批次审阅经验。
- **做法**：在 docs/spec/rag-prose-writing.md 固定来源分工与联合审阅职责；实质内容批次由写作 Agent 整理、未参与编写的 Agent 复核，人类确定采用目标并处理待裁决判断。已明确的采用范围与决定直接沿用，普通错字和格式调整不强制重复独立审阅。
- **输出**：spec、根 AGENTS.md、inbox 与相关活动引用同步；审阅过程使用现有实施笔记，不新建断言台账。
- **验收**：arknights-base-vault 明确为散文采用来源，toolbox-data 明确为 facts 唯一上游；正文正确性不交给严格机械校验。

### 2. 评估 facts 与解包数据的映射

- **输入**：arkntools/arknights-toolbox-data、当前 11 份 facts 输入、facts 解析与消费代码；现有清洗脚本只作参考。
- **做法**：固定解包提交，按源文件、对象 ID 与字段核对当前 facts 条目。重点分清技能原文、词条内嵌、解锁条件、替换关系、技能等价组的直接来源与转换规则；等价归组不能由名称相似或散文推断。采用必要样本确认转换可行，并核对各输入类别的覆盖，不要求在评估阶段重建管道。
- **输出**：在对应实施笔记形成三项结论：所用源版本与可读定位；11 份输入的覆盖、转换口径及缺口；后续实现范围与立项建议。已有 facts 消费者依赖的类别、概念等人工语义另行标明边界，不能伪装成解包直接字段。
- **验收**：可区分已核对映射、未覆盖项与需实现的转换；每项缺口有处理结论，不靠散文补填机械 facts。只有存在具体管道变更才另立实施计划，并按契约变化判断是否需要 ADR。不新增哈希或指纹字段。

### 3. 明确存量路径处置

- **输入**：现有 base / guides / raw 分工及已完成的主题子目录试点。
- **做法**：本轮不迁移存量正文或来源留档；新增按内容职责选择主题目录。以后出现具体本地维护问题，再从 inbox 单独评估迁移范围。
- **输出与验收**：本轮不迁移的结论及相关引用一致；内容增量与 facts 映射均不等待目录迁移。

### 4. 收束本轮文档与评估

- **输入**：规范同步与映射评估结论。
- **做法**：记录已完成项和遗留范围，核对后续主题批次入口；本轮纯文档变更运行 doc-check 与差异空白检查。若后续另有代码、facts 或关联改动，按其实际触发范围运行既有门禁。
- **输出与验收**：本计划有限交付全部有记录；无未定范围的导入任务混入验收，也不以检查名称代替事实映射证据。施工中的未勾选项仍由 doc-check 按现有规则报告，不为通过检查虚报完成。

## 后续内容批次与依赖

arknights-base-vault 的语料按主题纳入知识库，继续利用已核定的候选与承载评估；具体批次在实施前列清篇目、采用段落与落位，避免按源文件重复导入同一主题。贸易、制造等设施可同批处理相关技能释义与组合分工，办公室／宿舍、其他组合、资源、操作及布局分别收口。新内容可以新建文档与主题分类，不为填满来源目录导入无关内容。

每批执行 docs/spec/rag-prose-writing.md 的联合审阅要求，采用与冲突处理结论记入对应笔记。与已明确事实冲突的正文先核对来源版本和适用条件；对于游戏实践形成的理解，由人类与 Agent 判断是否采用及如何表达，不因当前 facts 缺项而一律拒绝，也不从散文反向生成事实条目。

沿用已交付的索引与 prose-links 格式。只有新增或变更必要关联、依赖关联删减重复事实、改变读取范围时，离线核对相关正文与关联送达；普通措辞调整不强制重复读取。新增文件同步 manifest 与实际受影响的记账；已有关系的数据缺口在原维护位置处理，新关系类型或公共契约变化另走工程入口。不得为了本次采用暗改查询策略。

已完成的试点与清单校准是可复用基础，不要求每批重做 91 篇统计或整库核验。facts 派生管道的后续实现不构成所有散文批次的共同前置依赖；只有当批真正依赖的事实缺口需要处理。内容采用不自动触发模型效果试验。

## 关联 ADR

- ADR-013 — 检索范围、原文扩展与 RAG 内部 facts 附带契约；沿用既有语料登记与送达边界。
- ADR-020 — 散文小节关联事实的引用、提示与显式展开契约。
- ADR-021 — facts 本地输入目录归并与事实出口；上游映射评估保持当前运行时读取边界。
- ADR-022 — 关联格式 v2、scope 与精确技能／概念引用；对象存在性不替代正文判断。
- 本轮只修订来源与内容治理口径，不改变公共契约，不新建 ADR。
