## 目标

复用现有派生脚本，完成 facts 与唯一上游解包数据的映射、差异及必要适配评估，并将已确认的散文增量按三批吸纳到知识库。长期规范、添加工作流与正式 facts 存储迁移方案已落位；新增候选及独立迁移工程不混入本计划验收。

## 非目标

- 不从零重建 facts 派生管道或直接全量更新正式 facts；可用既有脚本临时生成对照产物，评估只确定必要适配与后续实现边界。
- 不整库复制上游，不以目录或篇目数量为导入目标；meta、external、skill、README、镜像及治理材料不作为玩家正文导入，派生脚本与来源清单可供开发复用。
- 不增加散文逐句断言、手写全量事实表或重复校验框架；日常采用不要求付费运行或正确率达标。
- 不调整检索算法、查询指令、工具预算、分类及评分，不实施排班求解或重排存量散文目录。效果优化另见 docs/draft-prose-optimization-workflow.md。

## 架构分析

### 来源、规范与现状

| 对象 | 当前职责与状态 |

| 散文 | lejciy/arknights-base-vault 的总结与本地实践理解进入 knowledge/base、knowledge/guides，由人类和 Agent 联合审阅 |
| 长期规范与流程 | 写作及审阅见 docs/spec/rag-prose-writing.md，术语见 docs/spec/rag-prose-terminology.md；添加、验证与清理执行 skills/corpus-addition/SKILL.md |

既有 facts 检查覆盖结构与关系，check:reference-projection 只检查公共练度说明；prose-links 与离线 read 检查关联和送达。这些检查均不能代替解包映射证据或散文联合审阅。facts 暂缺不自动排除散文，采用时记录依据与关联缺口，不从散文反向补填机械事实。

### 承载与已知冲突

base 承载机制、通则与资源，guides 承载组合、操作、布局与用人；优先补既有正文，确需独立阅读再拆篇或新增主题分类。类别.md、歧义.md 保持原路径与格式，可检索文件须显式登记 manifest 且文件名全局唯一。

历史容量评估为上游 91 篇 / 837 块 / 327,721 字符，比较基准为当时本地 19 篇 / 128 块；不是当前或目标规模。评估未发现单块截断，但大篇分页及关联事实仍影响读取范围。采用时组织可独立理解的小节，核对实际送达，不据此提高工具预算或宣称问答收益。详细测量及其口径更正见 docs/plan-corpus-cleaning-and-pilot-notes.md「全量上游散文承载评估」及「评估口径更正」，无需每批重测整库。

已有冲突随采用段落处理，沿用已确认判断；发现新矛盾则按来源版本和适用条件联合审阅，不默认本地或上游总是正确：

- 贸易：特别订单的“隐含赤金”是等效价值，不能写成实物新增；龙舌兰的第三席区分完整与过渡形态；叙拉古、喀兰、格拉斯哥等中枢“四选一”是席位方案，不能写成技能硬互斥。
- 制造：重算自动化组“档 2 约 110%”与配合意识的错误算例；分别核对流程优化的清除范围、自动化与权变的例外，不合成统一规则。
- 辅助设施：菲亚梅塔保留恢复排除与操作顺序，不直接采用永续或代睡优先分公式；“会客室唯一追求速度”“絮雨刚需琴柳”“按消费水平固定选人”改为有场景和条件的取舍。
- 共用边界：散件筛选线（上游 35% 与本地 40%／35% 分档）、类别数量（上游 82／29 与本地 81／28）不机械对齐；建设文的不可降级限制与矛盾改建示例按具体依据处理。加工站“心情是唯一投入品”已不采用，既有正文保留原料与加工费，不重开整批审稿。

## 实施方案

### 1. 复用已落位规范与迁移方案

写作、术语及添加流程直接执行两份 spec 与 corpus-addition skill；ADR-024 和独立迁移计划已明确 facts/raw 分离方案。此步骤已完成，不重复编写流程或扩大为实际迁移；实际状态以对应计划为准。

### 2. 复用现有脚本评估映射与适配

- **输入**：上节固定版本链路、本地 11 份输入及 facts 解析消费代码；直接复用已核对的脚本和来源记录，不重新选型。
- **映射与对照**：核对源文件、对象 ID 与字段到技能原文、术语、解锁、替换及等价组的转换。按需要复用数据转换、清洗与全量渲染，在 dev-temp/work/facts-mapping 下生成临时对照，不覆盖正式输入或来源工作副本；镜像 JSON 是中间产物，不能替代第一段字段映射核对。用代表性样本确认转换，并对 11 份输入的覆盖及差异形成结论。
- **适配范围**：区分上游版本增量、文本格式差异、转换规则及本地消费者要求。本地名册为 425 名，镜像来源清单为 429 名，这类数量差异先按版本解释，不直接认定错误或强制同步。列明补充标签、外部成员名录的采用边界，以及格式、路径、公共练度说明和解析关系的最小适配；不照搬整套站点生成与校验流程。
- **输出与验收**：notes 记录固定源与脚本版本、11 份输入的映射和对照结果、可直接复用部分、必要适配及未覆盖项的处理结论。已有差异工具足够时直接使用，只补实际缺口；不新增逐条证明台账、哈希字段或一套平行门禁。实际管道接入或正式 facts 更新另定明确范围，按契约变化判断 ADR；临时产物按 scripts/INDEX.md 收束。

### 3. 按设施吸纳三批内容

- **输入与顺序**：按「本计划实施批次」处理贸易、制造、基础与辅助设施。三批不互设前置；跨批共用段落在首次涉及时确定落点，后续补增量。facts 映射评估与目录迁移不作为全部散文的共同前置，只处理当批实际依赖。
- **执行与记录**：每批使用 corpus-addition skill，从选取段落推进到审阅、验证、清理，在现有 notes 记录来源、采用内容、落点、冲突与结果；不另建逐篇计划或证明表。同版本沿用已有清单和对照，来源更新时仅核对相关文件差异；可直接读取固定副本，不强制复制到 raw。
- **改写边界**：将外部链接改成本地定位或自包含表述，去除目录编号、治理指令及外部元数据。操作步骤、先后关系、适用条件与必要不确定性按内容保留；移除 draft 标记不等于结论变为确定。段落、条目或紧凑表格由内容决定，不统一删除步骤或短段。
- **输出与验收**：增量正文及必要关联落位，manifest 与实际受影响的定位、计数同步；按 spec 完成独立 Agent 复核与人类参与，运行 skill 指定的适用检查和必要离线读取，清理本批临时材料后勾选该批。已交付内容复用，同源新段落由本批收束。

### 4. 收束交付

核对映射评估与三批采用记录，更新 inbox 和实际受影响入口；按变更类型执行既有门禁，文档部分运行 doc-check 与差异检查。未完成项保持未勾选；新候选不混入本轮完成条件。纯计划修订不代表正文吸纳、facts 迁移或材料清理已实施。
