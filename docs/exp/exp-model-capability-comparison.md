## 过程

### 问题与硬约束

比较三模型在当前 harness 下的证据获取、条件理解、事实忠实度和完整作答表现，并区分检索不足与证据送达后的回答错误。结论限定于本知识库、题集、接口及资源预算，不宣称模型通用能力上限。

用户最新澄清覆盖先前的全体 off 要求：`glm-5.3-flash` 显式开启思考并设置 `reasoning_effort: "low"`；`hy3`、`qwen3.7-flash` 仍显式关闭思考，其余方案不变。不得用 GLM-5.3 替代 Flash，或把 GLM low 描述为关闭思考。Hy3/Qwen 不得以隐藏 reasoning_content、提示词“不思考”或省略参数代替关闭。设计阶段仅修订方案并送独立审查。用户随后授权执行；必要 provider 适配和付费预检已完成，180 次主试验及匿名核查已完成，检索、提示词、知识库与核查规格保持不变。

本轮比较的是 GLM low、Hy3 off、Qwen off 三种指定配置在当前 harness 下的表现；模型和思考模式同时存在差异，不能将差异单独归因于模型权重，也不能称三模型无思考对照或等推理算力对照。

### 协议可行性与执行前提

| 模型 | 显式思考参数要求 | 当前状态 |
|---|---|---|

依据：[GLM-5.3-Flash 官方文档](https://docs.z.ai/guides/vlm/glm-5.3-flash)明确说明不能关闭思考；[TokenHub 协议](https://cloud.tencent.cn/document/product/1823/135872)给出显式 disabled；[百炼 Chat Completions 协议](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)给出 enable_thinking 控制。不同地区或产品的默认值不作为本试验依据。执行时重新核对实际服务端点的契约，记录请求模型名、返回模型名和服务日期。

设计阶段 key 平台未知；执行时用户确认智谱国内站，模型权限已由预检验证，账户实付与套餐优惠仍未知。密钥只能由既有 secret/env 机制读取，不输出值、前后缀或指纹，不向猜测的第三方端点发送。

三方主试验须核验实际端点支持 GLM enabled/low 与 Hy3/Qwen off，禁止静默回退到服务默认档位。HTTP 200、未返回思考文本或 reasoning token 字段缺失，均不能单独证明已关闭或实际档位；结合端点契约与实际发送参数核对，不可知项标未知。不得仅跑另外两家后称三方对比。

GLM 的思考 token、耗时和费用一并计入资源消耗；核验该端点 max_tokens 是否包含思考，并记录 4096 上限给正文带来的截断情况，不为 GLM 单独放宽上限。当前 Agent 不回传 reasoning_content；预检须验证 GLM 在该消息历史策略下的多轮工具协议能否成立，缺少必要字段时停止并路由最小协议适配。若需改变思考历史策略，记录具体差异，不静默改变其它模型或将其称为共同不变条件。

实施前另从 inbox 路由必要的 provider 工程任务到 plan，按架构判据判断 ADR。工程范围只包括模型注册、显式参数映射、usage/计费兼容及相关验证；不夹带质量优化。适配完成后，三模型都在同一个新代码基点运行，不能拿旧 Qwen 结果与新适配结果直接比较。若契约无法满足，停止该配置，记录兼容性结论，不记为知识问答能力失败。

### 样本、轮次与执行顺序

1. **无付费准备**：完成必要适配的 typecheck、test 与 dry 验证，检查真实请求构造、工具消息往返、终止状态、usage 缺失语义和模型标识；dry 不能证明远端接受或按指定思考模式执行。
2. **协议预检**：仅在执行条件满足且获得执行任务后，每模型 2 个非正式题会话，分别检查文本回答与真实工具调用后续答，共 6 会话。不计入主试验。任一模型未获得真实工具调用及后续答复的成功往返证据，视为预检未通过，三方主试验暂停；不自动追加请求或改变主试验 tool_choice。鉴权、型号、指定思考模式或工具协议失败时不进入主试验。
3. **主试验**：使用现有 [20 题](../../../bench/questions.json)，fact 10、system 8、gadget 2；每模型完整运行 3 次，共 180 个单题会话。重复 3 次用于观察稳定性，不宣称 60 个独立问题，也不将预检混入。
4. **配对交错**：各轮题序一致，按题依次跑三模型；轮 1 顺序 GLM/Hy3/Qwen，轮 2 Hy3/Qwen/GLM，轮 3 Qwen/GLM/Hy3。每次只有一个会话在途，减少限流干扰。调度复用现有 runner/agent，不重写 loop；临时调度产物按收尾约定清理。
5. **不挑结果**：保留全部预定样本的成功、超时、截断、空答、协议错误及重试汇总。基础设施重试按原规则；不为答错单题重跑。中断后记缺测，恢复不得覆盖已完成结果；整轮作废须说明独立的协议或输入污染依据。

原 20 题已参与历史观察，只能支持现有题集上的对照。本轮不优化，因此不额外制造留出题附件；任何后续质量优化须重新取得未参与调优的验证问题，并在对应 exp 内记录必要范围和结果。

### 评阅与能力边界

统一使用 [spec v4](../../spec/rag-answer-baseline.md)，先核对与执行时知识库一致性。当前正式质量基线未指定，既有 v4 运行仍有独立审定事项，不将其历史成绩当真值。参考答案、spec 和 gold 不送入端到端查询 Agent。

评阅时隐藏模型和轮次标签，按题打散答案；先完成质量核查，再查看轨迹归因。逐项遵守 spec 的满足/遗漏/冲突/待核验及整答“完整且有据”规则，同时检查所有额外断言。不得新设数字权重、及格线或用文风长短替代质量。争议判定由第二次独立复核核对真源和必要摘录；未审定项明确保留，不使用参测模型自评分作为唯一判据。

| 观察层 | 必须区分的证据 |
|---|---|
| 服务与协议 | 鉴权、限流、工具协议、空响应；这类失败单列，不推断知识能力 |
| 工具使用 | 合法参数、有效/空查、查询名称偏差、read_section 续读、预算耗尽、重复取证 |
| 证据送达 | 必答项的充分证据是否实际进入该次消息；全库有记录、topK 命中或 gold 命中不等于送达 |
| 理解与推导 | 充分证据送达后仍遗漏、混淆实体/设施、错用条件/替换关系、计算错误或无依据外推 |
| 资源限制 | 4096 截断、300 秒超时与无最终回答，不能直接宣称模型能力上限 |

证据不足与理解失败允许共同出现；没有充分轨迹证据时标归因未知。本文结果记录每题三个模型各三次的简明判定，以及支持关键差异的必要原答摘录和来源定位，不转储全部回答或思考文本。

**可选的固定证据诊断，不自动执行**：若主试验仍难区分检索与理解，可对预先指定的 F02、F09、F10、S04、S06、G01 做额外诊断，覆盖字段、练度、局部规则、组合、跨设施与条件型散件。由真源选择充分的原文小节，三模型收到相同文本和顺序，不使用 spec 答案改写或针对某模型补证据。每模型每题 3 次，共 54 次单次生成，沿用 GLM low、Hy3/Qwen off 与响应上限。该探针无自主检索，明确区别于原 harness 主试验；改善只能支持“给定证据后的表现改善”，不能把差值全归因于检索或声称图结构必然有效。若证据超出预设范围，先记录无法公平构造，不能静默放大上下文。

## 结论

在本轮当前 bm25 harness、20 道已知题、GLM low / Hy3 off / Qwen off 配置下，GLM 的完整性与事实冲突指标较好，代价是约 22.5 秒的中位会话耗时；Hy3 约 9.2 秒，完整性次之；Qwen 约 8.7 秒且总费最低，但含冲突回答明显更多。三者均有大量条件遗漏，不能据此宣布任一模型已足够覆盖本知识库，也不能将严格完整率改写成通用正确率或能力上限。

这轮结果为最初的 graph 方向提供了**可验证的局部问题**：实体名消歧、类别成员与技能引用分离、技能的设施/解锁/计数/排除条件可作为结构化关系候选。它没有证明“训练偏现实导致内部向量偏离游戏”，也没有检验 graph 的因果收益。当前检索是 BM25，不能用本轮表现直接诊断嵌入向量。已有实体/规则真源未被主动取得、正确证据送达后仍误推、指南层回答缺机械细节三种情况并存；仅把语料改成图未必解决后两类。

若后续获授权，先利用现有真源做相同证据的固定上下文诊断，区分补证与理解；再在未参与调优的问题上比较实体/类别/条件关系的结构化入口与当前方式，评估覆盖、错误、延迟和维护成本。此处是后续建议，未运行可选探针、未实现 graph、未调参追分，也未切换默认模型。

局限：仅 20 个历史题，没有留出集；三次重复不独立；评分为人工初审加争议复核，轮次未盲且有文风泄露可能；仅四个案例检查逐项证据送达；思考配置、provider 并行开关、默认采样、tokenizer 与缓存均有差异；实付账单和服务端内部档位无法独立核验。完整率/冲突率仅对当前配置和判据成立，不作显著性或通用排名承诺。
