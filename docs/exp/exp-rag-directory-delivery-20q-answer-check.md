## 过程

### 目的与范围

观察 ADR-023 目录树送达（命中行 100 字原文预览、仅命中行与文件根行带可调用 ID）在真实模型下的成本与取证行为，并按 docs/spec/rag-answer-baseline.md v6 做一轮逐题回答核查。关注三点：

- 成本与送达面：RAG 与 read 两侧送达字符、工具成功额度消耗、调用序列与终止原因、费用与耗时。
- 导航行为：模型是否使用 read 返回的「父级范围」ID 逐级爬升、是否改为读取整篇、是否出现同一 ID 重复读取。
- 覆盖：v6 必答编号的「满足／遗漏／冲突／待核验」与额外断言审查。

只观测与记录：未修改题集、gold、spec、语料、提示词、检索、facts、预算或 agent loop；未因答错重跑或追加轮次；未设达标线；未登记 bench/results 快照、未修改质量基线表。结论未经人工独立复核，不称最终结论，也不指定正式质量基线。

### 方法

- 运行：`pnpm run build` 后执行 `node dist/cli.js run --provider glm --thinking low`，真实付费请求；费用与耗时以 meta.json 实测为准，不预设额度。
- 送达面观测：读 trace.jsonl 逐条 tool_call（hitIds／injectedIds／fragmentRanges／readDelivery）与 meta.json，不凭知识库是否存在推断；对 read 调用判定其目标 ID 是否由本次运行此前的 rag_search 给出，分别统计「读命中行」「读整篇（doc:）」「重复读同一 ID」与 read 返回的父级范围是否被继续使用。
- 回答核查：逐题读 answers.md 全文（含自加例子、括注与额外名单），按 v6 必答编号判定状态；判定从严，编号要求的具体条件或数值未给出即记遗漏，不因「可反推」折算为满足。20 题分组由只读子代理执行，主代理汇总并对影响结论的冲突项回读 knowledge/raw/ 复核。
- 自加例子、括注与额外名单另记「未见冲突／存在冲突」与「有无未证实断言」；同一题全部必答项满足且额外断言无冲突、未证实或待核验时记「完整且有据」。
- 拟执行：运行与核查完成后回填「结果」与「结论」，并在结论中记录临时产物清理情况。
