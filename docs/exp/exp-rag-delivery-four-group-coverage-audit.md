### 方法

派生 12 个独立、上下文隔离子代理并行执行（每 run 一个：8 个用于四组对照，4 个用于补测；先例 exp-glm-low-20q-hybrid-recheck-v2.md 以 5 个子代理核查 1 个 run）。子代理 prompt 自带仓库与 spec 路径、目标 answers.md、trace.jsonl/injected.json 路径、判定口径与输出结构（逐编号 S/M/C/U + 原答摘录 + 判据 + 额外断言 + 完整判定 + 局限），逐题详细结果落至 dev-temp/work/four-group-coverage-audit/ 下按 run 命名的审计文件；补测子代理沿用同一 prompt，并对「纯澄清/否定型条件」（原答未作出错误断言即记 S）作了显式口径规定。主代理按重要度复核影响结论的关键项（四组：S06 夕方向、G02 梓兰档位、S03 映射与练度归属、S07.3 触发条件、S08 计数、F03 归组；补测：S03 表述范围、F05 档位、S08 练度），并更正一处子代理误判（见结果）。

送达归因以该题 trace.jsonl 的 tool_call（injectedIds/fulltextRanges/writtenContent）与 injected.json 为准。注意：injected.json 未收录 facts_search 记录卡与 read_section 返回内容，单看会低估送达量；G3/G4 开启原文扩展时 fulltextRanges 可能为空串，正文以父级整篇形式出现在 writtenContent，故送达判定以 writtenContent 文本命中为准。

### 判定口径与边界

- 按 spec 使用口径：一条必答项列出的条件均须满足，语义等价的自然语言接受；额外断言含冲突/未证实/待核验则不计「完整且有据」；事实层以 references/base 为准，库内缺依据记待核验，未证实不等于已证伪；旧展示名只记命名规范偏差，指向错误干员/成员/设施才是事实冲突。
- 边界口径差异：对「纯澄清/否定型条件」（如 F05.2「45% 是技能加成非含基础 5% 的总值」、F06.1 人数来源、F09.1「初始解锁=精零」、S01.3、S02.5/2.6、S03.2、S07.3、S08.3、G01.1/1.4），各子代理口径不完全一致——一种以「回答未作出该错误断言」记 S，另一种以「未显式覆盖」记 M。该差异主要落在 F05.2、F09.1、S01.3、S07.3、S08.3、G01.4 等边界项，使 S/M 计数带口径敏感性；本记录保留各子代理口径，不做统一改写。
