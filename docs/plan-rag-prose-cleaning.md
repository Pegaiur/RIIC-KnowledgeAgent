# RAG 散文清洗与索引组织计划

> 创建日期：2026-09-04
> 状态：施工中
> 下游：`docs/draft-facts-quality-iteration.md`（质量闭环在本计划完成后执行）

## 目标

把现有推荐散文清洗为适合 BM25 RAG 检索的玩家知识：删除外部项目实现与过程噪声，按少量主题文件和自然标题组织组合、培养与散件内容，并在人工通读后替换语料白名单中的旧 recommendation 文档。

## 非目标

- 不新建清洗台账、claim ledger、文档 schema、额外索引文件或索引生成器。
- 不修改 `knowledge/references/`、facts 记录卡、lookup/query_operators 或既有确定性门禁。
- 不在本轮重制 F01–F10/G01–G02 spec，不运行 12+5 正式评测；若发现 spec 与 `knowledge/references/` 直接冲突，只做最小一致性修正，并在实施笔记中记录。
- 不把 Rust、BFF、Redis、Python narrator、前端协议或其他外部项目实现迁入 RAG 语料。
- 不借清洗工作补做 S 类完整体系评测、`minEff` 数值化或 references 再生脚本。

## 架构分析

当前 `knowledge/recommendation/` 混合了玩家知识、产品策略、外部项目实现、历史状态与待办说明。`knowledge/corpus-manifest.json` 已把其中 `组合知识库.md`、`高效率散件与搓玉名单.md`、`新手必练与必收集名单.md` 纳入 RAG，因此 hybrid 查询可能检索到与当前仓库无关的实现描述或未经现有 references 重新核对的旧结论。

现有语料加载器已经按 `##` / `###` 标题切块，并以 `maxContextChars=12000` 作为上下文预算。清洗无需新建复杂索引体系，只需让文件名、一级标题和二三级标题直接表达玩家检索主题，并保证每个标题块可以独立理解且不被预算截断。

机械事实仍以 `knowledge/references/` 为唯一真源，机制公式以 `knowledge/base/` 为准。清洗后的散文主要承载组合用途、适用条件、协作原理、缺人替代和不适用场景；精确技能原文、完整持有者名单和动态分类继续由 facts 工具回答。

实施中还必须同步当前消费者路由：`knowledge/SKILL.md` 仍指向已经删除的 `docs/0-规则/`、`docs/2-体系/`、`docs/4-散件工具人/`，只切换白名单而不更新该入口会使 RAG 内容可检索但问答技能仍走失效路径。

## 组织形式

新增 `knowledge/guides/`，只建立五篇可检索成品：

```text
knowledge/guides/
├─ 贸易站组合.md
├─ 制造站组合.md
├─ 跨设施组合.md
├─ 新手培养.md
└─ 高效率散件.md
```

- 组合类文件按组合名称使用 `###` 标题；旧称或常见别名直接写在标题或开头一句，不维护独立别名索引。
- 每个组合块只保留：用途、适用条件、成员与分工、运作原理、缺人替代、冲突或不适用情况。
- 新手与散件文件按设施或用途使用 `##` / `###` 标题，不复制完整技能表。
- 不添加 YAML frontmatter、文档 ID、标签表或额外元数据层。

## 清洗规则

### 保留

- 玩家能直接使用的组合、培养与散件结论。
- 解释结论所需的设施条件、核心成员、关键练度、协作原理和缺人路径。
- 有助于检索的规范名、旧称和常见别名。
- 对选择有决定作用、且能由当前 `base/` 或 `references/` 核对的关键数值。

### 删除

- Rust、BFF、Redis、Python、前端、CLI、接口、缓存和部署描述。
- `data/*.json`、外部仓库路径、不存在的相对链接和旧实现状态。
- C1/T9 等内部裁决编号、阶段进度、TODO、交接和验收说明。
- 推荐人数上限、前端展示顺序等产品输出策略。
- 与 facts 重复的完整技能原文、完整干员名册和大段机械枚举。

### 核对

- 干员规范名、设施、练度、技能升级/替换、派系、技能类别和等价组直接对照 `knowledge/references/`。
- 设施公式和基础机制直接对照 `knowledge/base/`。
- 机械事实与关键数值必须由当前 `references/base` 确认；已批材料只承载玩家判断，且不得与机械真源冲突。`组合成员练度审阅稿.md` 可作为已批判断材料，但不是机械事实真源。
- 每个 `##` / `###` 块应能脱离上下文独立阅读，避免只写“同上”“见前文”。

## 实施方案

1. **首轮散件试点**：以现有 `knowledge/recommendation/高效率散件与搓玉名单.md` 为输入，生成未登记到白名单的 `knowledge/guides/高效率散件.md` 候选；保留玩家判断、成立条件和身份边界，删除实现、报告策略和内部裁决噪声。办公室章节按 `knowledge/references/技能-办公室.md` 补齐可核验的联络散件，并排除 references 未登记办公室技能的焰狐龙梓兰。
2. **首轮人工通读**：由用户逐段确认候选稿的事实冲突、条件是否被过度压缩、重复维护、内部术语和遗漏项；审查结果追加到实施笔记，并据此固定后续四篇的清洗规则。首轮审查未完成前不批量清洗、不切换白名单。
3. **清洗组合散文**：以现有 `knowledge/recommendation/组合知识库.md` 与已批审阅材料为输入，提取仍有用的玩家判断，按贸易站、制造站、跨设施三个主题改写为 guides；逐项以当前 references/base 修正成员、练度、设施和互斥关系。输出 `贸易站组合.md`、`制造站组合.md`、`跨设施组合.md`。
4. **清洗新手散文**：以现有 `knowledge/recommendation/新手必练与必收集名单.md` 为输入，整理为一篇短文，保留选择理由和条件，删除外部实现及产品输出规则。输出 `新手培养.md`。
5. **消费者与结构导航同步**：将 `knowledge/SKILL.md` 的机制、体系、散件和布局路由切换到 `knowledge/base/` 与 `knowledge/guides/`；更新 `AGENTS.md` 的仓库结构说明，标明 guides 是经审定的 RAG 散文；同步修正受影响的加载器注释或旧路径说明，不改变运行时接口。
6. **人工通读与收缩**：五篇成品完成后由用户逐篇确认事实冲突、重复维护、内部术语、失效链接和依赖上文才能理解的片段；未确认或无法核验的内容删除或收缩表述。人工通读未完成前不得切换白名单。
7. **原子切换白名单**：五篇均通过通读后，在 `knowledge/corpus-manifest.json` 中用 `guides/` 成品替换三篇旧 recommendation 文档，不整目录放行。同步更新 `bench/tests/corpus-allowlist.test.ts` 的批准集合，断言 9 篇 base、14 篇 references、5 篇 guides 被加载，旧 recommendation 成品不再加载。
8. **现有管线验收**：运行文档一致性、类型检查与测试；使用现有检索器的聚焦单测，以少量代表性问题确认组合规范名、旧称、新手与散件主题能命中正确标题块，且不会检索到外部实现内容；同时确认目标块没有被 12000 字符上限截断。验收不依赖当前停用的 hitrate gold。
