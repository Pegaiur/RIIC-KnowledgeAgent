### 范围、方法与证据边界

两份快照均为 20/20 `completed`，题号和顺序均为 F01–F10、S01–S08、G01–G02，答案数量相同。固定 spec v4 含 72 个必答编号；本轮逐份读取 A/B 的 40 份原答，复核 144 个编号、原答全文的额外名单/公式/范围断言，并逐题核对 trace 中真实 `writtenContent` 与 `injectedIds`。旧 v3 报告和其中的汇总不用于继承标签。

判定采用 v4 的四种编号状态：

- **满足**：原答覆盖该编号列出的全部条件，语义等价也算满足。
- **遗漏**：原答没有覆盖题目要求的已知条件；不把可选补充的未出现当作遗漏。
- **冲突**：原答对该编号要求的事实、范围、练度或边界作出不相容断言。
- **待核验**：原答给出涉及当前未消解来源映射或条件的结论，现有证据不足以安全落定。

“必答状态”和“额外断言”分开记录。额外断言即使不改变该编号的覆盖状态，也会阻止该题被称为“完整且有据”。清楚标明旧称或语义无歧义的简称可接受；仅使用旧展示名可记命名规范偏差，把名称指向错误实体则是事实冲突。

证据送达核对使用快照中的 `injectedIds`、两个 runId 对应的 `injected.json` 及 `records.jsonl`，不凭知识库存在与否推断模型是否收到证据。两份结果的 `injectedIds` 与对应 `injected.json` 逐题完全一致；两个原件目录的 `answers.md`、`injected.json`、`records.jsonl`、`trace.jsonl` 均存在。

证据：[`机制-发电站#无人机充能速度`](../knowledge/base/机制-发电站.md#无人机充能速度)、[`技能-发电站`](../knowledge/references/技能-发电站.md)。

**A**

- **F01.1 满足**：原答“无干员加成时，每架无人机的基础充能时间为6分钟”。
- **F01.2 满足**：原答给出“有工作干员则 `B_i=0.05+Y_i`，无工作干员则0”，并说明注意力涣散不算、5%每站一次。
- **F01.3 满足**：原答给出所有站相加 `B=ΣB_i` 和 `6/(1+B)` 分钟/架，并说明百分比代入小数。
- **额外断言**：示例“电站A进驻异客和一名普通干员”违反发电站每站1个进驻席位；“多数通用干员+10%”过于泛化，未作为本题必答事实采纳。

**B**

- **F01.1 满足**：原答明确“每架无人机需要6分钟”。
- **F01.2 满足**：原答逐项写出工作状态、`0.05+Y_i`、注意力涣散和每站只计一次。
- **F01.3 满足**：原答逐项写出 `B=ΣB_i` 及 `6/(1+B)` 分钟/架。
- **额外断言**：表格把 GALLUS²、CONFESS-47、异客、格劳克斯分别写成“加洛德、告密者、Reed、Gladiia”等错误或无法由当前实体对应的映射；当前 references 的实体标题是 GALLUS²、CONFESS-47、异客、格劳克斯。计算示例本身没有 A 的双人站位问题。

#### F02 制造站生产力、心情与仓库

证据：[`机制-制造站#生产力与心情消耗`](../knowledge/base/机制-制造站.md#生产力与心情消耗)、[`机制-制造站#仓库容量与制造流程`](../knowledge/base/机制-制造站.md#仓库容量与制造流程)、[`机制-后勤技能结算#先区分结算对象`](../knowledge/base/机制-后勤技能结算.md#先区分结算对象)、[`技能-制造站.md`（泡泡条目）](../knowledge/references/技能-制造站.md)。

**A**

- **F02.1 遗漏**：原答只写“`1+X+Y`”和“100%加技能百分比”，没有给出 n 为有效工作人数、每人+1%及三级三人时才有3%人数项。
- **F02.2 遗漏**：原答把心情作为独立字段并写基础消耗，但没有给出计量表 `1-X-Y`、1/2/3人对应0/0.05/0.1及中枢项。
- **F02.3 满足**：原答明确容量与生产力独立，只有特定技能明确转化时才关联。
- **额外断言**：把泡泡“大就是好！”写成精二；references 明确为精一解锁。火神、石棉的容量/心情示例与当前条目基本一致；A 的示例没有 B 那种把 −0.2/小时直接写成总心情消耗的断言，但这不抵消 F02.2 的遗漏。

**B**

- **F02.1 遗漏**：原答写“`1+X`”，但没有定义 n、有效工作状态和三级满员3%边界。
- **F02.2 遗漏**：原答说明字段独立，却没有给出计量表人数项、Y减免和自身心情变化不计入面板的完整关系。
- **F02.3 满足**：原答明确容量不是生产力，只有技能明示时才转化。
- **额外断言（事实冲突及遗漏）**：泡泡精一和“仓库容量→生产力”的转化方向写对，但原答把“若其技能提供 −0.2/小时，则每小时心情 −0.2”直接当作每小时总消耗。当前机制的心情面板按 `1-X-Y` 计量，干员自身技能造成的心情变化不计入该面板，实际消耗可能不同；该处是事实边界冲突，不是单纯遗漏。“每格1%–3%”也未展开当前制造站内干员作用范围及提升16格以下/大于16格的分界。
