# 提示词与 tool schema 优化实施计划

> 创建日期：2026-09-07
> 状态：施工中（实现与本地验证完成，待用户验收）
> 需求入口：[inbox](inbox.md)
> 前置：[facts 计划](plan-facts-tool-optimization.md)、[验收与单次对比](plan-facts-tool-optimization-notes.md)

## 目标

使提示词的取证与停止策略、工具 schema 描述和已有执行契约一致，减少调用决策和参数构造歧义；不承诺真实模型成功率或成本改善。

## 非目标

不改工具名称、输入字段/类型/required/anyOf、查询实现、facts 结果协议、宿主 agent loop、预算、provider 或知识事实。不实施 enum、值域发现、分页、别名、grep 行为调整、strict 模式或付费模型实验。候选分析中的后置项均不属于本计划施工范围。

## 架构分析

核对基点 `2e31fa6`。有优化空间，优先消除停止条件歧义和 schema 与实现之间的表达落差，再去重人工指令。保留四个独立工具、扁平 arguments、现有本地校验、auto、5点预算与查询算法；不以 facts 调用占比提高为目标，不重新处理已修复的空查状态。

依据为 knowledge/AGENTS.md、agent.ts 的 buildSystemPrompt、tool-executor.ts 的定义与校验、facts/store.ts 的匹配逻辑。历史样本提示指纹不同，不能从单次费用或延迟推导本轮设计。以下收益属于待验证假设，不宣称能提高成功率。

## 实施方案

### 1. 校正工具描述

只修改 tool-executor.ts 中 lookup/query_operators 的 description 及字段描述；已有 rag_search/grep_search 定义保持。以以下文字为语义依据，可精简措辞但不得扩大匹配能力或改变输入校验。工具 schema 版本从3递增为4，factsResultVersion 保持1；更新 runner/schema 版本相关断言，指纹仍由实际工具数组生成，不手写固定 hash。

能力说明不新增参数拒绝：lookup 拼接名称、完整等价组标题或 termQuery 多词串只要是合法非空字符串仍会执行并扣1点，未被索引/未匹配时返回 empty。termQuery 若原文确有包含空格的完整连续子串，仍应命中；“不拆词”不等于“含空格必空”。旧运行和快照的版本、指纹均不回写。

### 2. 统一人工指令与预算表达

修改 knowledge/AGENTS.md 的唯一人工指令源；agent.ts 仅修改运行能力块的预算说明，不新增第二份人工决策提示。先建立以下旧条款映射，再合并重复条款：

| 旧条款 | 新规则必须保留的含义 |
|---|---|
| 1 | 领域限制及不展开战斗、关卡、抽卡和战斗练度 |
| 2 | 识别对象、数值口径及缺失前提；多事项分别取证 |
| 3 | 只使用当前已暴露工具；按证据缺口路由；缺失工具回退；独立调用可同批、依赖结果分批、call ID关联。参数 JSON 移交 schema，不保留重复样例 |
| 4 | 只依工具证据；冲突优先直接且对象明确的记录，说明出入；未查到不等于不存在 |
| 5 | 制造/贸易侧口径，解锁、提升、对象、范围、叠加、替换、归零、清除；组合总效率不冒充成员固定值 |
| 6 | 只用已有数值和可解释的简单估算；缺参数不补模型、不反推用户配置 |
| 7 | 中文、先结论后条件与未知；停止策略按本节重写；不重复无效查询 |
| 8 | 具体对象先取证；不同对象、不同设施或相邻片段不能互相替代；与第2条合并但不丢约束 |
| 9 | 保留第5条之外的“不得把不同效果合成未经支持的总收益” |
| 10 | 最终结论和数值须有证据；缺参数明确未知，与第6条合并 |

运行块保留动态工具列表和配置预算，不把5硬编码进文字：每个准入工具调用占1点，参数错误也占点，同批分别扣点；余额用尽后新增调用不会执行。缺失/重复 call ID 的整批协议拒绝仍不扣点，宿主逻辑不变；“每个调用都扣点”不是允许的简写。

### 3. 选定措辞与边界

人工指令的路由与停止条款（其余规则按上表合并）：

> 按尚缺的证据选择本次已暴露工具：查精确对象的技能事实优先用 lookup；筛选候选干员集合优先用 query_operators；查机制、组合关系与取舍优先用 rag_search。若当前模式没有对应工具，使用已暴露的工具查证其能覆盖的部分；无法覆盖的关系或建议明确说明未知，不凭记忆补全。已有工具证据足以支持当前结论时直接回答，无须为满足工具偏好重复查询。相互独立的证据需求可以同批查询；依赖上一结果的查询分批进行，并按 call ID 对应结果。
>
> 空结果只表示本次匹配未找到记录。有剩余预算且已有线索支持另一条查询路径时可以继续；证据足够、预算用尽或没有有依据的后续路径时，用已有证据作答并说明未覆盖部分。不要重复提交同一无效查询，也不要把未查到写成游戏中不存在。

lookup.description：

> 用精确名称读取干员完整记录卡。支持干员正式名、技能名（含等价组内技能名）及已收录技能组词；一个名称可能返回多位持有者。不做模糊或子串匹配，不会把拼接的多个名称拆开查询。机制和组合关系优先用片段检索工具（若本次已暴露）；无可用证据时说明未覆盖。

lookup.term：

> 一个干员正式名、技能名或已收录技能组词；保留名称中的标点。不要传整句问题或等价组完整标题。

query_operators.description 增补（保留精确/子串/多字段交集/至少一个正向条件）：

> 未用字段省略，不传 null；字符串字段不得为空或仅含空白。分类值须精确；未知值可能合法但无匹配。返回匹配干员卡集合，技能文本按查询投影；不按效率排序。

termQuery：

> 一个连续关键词或短语，按字面子串匹配，不拆词或解释查询运算符。检查名称及技能等字段；设置 room 时只检查该设施技能，多设施卡的全局技能组和备注不作为该设施的命中依据，名称匹配仍有效。

不在常驻提示中重复解释结果的每个字段；query_operators 输出已有范围说明。若补充 complete 的解读，沿用“本次过滤的卡集合完整，不保证每卡所有技能都展示”，不要说成知识库或答案完备。

## 后置项与不建议项

- room/profession 当前真实投影分别有9/8个值，可评估由权威分类定义生成提示值域。优先只展示合法值，避免直接加 enum 将原本合法空查改为参数错误；硬枚举必须与本地校验、未知值契约一起定稿。faction 不塞入长名单，也不增加发现工具来解决尚未证实的高频需求。
- grep_search 在 both/grep 模式应说明它是片段检索、不是 shell grep 或正则接口；当前会分词并回退 bigram，不能承诺严格短语搜索。其200字符上限会导致长查询返回空集，后续如暴露 maxLength 应同步考虑本地拒绝语义；不顺带改变本轮 hybrid。
- 不再次拆分 query_operators，不将可选字段全部改成必填 nullable，不移除 anyOf，不新增计划、自评、置信度字段。没有兼容性证据，不引入 provider strict 模式或假定服务端执行本地全部约束。
- 不提高预算、不恢复 required、不规定每题必须 lookup、不建立固定 RAG→facts 链。RAG 已返回直接事实时，重复事实查询可能只增加成本。

## 验证方案

1. 先做 schema 描述准确性：termQuery、省略可选字段、lookup 输入范围。输入形状不变；检查当前合法/非法输入结果不变，并同步 schema 版本与指纹。
2. 再单独调整人工指令的路由、停止条件与重复规则，列出旧条款到新条款的对应关系；运行能力块只生成工具列表和准确预算事实。停止条件是策略变化，不混作纯压缩文字。
3. 确定性验证覆盖如下。复用已有测试，有覆盖才不重复新增；不对整段提示措辞写快照式断言。
4. 如另获跑测授权，先固定当前正式提交与指令为对照，描述改动和策略改动分组评估，使用未参与本次设计的问题并保留全部结果。观察参数合法率、空查后的有效取证、重复查询、证据覆盖与无依据结论，同时记录 token 和成本；不以调用分布或答题分数设强制达标线。
