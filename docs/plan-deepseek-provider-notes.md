# 实施笔记：DeepSeek provider

> 对应 spec：[适配计划](plan-deepseek-provider.md)
> 开始日期：2026-09-09

## 决策偏离

沿用用户同配置要求，DeepSeek 显式 off；GLM low 为上一轮特例不推广。价格注册使用高峰价上界，exp 根据请求时间另核算空闲/高峰估算；不为此引入通用分时计价引擎。

## 实现调整

已注册 provider 并兼容 prompt_cache_hit_tokens；显式无效嵌套缓存值不被兜底掩盖。类型检查、355 项测试、构建、DeepSeek dry 通过，未修改查询消息历史。

## 债务记录

无新增。思考模式不在本轮支持范围，明确拒绝。

## 意外发现

官方接口缓存字段不同且采用分时价格，不能将缓存当0或套用其他模型单价。

## 阻塞与解决

提交复审按官方契约发现 DeepSeek 缓存命中/未命中为必需分项，不能沿用其他接口可省略为零的语义。解析器现按 provider 校验两分项、输入总量及嵌套缓存值的一致性，缺失或无效时费用不完整；完全未取得 usage 的缓存分项统一为 null。补充解析与 callLLM/HTTP 台账/总费用贯通回归，并保留其他 provider 有效 usage 中可省略缓存字段的原契约。历史试验独立检查过所有缓存分项，运行结果不变。

已完成两会话预检与 60 次正式会话；全部 180 次 HTTP 成功，未发生协议或用量阻塞。空闲时段总估算 0.7045248 元；runner 仍以高峰价格保守估算，差异已在[试验](archive/exp/exp-deepseek-capability.md)明确。本轮结束前核验 121 个冻结文件无漂移；运行完成后仅去掉 CLI 文件末尾多余空行。工程验收完成，计划随未来发版工作流归档，本次不提交或合并。
