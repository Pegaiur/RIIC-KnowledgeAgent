# 上游语料「不采用」判据与遗漏归口草案

> 创建日期：2026-09-19
> 状态：未定稿（范围与方案讨论中）
> 需求入口：docs/inbox.md

## 目标

把上游语料的「不采用」从笼统理由细化为可复核的判据与归口：含玩家使用判断的内容不得与编辑性建议、重复推导或外部格式整类舍弃；「本地尚无对应档位表、参考线或参数」不构成内容不成立的依据，而应触发回查来源、补必要增量或明确待核验；五批对象之外与跨批交接的内容须有可追踪的归口。

## 非目标

- 不重开 docs/archive/plan-corpus-candidate-batches.md 的已验收结论，不推翻已审定参考线、已采用正文与既有冲突处置；不因问答答错触发修复。
- 不整库重新导入，不为每个未采用段落建立逐条证明台账，不新增哈希或指纹字段。
- 不改检索算法、查询指令、工具预算与评分，不启动付费运行。
- 不预先认定审计条目「应当采纳」；本草案只提出判据与复核流程，采纳与否以来源原文复核为准。
- 付费与抽卡攻略、外部 frontmatter／wikilink／目录编号、meta 与治理材料、非规范俗称的排除继续有效，这些不是本草案的复核对象。

## 背景与依据

docs/archive/plan-corpus-candidate-batches.md 的「实施纪要」记录五批候选的采用与不采用项。收束复核发现四类问题：

### 1. 被并入「编辑性建议／重复／格式」的玩家使用判断

- 批次二人间烟火组把「建议烟火池 60 点以上再启用」「制造端不建议」与「柴卡／杏叶等获取途径」并列为「编辑性建议」整体舍弃（记录层与「别名」是并列两组）；来源表行才合并写作「别名与编辑性建议不采用」。其中「制造端不建议」已有部分本地承载：knowledge/guides/组合/贸易站组合.md 的「人间烟火组」节已写明截云与黍转化率低、通常不值得为它们补满资源链。该项复核应先核对采用记录与正文是否一致，不按完全遗漏重复补写；判据也应据此区分「记录未单独说明但正文已承载」与「正文与记录都没有」。
- 批次五把「243 通用收益底限」与 frontmatter、付费内容并列，理由记为「重复推导或条件不足」，未指明重复于哪条已采用基准。
- 批次四把定时换班的「不要开启宿舍锁定」提示与 mower 功能名、条件运算符并列，归为「第三方工具实现、外部格式或本地无依据口径」；宿舍锁定属游戏侧功能，其与定时换班的相互作用属使用条件。

### 2. 以「本地无对应表」排除比较判断

- 批次一「可露希尔特别订单 60% 触发档同站共存」记为「依赖本地不存在的档位定义」。
- 批次二「可露希尔 80% 档与等效贸易／赤金效率」记为「本地无该档位表」；债务记录只登记未采用，未写偿还条件；批次五又以「重复推导」复列，同一类内容在三批用了三个理由。
- 批次二凯尔希挂件的「发电站散件 20% 参考线」因本地无该参考线而不写，未记待核。
- 批次二能天使 35% 与海蒂交叉引用因本地按 40% 线筛选而拒；批次五又把 35% 与 40/40/40/35 作为待处置冲突，前批结论未沉淀为后续判据。
- 批次五泡泡组裸 54 格派生 8.6 小时因日产速率未收录而丢弃；该不采用已记入债务（批次二未决与遗留条），但未登记偿还条件，另条爆仓算例记录只覆盖公式落位。

### 3. 交接悬空与归口缺失

- 批次三「1 制造效率≈13 线索效率」明写「涉及未列入任何批次的办公室／会客室取向，本批不引入」，未按计划收束要求落到 docs/inbox.md 归口。
- 批次三称「搓玉的换班间隔属排班主题第四批」，但第四批 6 篇候选与采用记录均不含搓玉篇，该段未在任何批次评估。
- 批次一把社区俗称归为「非规范词」舍弃；批次四按术语规范把「红脸」统一为「注意力涣散」，其不采用项原记录未单列「非规范词」（两批俗称处理本身符合术语规范）。俗称类未与已归口的歧义三篇一起并入 docs/inbox.md 的查询侧消歧待办。

### 4. 计划自认的同类失效模式

批次五验收记录已写明「实施阶段把本地尚无锚点作为排除数值的理由，未能支撑已保留的排序与比较」，并据计划重新核对补充来源；该判断未回扫前四批，故上列条目以原措辞留存。

计划依据：docs/archive/plan-corpus-candidate-batches.md 规定「布局比较、用人取舍与有条件的收益估算属于采用范围」，「逐篇评估后可不采用无增量、不适用或依据不足的具体段落，但不能把尚未评估的整个主题预先排除」，「所需参数尚未收录时回查来源、补必要增量或明确该项待核验」，五批以外对象「继续留在 docs/inbox.md，另定范围再实施」。

依据边界：本轮未重读上游原文，只核对记录层与本地相关正文；来源工作副本已按 skills/corpus-addition/SKILL.md 清理。任何条目的成立与否须重新取得固定提交 53cf2f74d71c88fca4e13f1ad3f3fbe275186129 的对应篇目复核后才可判定，审计清单不是结论。

## 候选方案与评估

| 方案 | 内容 | 收益 | 代价与风险 | 倾向 |
|---|---|---|---|---|
| A 判据细化＋有限逐项复核 | 先建立「可排除」与「不可仅以本地缺参数排除」两张判据表，落到写作 spec 或 corpus-addition skill 的采用环节；再对审计清单按来源复核处置 | 同类问题在后续语料工作中有统一判据，复核范围可控 | 需决定判据落位处，避免与既有 spec 重复维护 | 优先 |
| B 只逐项复核清单 | 不立判据，仅重取来源逐条判定 | 改动最小 | 判据不沉淀，同类问题会再犯，可复现性差 | 可作为 A 的第一批执行内容 |
| C 重建不采用台账 | 为全部未采用段落建索引与依据 | 完备 | 与计划「不新增逐条证明台账」冲突，维护负担大 | 不采用 |

判据表初稿方向：

- **可排除**：外部格式与元数据、治理与镜像材料、付费与抽卡攻略、非规范俗称（走术语规范并归口消歧待办）、与本地真源冲突且无来源支持的数值。
- **不可仅以本地缺参数排除**：取舍阈值、收益比较基准、启用门槛、参考线、档位效率。此类内容先复核来源；成立且本计划范围覆盖的补必要增量，暂不具备本地承载的记入债务并写明偿还条件，批次外的归口 docs/inbox.md。

## 实施方案（候选）

### 1. 确立判据与落位

输入：本草案判据表初稿、docs/spec/rag-prose-writing.md、skills/corpus-addition/SKILL.md。做法：确定判据写入哪一处（避免两处维护），补充「本地缺参数」时的处置顺序，并区分「记录未单独说明但正文已承载」与「正文与记录都没有」。输出：修订后的 spec 或 skill 条目。验收：判据可依据来源与条件人工复核，不与既有写作要求冲突。

### 2. 按来源逐项复核

输入：重新取得的固定提交对应篇目、上文四类审计清单。做法：逐项核对来源原文与本地上游依据，区分「确有内容但不属采用范围」「本地缺参数且内容成立」「来源依据不足」。输出：逐项结论与依据，记入对应 notes 或后续 plan。验收：复核对象可追到来源篇目与段落，主代理亲自核对关键项。

### 3. 处置与归口

采用项按 corpus-addition skill 落位并通过既有检查；暂不采用项记入债务并写明偿还条件；批次外对象归口 docs/inbox.md。验收：三者互不混用，不以「以后可能有用」为由保留临时材料。

### 4. 跨批口径收口

对可露希尔档位类内容（批次一／二／五）与散件筛选线（35%／40%）给出统一结论，避免同一类内容在不同批次理由不一致。验收：同一对象的历次记录结论一致或明确标注取代关系。

### 5. 验证与收尾

按变更类型运行 node scripts/doc-check.mjs、术语与投影检查及既有测试；涉及正文改写时按语料流程做独立审阅与实际送达核对。临时材料按 scripts/INDEX.md 显式清单清理。
