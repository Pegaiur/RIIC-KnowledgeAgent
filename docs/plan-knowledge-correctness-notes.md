### 2026-09-18 — 长期规范同步与验收边界更正

- **plan 原文**：每个内容批次独立审查，但写作 spec v1 未要求每次由第二名 Agent 复核；现有门禁被概括为保证 facts 正确。
- **实际做法**：spec 升为 v2。实质新增、导入及机制、条件、建议改动由独立 Agent 复核；错字、格式和不改含义的措辞修订由当前 Agent 自查。人类参与采用目标、实践判断和争议取舍，已有决定直接沿用。根 AGENTS.md、术语规则、inbox 与 ADR-020 内容维护引用同步。
- **原因**：让长期规范承载共同要求，避免活动计划归档后丢失口径，也避免每次细小修订触发完整审稿流程。
- **后果**：check:reference-projection 仅能验证公共练度说明投影，prose-links 与 read 仅验证各自结构或送达契约；完整上游映射仍待计划步骤 2。该评估需记录固定解包提交、源文件及对象字段、11 份输入覆盖与转换、缺口和后续实现范围，不在本次修订中虚报完成。

前轮修订消解了范围无边界、门禁能力过度表述、raw 无法裁决全部散文主题及长期审阅要求冲突。本轮核对 raw 共 19 份文档，11 份事实输入由 references.ts、equivalence.ts 直接读取，gold 定位与三个维护脚本也依赖旧路径；剩余 8 份为来源材料。由此将“先迁正式输入，再清理临时材料”写入独立实施计划，避免仅改文档定义而误删运行时输入。
